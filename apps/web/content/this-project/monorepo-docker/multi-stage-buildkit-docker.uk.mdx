## 1. Тристадійний конвеєр збірки (`pruner -> builder -> runner`)

Щоб у продакшен-контейнери не потрапляли сирці, компілятори та чужі пакети монорепозиторію, кожен Dockerfile у папці `docker/` будує образ у три кроки:

1. **`pruner`:** запускає `turbo prune @repo/<app> --docker`, формуючи мінімальний підграф (`out/json/`, `out/full/`, `out/pnpm-lock.yaml`) лише для цільового сервісу.
2. **`builder`:** активує `pnpm@12.21.0`, ставить залежності через `--frozen-lockfile --ignore-scripts` зі спільним кешем BuildKit, запускає `pnpm turbo run build --filter=@repo/<app>...` та очищає `devDependencies`.
3. **`runner`:** копіює лише скомпільовані артефакти (`dist/` або `.next/standalone`) і запускає процес від непривілейованого користувача (`USER node` / `USER nextjs`).

## 2. `turbo prune` та спільний BuildKit Cache Mount

При збірці декількох мікросервісів з одного монорепозиторію `out/json/` стабілізує Docker-шар залежностей, а монтування `/root/.local/share/pnpm/store` через BuildKit `type=cache,id=pnpm` дозволяє завантажити спільні пакети один раз і перевикористати їх у всіх образах:

```dockerfile title="docker/api.Dockerfile"
FROM node:22-alpine AS pruner
RUN apk add --no-cache libc6-compat openssl
ENV DO_NOT_TRACK=1
ENV TURBO_TELEMETRY_DISABLED=1
RUN npm install -g turbo@^2
WORKDIR /app
COPY . .
RUN turbo prune @repo/api --docker

FROM node:22-alpine AS builder
RUN apk add --no-cache libc6-compat openssl
ENV DO_NOT_TRACK=1
ENV TURBO_TELEMETRY_DISABLED=1
RUN corepack enable && corepack prepare pnpm@12.21.0 --activate && pnpm --version
WORKDIR /app

COPY --from=pruner /app/out/json/ .
COPY --from=pruner /app/out/pnpm-lock.yaml ./pnpm-lock.yaml
RUN --mount=type=cache,id=pnpm,target=/root/.local/share/pnpm/store \
    pnpm install --frozen-lockfile --ignore-scripts
```

## 3. Очищення `devDependencies` та Rust-free Prisma 7

У стадії `builder` команда `pnpm turbo run build --filter=@repo/api...` генерує ESM-клієнт Prisma 7 (`prisma-client`) у `apps/api/src/generated/prisma/` і компілює його через `tsc` прямо в `apps/api/dist/generated/prisma/`. Оскільки Prisma 7 замінила нативний Rust-рушій у `.prisma/client` на Wasm-компілятор запитів усередині production-пакета `@prisma/client` (у парі з `@prisma/adapter-pg` та `pg`), очищення `pnpm prune --prod --ignore-scripts` виконується без тимчасового буфера `/tmp`, а стадії `runner` більше не потрібен `openssl`:

```dockerfile title="docker/api.Dockerfile"
RUN --mount=type=cache,id=pnpm,target=/root/.local/share/pnpm/store \
    pnpm turbo run build --filter=@repo/api... && \
    pnpm prune --prod --ignore-scripts

# Stage 3: Production non-root runner
FROM node:22-alpine AS runner
WORKDIR /app
ENV NODE_ENV=production
ENV PORT=4000
```

### Характеристики фінальних продакшен-образів

| Контейнер | Базовий образ | Експонований порт | Користувач рантайму |
| :--- | :---: | :---: | :---: |
| `workfolio-telemetry-ms` | `node:22-alpine` | `4001` (лише внутрішня мережа) | `node` (не-root) |
| `workfolio-api` | `node:22-alpine` | `4000` | `node` (не-root) |
| `workfolio-web` (`standalone`) | `node:22-alpine` | `3000` | `nextjs` (`UID 1001`) |

> [!TIP]
> Оскільки продакшен-образ `api` не містить `Prisma CLI`, міграції схеми БД (`prisma migrate deploy`) виконуються окремим кроком у CI/CD перед перемиканням трафіку.

## 4. Розділення `docker-compose.yml` (Zero-Friction Reviewer Demo) та `docker-compose.prod.yml` (Strict Production)

Щоб тімлід або СТО міг розгорнути весь стек однією командою `docker compose up --build` без ручного створення `.env`, але бойовий деплой на VPS залишався суворо захищеним від дефолтних секретів, оркестрацію розділено на два файли:

| Параметр | `docker-compose.yml` (Local Reviewer Demo) | `docker-compose.prod.yml` (Strict Production) |
| :--- | :--- | :--- |
| **Команда запуску** | `docker compose up --build -d` | `docker compose -f docker-compose.prod.yml --env-file .env.prod up --build -d` |
| **`WORKFOLIO_DEMO_MODE`** | `"true"` (дозволяє fallback на єдиний `DEFAULT_DEV_JWT_SECRET` із `@repo/shared-schemas` і виводить `console.warn`) | Не заданий (`"false"` — жорсткий fail-fast у `loadAppConfig` при порожніх або дефолтних секретах) |
| **Перевірка секретів на рівні Compose** | `${JWT_SECRET:-}` (авто-резолв через `resolveJwtSecret()` без `.env`) | Обов’язкова інтерполяція `${JWT_SECRET:?}`, `${ADMIN_SECRET_PASSCODE:?}`, `${POSTGRES_PASSWORD:?}` |
| **Прапорець `Secure` у `HttpOnly` куці `kb_access_token`** | `false` (`appConfig.isProduction && !appConfig.isDemoMode` — працює по `http://localhost:3000`) | `true` (працює суворо поверх HTTPS / TLS) |
| **Порт `postgres` (`5432`)** | `127.0.0.1:5432:5432` (доступний лише з localhost для DBeaver / DataGrip) | **Не опублікований на хост** (100% ізольований усередині приватної мережі `backend-network`) |
