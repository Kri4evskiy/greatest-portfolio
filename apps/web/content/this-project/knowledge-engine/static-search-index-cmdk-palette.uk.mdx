## 1. Нульовий оверхед HTML і JS у кореневому `layout.tsx`

Якщо в кореневому `apps/web/src/app/[locale]/layout.tsx` передавати масив `searchIndex` напряму через пропси — або жадібно імпортувати `CommandPaletteModal` разом із примітивами Radix `Dialog` та `MiniSearch` — кожен відвідувач завантажуватиме заголовки всіх статей і JS-код модалки на **кожній** сторінці, навіть якщо жодного разу не відкриє пошук.

Ми розділили фічу `apps/web/src/features/search/` на ізольовані модулі:

- `command-palette-loader.tsx` — легкий слухач `Cmd+K` / `Ctrl+K` у `layout.tsx`.
- `search-index-client.ts` — клієнтський завантажувач, дедуплікація запитів, Zod-валідація та кеш.
- `lib/filter-command-entries.ts` — чистий рушій на `MiniSearch`, `#tag`-фільтрація та групування Public/Protected (покритий юніт-тестами в `__tests__/filter-command-entries.test.ts`).
- `ui/command-palette-modal.tsx` та `ui/command-palette-item.tsx` — ліниво підвантажуваний `Dialog` і атоми рядків видачі.

```tsx title="apps/web/src/features/search/command-palette-loader.tsx"
'use client'

import type { SupportedLocale } from '@repo/shared-schemas'
import dynamic from 'next/dynamic'
import { useEffect, useState } from 'react'
import { useIsCommandPaletteOpen, useUIActions } from '@/shared/store/use-ui-store'

const LazyCommandPaletteModal = dynamic(
  () => import('./ui/command-palette-modal').then((m) => m.CommandPaletteModal),
  { ssr: false },
)

export function CommandPaletteLoader({ locale }: { locale: SupportedLocale }) {
  const isOpen = useIsCommandPaletteOpen()
  const { openCommandPalette: openPalette, closeCommandPalette: closePalette } = useUIActions()
  const [hasLoaded, setHasLoaded] = useState(false)

  useEffect(() => {
    const handleKeyDown = (event: KeyboardEvent) => {
      if ((event.metaKey || event.ctrlKey) && event.key.toLowerCase() === 'k') {
        event.preventDefault()
        if (isOpen) closePalette()
        else openPalette('')
      }
    }
    window.addEventListener('keydown', handleKeyDown)
    return () => window.removeEventListener('keydown', handleKeyDown)
  }, [isOpen, openPalette, closePalette])

  useEffect(() => {
    if (isOpen && !hasLoaded) setHasLoaded(true)
  }, [hasLoaded, isOpen])

  if (!isOpen && !hasLoaded) return null
  return <LazyCommandPaletteModal locale={locale} />
}
```

## 2. Статичний SSG Route Handler (`/search-index/[locale]`) та єдиний Zod-контракт

У Next.js App Router ендпоїнти визначаються структурою папок: файл `apps/web/src/app/search-index/[locale]/route.ts` обслуговує `GET /search-index/en`, `/search-index/uk` і `/search-index/ru` (шлях `search-index` явно виключено з редиректів `next-intl` у `config.matcher` усередині `apps/web/src/proxy.ts`).

Директива `export const dynamic = 'force-static'` у парі з `generateStaticParams()` завчасно збирає всі 3 JSON-індекси на етапі `next build` — без звернень до диска чи БД у рантаймі:

```typescript title="apps/web/src/app/search-index/[locale]/route.ts"
import { DEFAULT_LOCALE, SUPPORTED_LOCALES, SupportedLocaleEnum } from '@repo/shared-schemas'
import { NextResponse } from 'next/server'
import { getAllKnowledgeTags, getKnowledgeSearchIndex } from '@/entities/knowledge-content'

export const dynamic = 'force-static'

export function generateStaticParams() {
  return SUPPORTED_LOCALES.map((locale) => ({ locale }))
}

export async function GET(_request: Request, context: { params: Promise<{ locale: string }> }) {
  const { locale } = await context.params
  const parsed = SupportedLocaleEnum.safeParse(locale)
  const resolvedLocale = parsed.success ? parsed.data : DEFAULT_LOCALE

  return NextResponse.json(
    {
      items: getKnowledgeSearchIndex(resolvedLocale),
      topTags: getAllKnowledgeTags(resolvedLocale),
    },
    {
      headers: {
        'Cache-Control': 'public, max-age=3600, stale-while-revalidate=86400',
      },
    },
  )
}
```

Серверна проєкція (`mdx-types.ts` реекспортує `KnowledgeSearchItem`) і клієнтський завантажувач спираються на єдину схему `KnowledgeSearchPayloadSchema` з `@repo/shared-schemas/src/knowledge.schema.ts` — це повністю унеможливлює тихий розсинхрон полів між JSON-відповіддю та клієнтом.

## 3. Модульний кеш без витоків, дедуплікація та синхронний старт без мерехтіння

В `apps/web/src/features/search/search-index-client.ts` дві `Map`-таблиці на рівні ES-модуля (`resolvedCache` і `inflightCache`) кешують відповіді між SPA-переходами та дедуплікують паралельні запити:

```typescript title="apps/web/src/features/search/search-index-client.ts"
import { type KnowledgeSearchPayload, KnowledgeSearchPayloadSchema, type SupportedLocale } from '@repo/shared-schemas'

const resolvedCache = new Map<SupportedLocale, KnowledgeSearchPayload>()
const inflightCache = new Map<SupportedLocale, Promise<KnowledgeSearchPayload>>()

export function getCachedKnowledgeSearchIndex(locale: SupportedLocale): KnowledgeSearchPayload | null {
  return resolvedCache.get(locale) ?? null
}

export function loadKnowledgeSearchIndex(locale: SupportedLocale): Promise<KnowledgeSearchPayload> {
  const existingResolved = resolvedCache.get(locale)
  if (existingResolved) return Promise.resolve(existingResolved)

  const existingInflight = inflightCache.get(locale)
  if (existingInflight) return existingInflight

  const requestPromise = fetch(`/search-index/${locale}`, {
    method: 'GET',
    credentials: 'same-origin',
  })
    .then(async (res): Promise<KnowledgeSearchPayload> => {
      if (!res.ok) {
        if (process.env.NODE_ENV !== 'production') {
          console.error(`[search-index-client] Failed to load /search-index/${locale}: HTTP ${res.status}`)
        }
        return EMPTY_PAYLOAD
      }

      const rawJson: unknown = await res.json()
      const parsed = KnowledgeSearchPayloadSchema.safeParse(rawJson)
      if (!parsed.success) {
        if (process.env.NODE_ENV !== 'production') {
          console.error(`[search-index-client] Invalid /search-index/${locale} payload:`, parsed.error.issues)
        }
        return EMPTY_PAYLOAD
      }

      resolvedCache.set(locale, parsed.data)
      return parsed.data
    })
    .catch(() => EMPTY_PAYLOAD)
    .finally(() => {
      inflightCache.delete(locale)
    })

  inflightCache.set(locale, requestPromise)
  return requestPromise
}
```

> [!TIP]
> **Чому модульний кеш безпечний для пам'яті та прибирає мерехтіння спінера:**
> - **Жорстка межа по RAM:** `inflightCache` видаляє `Promise` одразу в `.finally()` (у спокої `size === 0`), а `resolvedCache` ключується строго за `SupportedLocale` (`en | uk | ru` — максимум `3` записи, ~45 КБ на весь час життя вкладки). Модуль викликається лише на клієнті (`'use client'` + гард `typeof window === 'undefined'`), тож ніколи не розділяє стан між SSR-запитами.
> - **Prefetch + синхронний `getCachedKnowledgeSearchIndex()`:** кнопки пошуку у `WorkfolioHeader` та `KnowledgeSidebarPanel` прогрівають індекс на `onMouseEnter` / `onFocus`. Оскільки `loadKnowledgeSearchIndex()` завжди повертає асинхронний `Promise`, у `CommandPaletteModal` початковий стан ініціалізується синхронно через `useState(() => getCachedKnowledgeSearchIndex(locale))` — на 1-му ж кадрі рендеряться `#теги` і статті без 1-кадрового мерехтіння спінера `<Loader2 />`.

## 4. Рушій `MiniSearch`, захист від stale-locale та Soft-Lock UX Hybrid KB

### Чистий рушій `MiniSearch` (`lib/filter-command-entries.ts`)

Алгоритм пошуку та ранжування винесено з React-компонента в чистий TypeScript-модуль на базі `MiniSearch`:

- **Prefix + Fuzzy-пошук із захистом від одруківок:** `prefix: true` миттєво знаходить слова за префіксом (включно з латиницею та кирилицею EN/UK/RU), а `fuzzy: (term) => (term.length >= 4 ? 0.2 : false)` пробачає одруківки на кшталт `compler -> compiler`, не створюючи шуму на коротких термінах (`js`, `ts`, `ui`).
- **Ваговий скоринг і `AND -> OR` fallback:** пріоритети полів — `title (4) > sidebarLabel (3.5) > subtopicLabel (3) > tags (2.5) > topicLabel / headings (2) > summary (1.2)`. Для багатослівних запитів спершу виконується строгий `combineWith: 'AND'`, і лише при порожній видачі — fallback на `'OR'`.
- **Режим `#тегів` і перехід до `h2/h3`:** запити з `#` фільтрують теги напряму (`#zod`, `#jwt`), а при збігу підзаголовка додається `matchedHeading`, щоб за `Enter` перейти одразу на `/ua/knowledge-base/...#section-id`.

### Захист від stale-locale та Soft-Lock у `ui/command-palette-modal.tsx`

1. **Пара `{ locale, payload }`:** при перемиканні мови (`en -> uk`) застарілий індекс іншої локалі миттєво відкидається, показується спінер `Loader2` до відповіді нового `loadKnowledgeSearchIndex(locale)`, а прапорець скасування `active` у cleanup ефекту захищає від гонки відповідей.
2. **Soft-Lock UX для Hybrid KB (`isPublicKnowledgeBasePath`):**
   - Для неавторизованих гостей при порожньому запиті список ділиться горизонтальним роздільником на **Публічні нотатки (`This Project`)** та **Захищені нотатки • Перепустка в 1 клік**, а під `#тегами` показується компактний 1-рядковий банер розблокування.
   - Закриті результати позначаються іконкою `Lock` і бейджем `1-Click Unlock`, у футері підказка клавіші `Enter` динамічно змінюється з `↵ open` на `↵ unlock & open`, а вибір закритої нотатки відкриває `GuestPassModal` на місці (`openGuestPassModal(baseArticlePath)`) без різкого `307`-редиректу.

## 5. Архітектурне рішення (ADR): чому Git MDX + SSG, а не перенесення Бази Знань у PostgreSQL CMS?

Часте питання на технічному інтерв'ю та архітектурному рев'ю: *«Статей стає дедалі більше (зараз ~90 MDX-файлів = 30 статей × 3 мови), чи не логічніше перенести дерево сайдбару, статті та пошук у NestJS + PostgreSQL?»*

### Індустріальний контекст: Docs-as-Code

Зберігання інженерної бази знань у Git у форматі Markdown/MDX із компіляцією у статику (**Docs-as-Code**) — перевірений стандарт великих технічних платформ: саме так працюють **Cloudflare Docs** (`cloudflare/cloudflare-docs`), **Next.js Docs** (`vercel/next.js`), **Tailwind CSS Docs** (`tailwindlabs/tailwindcss.com`) та **Stripe Docs** (на базі їхнього open-source фреймворку **Markdoc**).

### Матриця компромісів

| Критерій | A. Git MDX + SSG (поточний вибір) | B. Повний переїзд у PostgreSQL + NestJS CMS | C. Гібридний шлях еволюції |
| :--- | :--- | :--- | :--- |
| **TTFB і SEO** | Миттєва статика HTML/RSC (`0` запитів у БД на рендер) | Залежить від БД і cold start Neon (300–800 мс) без жорсткого ISR/Redis-кешу | Миттєвий SSG для публічного + On-Demand ISR для решти |
| **Відмовостійкість** | **100% автономність:** KB, сайдбар і `Cmd+K` працюють навіть при рестарті API/БД | Падіння БД/API ламає сайдбар і статті без fallback-кешу | Контент незалежний; бекенд підсилює пошук та інтерактив |
| **Редагування та AI-воркфлоу** | IDE, `git diff`, PR-рев'ю, прямі правки AI-агентами; мінус: потрібен коміт + деплой | Правки з браузера, статуси `draft/published`; мінус: немає `git diff`, потрібна своя Admin UI + завантаження зображень у S3/R2 | Статті версіонуються в Git; мутовані дані — в БД |
| **Пошук і масштаб** | Клієнтський `MiniSearch`: `< 1 мс` по метаданих і `h2/h3` (~4 КБ gzip на 30 статей; ~25–30 КБ gzip на 300 статей) | PostgreSQL `tsvector` + `pg_trgm`: пошук по всьому тексту абзаців + серверна фільтрація RBAC | Синхронізація тексту MDX у Postgres FTS при деплої, коли індекс перевищить >150–200 КБ |
| **Інтерактивні віджети** | Zero-Eval HAST безпечно мапить `<ReactRenderGraphD3 />` і `::sandbox{}` без ризику XSS із БД | Потрібна pre-компіляція HAST при збереженні + сувора санітизація | Нативні MDX-віджети + стан Лабораторії в БД |
| **Вартість упровадження** | Вже працює в production | Висока (XL: Prisma-схема, Admin CRUD, кеш Shiki у runtime, S3, ISR-вебхуки) | Поетапна (S–M на крок) |

### Чіткі точки перегину (коли змінювати архітектуру)

1. **До ~300 статей (~900 MDX-файлів):** Git MDX + статичний `/search-index/[locale]` + клієнтський `MiniSearch` — оптимальний баланс швидкості, відмовостійкості та простоти підтримки.
2. **На позначці ~500–1 000+ файлів (якщо час `next build` через Shiki стане помітним):** залишаємо Git як джерело істини, але переводимо захищені маршрути `[...slug]` на **On-Demand ISR** (збираючи під час білду лише публічний `this-project`).
3. **Коли знадобиться повнотекстовий пошук по абзацах або сувора серверна фільтрація RBAC:** додаємо синк-скрипт при деплої в PostgreSQL (`tsvector` + `pg_trgm`) за ендпоїнтом `GET /api/knowledge/search`, перевикористовуючи вже готовий контракт `KnowledgeSearchPayloadSchema` із `@repo/shared-schemas`.
4. **Де NestJS + PostgreSQL дають максимум цінності вже зараз:** живі мутовані домени — метрики й реакції статей, live SSE-телеметрія, користувацькі закладки/прогрес і майбутні інтерактивні пісочниці **Engineering Lab**.
