## 1. Зачем современному Full-Stack приложению эшелонированная защита

В монорепозитории, объединяющем публичный интерфейс Next.js, API на NestJS, внутренний TCP-микросервис и PostgreSQL, компрометация одного узла может каскадно затронуть всю систему. Наша архитектура реализует принцип **Defense-in-Depth (Глубокоэшелонированная оборона)** на пяти независимых уровнях:

```text
[ Браузер ]
    │
    ├── (1) HTTP Security Headers (Next.js): суженный CSP, HSTS, COOP, CORP: same-origin, X-Frame-Options
    │
    ├── (2) Edge Auth Barrier (proxy.ts + edge-jwt.ts): гибридная БЗ + Fail-Closed HS256 Web Crypto JWT
    │
    ├── (3) API Gateway Hardening (NestJS): JSON-only парсер 100kb + строгий Helmet CSP + CsrfOriginMiddleware
    │
    ├── (4) Rate Limiting и RBAC: общий Throttler (60/мин база, 5/мин auth и SSE) + HS256 1d JWT + Roles
    │
    └── (5) Изоляция контейнеров и сетей (docker-compose.prod.yml): read_only, cap_drop ALL, 127.0.0.1, приватный TCP :4001
```

Каждый слой автономен: обход клиентской валидации останавливается `CsrfOriginMiddleware`, `ZodValidationPipe` и `ThrottlerGuard` на API, а попытка встроить сайт в чужой `<iframe>` блокируется `frame-ancestors 'none'`.

## 2. HTTP Security Headers в Next.js 16 (`apps/web/config/security-headers.config.ts`)

Чтобы `apps/web/next.config.ts` оставался компактным и не смешивал инфраструктурный конфиг со слоями FSD, генерация всех заголовков вынесена в `apps/web/config/security-headers.config.ts`. В продакшене из `connect-src` намеренно убран широкий `https:` — разрешены только `'self'` и явно провалидированные через `parseSafeHttpOrigin` домены (`NEXT_PUBLIC_API_URL`, `NEXT_PUBLIC_POSTHOG_HOST`, `NEXT_PUBLIC_SENTRY_DSN`):

```typescript title="apps/web/config/security-headers.config.ts"
export function buildContentSecurityPolicy(
  isProduction: boolean,
  publicApiUrl = '',
  options: ContentSecurityPolicyOptions = {},
): string {
  const { allowSameOriginFraming = false } = options
  const allowedConnectOrigins = new Set<string>()
  const safeApiOrigin = parseSafeHttpOrigin(publicApiUrl)
  if (safeApiOrigin) allowedConnectOrigins.add(safeApiOrigin)

  const posthogOrigin = parseSafeHttpOrigin(process.env.NEXT_PUBLIC_POSTHOG_HOST)
  if (posthogOrigin) allowedConnectOrigins.add(posthogOrigin)
  const sentryOrigin = parseSafeHttpOrigin(process.env.NEXT_PUBLIC_SENTRY_DSN)
  if (sentryOrigin) allowedConnectOrigins.add(sentryOrigin)

  const extraConnectSrc = allowedConnectOrigins.size > 0 ? ` ${Array.from(allowedConnectOrigins).join(' ')}` : ''

  // В продакшене внутренние порты и широкий `https:` НИКОГДА не попадают в connect-src.
  const connectSrc = isProduction
    ? `'self'${extraConnectSrc}`
    : `'self' http://localhost:4000 http://localhost:4001 http://127.0.0.1:4000 http://127.0.0.1:4001 ws: wss:${extraConnectSrc}`

  // В продакшене 'unsafe-eval' полностью отключён (MDX компилируется в HAST без eval).
  const scriptSrc = isProduction ? "'self' 'unsafe-inline'" : "'self' 'unsafe-inline' 'unsafe-eval'"
  const frameAncestors = allowSameOriginFraming ? "'self'" : "'none'"

  const directives: string[] = [
    "default-src 'self'",
    `script-src ${scriptSrc}`,
    "style-src 'self' 'unsafe-inline'",
    "img-src 'self' blob: data: https:",
    "font-src 'self' data:",
    `connect-src ${connectSrc}`,
    "frame-src 'self'",
    `frame-ancestors ${frameAncestors}`,
    "form-action 'self'",
    "base-uri 'self'",
    "object-src 'self'",
    ...(isProduction ? ['upgrade-insecure-requests'] : []),
  ]

  return directives.join('; ').trim()
}
```

### Ключевые директивы `getSecurityHeaders()`
- **Суженный `connect-src` и Zero Eval в продакшене:** удалены порты `:4000`, `:4001`, `localhost`, широкий `https:` и `'unsafe-eval'`.
- **`Cross-Origin-Opener-Policy: same-origin` и `Cross-Origin-Resource-Policy: same-origin`:** изолируют контекст окна и блокируют кросс-доменное чтение фронтенд-ресурсов (защита от XS-Leaks и Spectre).
- **Clickjacking и точечный скоуп для `/cv/:path+`:** `next.config.ts` отключает `poweredByHeader`, применяет `frame-ancestors 'none'` + `X-Frame-Options: DENY` ко всем маршрутам `/(.*)` и ослабляет их до `'self'` / `SAMEORIGIN` **исключительно** для `/cv/:path+`, чтобы SPA-переход `<Link href="/cv">` рендерил `<object type="application/pdf">` без ослабления остального сайта.
- **`Strict-Transport-Security` (только прод), `nosniff`, `Referrer-Policy`, `Permissions-Policy`:** `max-age=63072000; includeSubDomains; preload`, `X-Content-Type-Options: nosniff`, `strict-origin-when-cross-origin` и `camera=(), microphone=(), geolocation=(), browsing-topics=()`.

## 3. Гибридный доступ к БЗ, явный `matcher` статики и Fail-Closed Edge JWT (`proxy.ts` и `edge-jwt.ts`)

В Next.js 16 `apps/web/src/proxy.ts` реализует **гибридную политику доступа** к Базе Знаний через `isProtectedKnowledgeBasePath()`:
- **Публичные и индексируемые (SEO):** хаб `/knowledge-base` и вся ветка `/knowledge-base/this-project/**` открываются напрямую без редиректов для поисковиков, рекрутеров и тимлидов.
- **Защищённые Edge Web Crypto JWT:** остальные доменные категории конспектов (`/knowledge-base/react/**` и т.д.) требуют валидную куку `kb_access_token`, проверяемую через `verifyEdgeJwtHs256()`.

```typescript title="apps/web/src/proxy.ts"
// Явно исключаем только известные расширения статики вместо широкого `.*\..*`,
// чтобы будущие слаги Базы Знаний с точками (например, `next.js-16`) не обходили Edge Auth.
export const config = {
  matcher: [
    '/((?!api|search-index|icon|apple-icon|_next|_vercel|.*opengraph-image.*|.*\\.(?:ico|png|jpg|jpeg|gif|svg|webp|avif|pdf|css|js|mjs|map|woff|woff2|ttf|otf|txt|xml|json|webmanifest)$).*)',
  ],
}
```

Функция `verifyEdgeJwtHs256()` в `apps/web/src/shared/lib/edge-jwt.ts` работает строго по принципу **fail-closed**:
1. Проверяет `header.alg === 'HS256'`, `exp`, опциональный `nbf`, непустой `sub` и `role` из `{'USER', 'ADMIN'}`.
2. Вызывает `resolveEdgeJwtSecretStrict()`, который возвращает `null` в продакшене (вне явного `WORKFOLIO_DEMO_MODE=true`), если `JWT_SECRET` отсутствует, короче 32 символов или равен `DEFAULT_DEV_JWT_SECRET` — Edge Auth никогда не откатывается на публичный dev-ключ.
3. Кэширует импортированный Web Crypto `CryptoKey` по значению секрета и очищает отклонённый промис при ошибке, чтобы транзиентный сбой не «отравил» Edge-изолят.

## 4. Защита API-шлюза (`main.ts`), JWT `1d` с `HS256` и безопасные фильтры ошибок

В `apps/api/src/main.ts` Express запускается с `bodyParser: false` и регистрирует **только** JSON-парсер `100kb` (парсер `urlencoded` полностью удалён), настраивает `trust proxy` через валидированный `appConfig.trustProxyHops` (`0..5`, по умолчанию `1`) и включает **строгий Helmet JSON CSP** вместе с cross-origin CORP для авторизованных кросс-доменных запросов Vercel ➔ Render:

```typescript title="apps/api/src/main.ts"
async function bootstrap(): Promise<void> {
  const app = await NestFactory.create<NestExpressApplication>(AppModule, {
    bodyParser: false,
  })
  app.useBodyParser('json', { limit: '100kb' })

  if (appConfig.isProduction && appConfig.trustProxyHops > 0) {
    app.set('trust proxy', appConfig.trustProxyHops)
  }

  app.setGlobalPrefix('api')
  app.use(
    helmet({
      crossOriginResourcePolicy: { policy: 'cross-origin' },
      contentSecurityPolicy: {
        directives: {
          defaultSrc: ["'none'"],
          frameAncestors: ["'none'"],
        },
      },
    }),
  )
  app.use(cookieParser())
  app.useGlobalFilters(new SentryExceptionFilter())
  app.useGlobalInterceptors(new LoggingInterceptor())

  app.enableCors({
    origin: appConfig.allowedOrigins,
    credentials: true,
    methods: ['GET', 'POST', 'PUT', 'PATCH', 'DELETE', 'OPTIONS'],
    exposedHeaders: ['X-Request-Id'],
  })
  app.enableShutdownHooks()
}
```

### Усиление аутентификации и безопасная сериализация ошибок
- **TTL `1d`, закрепление `HS256` и отказ при неверном `adminPasscode` (`AuthService`):**
  `KB_COOKIE_MAX_AGE_MS` сокращён до **1 дня** (`expiresIn: '1d'`), подпись жёстко фиксирует `algorithm: 'HS256'`, а верификация — `algorithms: ['HS256']`. При передаче непустого `adminPasscode` метод `isPasscodeMatch()` сравнивает SHA-256 хеши через `crypto.timingSafeEqual()` и при несовпадении выбрасывает **`403 ForbiddenException`** без тихого понижения до `USER`.
- **Защита `headersSent` и санитизация логов (`SentryExceptionFilter`):**
  При обрыве активного SSE-потока HTTP-заголовки уже отправлены клиенту — проверка `if (response.headersSent) return` предотвращает неперехваченное падение воркера с `ERR_HTTP_HEADERS_SENT`. Все пользовательские URL и заголовки проходят через `sanitizeLogValue()` (удаление ANSI-последовательностей, `\r\n` и управляющих символов) против Log Forging.
- **Zero-Eval санитизация MDX (`apps/web/src/entities/knowledge-content/lib/`):**
  `mdx-ast-parser.ts` отключает legacy eval-движки `js`/`javascript` в `gray-matter` и вырезает произвольные сырые HTML-блоки, а `link-sanitizer.ts` (`classifySafeMarkdownLink` / `isSafeMarkdownImageSrc`) блокирует `javascript:`, `data:` и protocol-relative ссылки `//` / `/\`.

## 5. `CsrfOriginMiddleware` и безопасные паттерны для будущих загрузок медиа

Поскольку куки `SameSite=Lax` не закрывают все кросс-сайтовые векторы (например, атаки с соседних поддоменов или простые HTML `<form>`-запросы), `AppModule` применяет `CsrfOriginMiddleware` на `'{*path}'` ко всем мутирующим методам (`POST`, `PUT`, `PATCH`, `DELETE`):

1. **JSON-only барьер `Content-Type` (`415 Unsupported Media Type`):** отклоняет любой мутирующий запрос с телом, чей `Content-Type` не содержит `application/json` — блокируя все три типа CORS «simple requests» (`application/x-www-form-urlencoded`, `text/plain`, `multipart/form-data`), которые кросс-сайтовая HTML-форма может отправить без preflight.
2. **Белый список `Origin` (`403 Forbidden`):** при наличии заголовка `Origin` он обязан входить в `appConfig.allowedOrigins`.
3. **Проверка `Sec-Fetch-Site` (`403 Forbidden`):** отклоняет любые значения `Sec-Fetch-Site`, отличные от `same-origin` и `none`, если `Origin` не находится в явном белом списке (сохраняя кросс-доменные запросы Vercel ➔ Render при настроенном `WEB_ORIGIN`).

### Архитектурные паттерны расширения для будущих загрузок файлов
Если в платформе появятся загрузка аватаров, вложений или медиафайлов, в `CsrfOriginMiddleware` зафиксированы два безопасных паттерна:
- **Паттерн A (Рекомендуемый — Presigned URLs для S3/R2):** клиент вызывает JSON-эндпоинт (`POST /api/storage/presign`), который проходит `CsrfOriginMiddleware` без изменений, получает короткоживущую подписанную ссылку и загружает бинарник напрямую в Cloudflare R2 / MinIO — API остаётся строго JSON-only без нагрузки на RAM Node.js.
- **Паттерн B (Точечный Multipart Proxy):** если отдельному маршруту NestJS всё же потребуется `multipart/form-data`, из JSON-проверки исключается **строго** этот конкретный путь по узкому allowlist с обязательным сохранением проверок `Origin`, `Sec-Fetch-Site` и кастомного заголовка для preflight (например, `X-Requested-With`).
- **Обязательное правило против Stored XSS:** никогда не принимать и не отдавать пользовательские `.svg` инлайн с домена приложения; разрешать только растровые форматы (`PNG`, `WebP`, `AVIF`, `JPEG`), проверенные по magic bytes и раздаваемые с изолированного CDN/R2-домена или под песочницей CSP.

## 6. Защита от брутфорса и DoS: общий бакет `@nestjs/throttler` и ограниченный SSE

`AppModule` устанавливает глобальный лимит **`60 req/min`** и кастомный `generateKey`, чтобы `/api/auth/guest-pass` (`issueGuestPass`) и его алиас `/api/auth/login` (`login`) делили **единый бакет `5 req/min`** — злоумышленник не сможет удвоить число попыток подбора пароля через два маршрута:

```typescript title="apps/api/src/app.module.ts"
const SHARED_AUTH_THROTTLE_HANDLERS = new Set(['issueGuestPass', 'login'])

ThrottlerModule.forRoot({
  throttlers: [{ ttl: 60000, limit: 60 }],
  generateKey: (context, trackerString, throttlerName) => {
    const className = context.getClass().name
    const handlerName = context.getHandler().name
    if (className === 'AuthController' && SHARED_AUTH_THROTTLE_HANDLERS.has(handlerName)) {
      return `AuthController:issuePass:${trackerString}:${throttlerName}`
    }
    return `${className}:${handlerName}:${trackerString}:${throttlerName}`
  },
})
```

### Ограниченный SSE вместо `@SkipThrottle()`
Вместо полного снятия лимита метод `TelemetryController.streamEvents()` использует **`@Throttle({ default: { limit: 5, ttl: 60000 } })`** (не более 5 переподключений в минуту с одного IP) в паре с **`@SkipTimeout()`**, чтобы `TimeoutInterceptor` не рвал открытый поток. Одновременно `TelemetryService` ограничивает активные стримы квотами **`2/IP`**, **`50` глобально** и максимальным временем жизни **`15 минут`** (`finalize()` освобождает слот при разрыве).

### Эволюция: In-Memory ➔ распределённый Redis Throttler
На одном инстансе работают бесплатные In-Memory счётчики. При горизонтальном масштабировании `apps/api` подключение `ThrottlerStorageRedisService` поверх `REDIS_URL` синхронизирует скользящие окна между репликами с автоматическим откатом на локальную память при отсутствии `REDIS_URL`.

## 7. Чек-лист защищённости, изоляция контейнеров и осознанные компромиссы

В `docker-compose.prod.yml` все контейнеры приложения (`web`, `api`, `telemetry-ms`) запускаются с `read_only: true`, `cap_drop: [ALL]`, `no-new-privileges:true`, `pids_limit: 256`, биндингом портов строго на `127.0.0.1`, обязательными секретами `${JWT_SECRET:?...}`, а PostgreSQL и TCP `:4001` изолированы внутри `backend-network`.

| Вектор угрозы | Механизм защиты в монорепозитории | Статус |
| :--- | :--- | :--- |
| **Кража сессии через XSS** | `HttpOnly` куки + Zero-Eval HAST (отключены JS-движки `gray-matter`) + `classifySafeMarkdownLink` | 🛡️ Защищено |
| **CSRF (Login/Logout/мутации)** | `SameSite=Lax` + `CsrfOriginMiddleware` (JSON-only `415`, `Origin` + `Sec-Fetch-Site` `403`) + удалён `urlencoded` | 🛡️ Защищено |
| **Clickjacking и XS-Leaks** | `X-Frame-Options: DENY`, CSP `frame-ancestors 'none'` (scoped `/cv/:path+`), `COOP: same-origin`, `CORP: same-origin` | 🛡️ Защищено |
| **Брутфорс и SSE-флуд** | Глобально `60/мин`, общий `5/мин` на auth, `403` на плохой `adminPasscode`, SSE `5/мин` + `2/IP` / `50` глобально / `15m` TTL | 🛡️ Защищено |
| **Log Forging и падение на стриме** | `resolveCorrelationRequestId` + `sanitizeLogValue` + проверка `response.headersSent` в `SentryExceptionFilter` | 🛡️ Защищено |
| **Побег из контейнера / утечка TCP** | Loopback `127.0.0.1:4001` по умолчанию + `docker-compose.prod.yml` (`read_only`, `cap_drop: ALL`, `backend-network`) | 🛡️ Защищено |

### Осознанные архитектурные компромиссы (Engineering Trade-offs)
1. **Статическая генерация `SSG` (`'unsafe-inline'`) против динамического `CSP Nonce`:**
   - *Компромисс:* Отказ от `'unsafe-inline'` в `script-src` требует генерации уникального `nonce` на каждый запрос, что принудительно переводит все **199** статических маршрутов из **SSG** в динамический `SSR` и лишает CDN-кэширования.
   - *Компенсация:* Платформа не рендерит пользовательский UGC HTML (все `.mdx` лежат в репозитории, компилируются Zero-Eval HAST с вырезанием сырого HTML и санитизацией ссылок), а JWT-сессии изолированы в `HttpOnly` куках.
2. **Гибридное дискавери (`/search-index/[locale]` и `/knowledge-base/this-project/**`) против защищённых конспектов:**
   - *Компромисс:* `proxy.ts` намеренно оставляет публичными `/search-index/[locale]`, `/knowledge-base` и `/knowledge-base/this-project/**` ради SEO и мгновенной оценки архитектуры рекрутерами, закрывая остальные категории БЗ fail-closed Edge `HS256` JWT-проверкой.
3. **Stateless-проверка `1d` JWT на Edge против мгновенного отзыва сессий (до Redis):**
   - *Компромисс:* `verifyEdgeJwtHs256` проверяет подпись и `exp` за `< 0.2 мс` без похода в БД, поэтому токен на **`1d`** нельзя отозвать индивидуально до истечения срока без ротации `JWT_SECRET`.
   - *Компенсация:* Сокращение TTL токена с 7 дней до **`1d`** радикально сужает окно риска, а Post-MVP Roadmap предусматривает связку **Redis** + короткий `Access` (`15m`) + ротируемый `HttpOnly Refresh` на базе `VisitorSession`.
