## 1. Architecture of Our 3-Tier Testing Pyramid

Rather than relying on slow UI tests for logic checks or mocking away entire frameworks, every workspace layer uses the lightest tool that preserves real runtime semantics:

```text
                        ▲
                       / \
                      /   \    Tier 3: Playwright POM E2E (apps/web/e2e/)
                     / E2E \   Real Chromium + built Next.js 16 + NestJS 12 webServer
                    /-------\
                   /  HTTP   \ Tier 2: NestJS AppModule + Supertest + RTL/MSW v3
                  /  & UI Int \ Real DI/Guards/Filters/Pipes & React Query + MSW v3
                 /-------------\
                /   Unit & Zod  \ Tier 1: Pure Vitest (shared-schemas, web, api)
               /_________________\ Schema contracts, Zustand store, Axios, Prisma fallback
```

| Layer | Runner & Libraries | Scope & Location | Key Guarantees |
| :--- | :--- | :--- | :--- |
| **Contracts (`Tier 1`)** | `Vitest` (Node) | `packages/shared-schemas/src/__tests__/` | `resolveEndpoint`, Zod defaults/bounds, integrity of 16 localized ADRs |
| **Web Unit (`Tier 1`)** | `Vitest` (`node` + `jsdom`) | `apps/web/src/shared/**/__tests__/` | Axios normalization, `verifyEdgeJwtHs256`, `QueryClient` error filter, `APP_ROUTES`, `useUIStore` |
| **Web Integration (`Tier 2`)** | `Vitest` + `RTL` + `MSW v3` | `apps/web/src/features/**/__tests__/` | Interactive pagination, category filter & sort transitions wired through real `TanStack Query` |
| **API Unit (`Tier 1`)** | `Vitest` + `unplugin-swc` | `apps/api/src/**/__tests__/*.spec.ts` | `app.config` prod guards, `request-id` CRLF sanitization, `PrismaService` fallback, `AuthService` / `JwtRolesGuard` |
| **Telemetry Unit (`Tier 1`)** | `Vitest` (Node + `@vitest/coverage-v8`) | `apps/telemetry-ms/src/__tests__/` | `TelemetryMicroserviceController` schema validation, bounded 50-event ring, and `getStats()` |
| **API HTTP E2E (`Tier 2`)** | `Vitest` + `Supertest` | `apps/api/test/*.e2e-spec.ts` | Full `AppModule` bootstrap (`CORS`, `CookieParser`, `ThrottlerGuard`, `ValidationPipe`, `HttpOnly` JWT) |
| **Browser E2E (`Tier 3`)** | `Playwright` Chromium | `apps/web/e2e/{fixtures,pages,specs}/` | Edge `src/proxy.ts` JWT verification, `GuestPassModal` unlock flow, `/system-status` inspection |

> [!NOTE]
> **Storybook 10 (`@repo/ui`) vs Vitest / Playwright:** UI primitives live in `packages/ui/` and are visually inspected in Storybook without coupling business API state into design-system stories. Logic, caching, RBAC redirects, and full-stack hydration stay inside `Vitest` + `Playwright`.

## 2. Why `Vitest` + `unplugin-swc` Replaced `Jest` and `ts-jest`

Our monorepo targets **`TypeScript 7` + `NodeNative ESM` (`"type": "module"`)**, which surfaces two blockers for legacy `Jest` stacks:

1. **`ts-jest` TypeScript Compiler Coupling:** `ts-jest` relies on older TypeScript JS compiler internals (`typescript <7`) and often requires experimental `--experimental-vm-modules` flags with brittle CJS/ESM transforms.
2. **NestJS `emitDecoratorMetadata` in ESM:** Vite's default `esbuild` / `oxc` strips TypeScript decorator parameter metadata (`design:paramtypes`) required by NestJS Dependency Injection (`ConfigService`, `JwtService`, `PrismaService`). Replacing it via **`unplugin-swc`** inside `apps/api/vitest.base.ts` preserves `decoratorMetadata: true` at Rust speed.

```ts title="apps/api/vitest.base.ts"
function resolveTsExtensionPlugin(): Plugin {
  return {
    name: 'resolve-ts-extensions',
    enforce: 'pre',
    resolveId(source, importer) {
      if (!importer || !source.startsWith('.') || !source.endsWith('.js')) return null
      const base = path.resolve(path.dirname(importer), source.slice(0, -3))
      for (const ext of ['.ts', '.tsx']) {
        if (fs.existsSync(base + ext)) return base + ext
      }
      return null
    },
  }
}
```

### Three NestJS-Specific Vitest Requirements

1. **Explicit `.js` ➔ `.ts` Vite Resolver:** TypeScript `NodeNext` requires importing `./auth.service.js` in `.ts` sources. While `tsc` handles this automatically, Vite resolves raw source files during tests—so `resolveTsExtensionPlugin()` maps relative `.js` imports back to `.ts` before bundling.
2. **`reflect-metadata` + `pool: 'forks'`:** `apps/api/vitest.setup.ts` imports `'reflect-metadata'` once before any NestJS controller loads, and **`pool: 'forks'`** avoids worker-thread native `@swc/core` registration crashes on Windows/Linux.
3. **`SWC_NATIVE_BINDING_CACHE` + `passThroughEnv`:** On Windows or constrained sandboxes where `%LOCALAPPDATA%\swc` is blocked or nested paths approach `MAX_PATH`, `@swc/core@1.16` fails unless pointed to a short writable cache folder. Setting a fallback to `.turbo/swc` in `vitest.base.ts` **and** declaring `"passThroughEnv": ["SWC_NATIVE_BINDING_CACHE"]` in `turbo.json` guarantees Turborepo forwards the override instead of stripping it under Strict Env Mode.

## 3. Frontend Testing Patterns: React 19, `TanStack Query`, and `MSW v3`

Modern React 19 + Next.js App Router testing requires deliberate isolation of async timers, browser APIs, and DOM cleanup:

### Essential Patterns Implemented in `apps/web`

- **Explicit `'vitest'` Imports + `afterEach(cleanup)`:** Biome and strict TS work cleanly without injecting ambient `describe`/`it`/`expect` globals (`globals: false`). Because `@testing-library/react` only registers automatic cleanup when global `afterEach` exists, `apps/web/vitest.setup.ts` calls `afterEach(() => cleanup())` explicitly—preventing duplicate DOM elements across multiple `render()` calls in one file.
- **No Unhandled Requests in `MSW v3`:** Integration suites call `server.listen({ onUnhandledFrame: 'error' })` inside `beforeAll`, `server.resetHandlers()` in `afterEach`, and `server.close()` in `afterAll`. Any accidental unmocked `/api/*` URL immediately fails the test loudly instead of hanging or hitting localhost.
- **Deterministic Async Cancellation vs Fake Timers:** Testing `makeQueryClient()`'s `AbortError` suppression with real network teardown calls `unmount()` on an in-flight `useQuery` hook wrapped with a deferred `Promise` that stays clean—zero flaky timeouts or unhandled rejections.
- **`window.indexedDB` Availability Guard:** `QueryProvider` persists cache via `idb-keyval` + `IndexedDB`. Because `jsdom` does not bundle a browser `IndexedDB` backend by default, checking `typeof window.indexedDB !== 'undefined'` keeps client components crash-free in both SSR and unit tests without polluting prod logic with mock hacks.
- **Radix UI Portals in Component Tests:** Clicking a Radix `<Select>` or `<Dialog>` trigger portals options directly to `document.body` outside the test wrapper; queries always run through `@testing-library/react` `screen` (which reads `document.body`) paired with `@testing-library/user-event` (`pointer-events` and keyboard events).

## 4. Playwright E2E: `POM`, `test.step`, `Zero-Cruft data-testid`, and Scalable `WebServer`

End-to-end specs live in `apps/web/e2e/` and follow the **Page Object Model (POM)**:

```text
apps/web/e2e/
├── fixtures/app.fixture.ts         # Injects GuestPassPage & SystemStatusPage fixtures
├── pages/
│   ├── guest-pass.page.ts          # Encapsulates modal open, displayName, visitorType, submit
│   └── system-status.page.ts       # Encapsulates capabilities matrix, leaderboard page 2, live events
└── specs/
    └── rbac-and-observability.spec.ts # Full RBAC + /system-status verification structured via test.step()
```

### Engineering Rules for Maintainable E2E Suites

1. **`Zero-Cruft data-testid` Policy:** Playwright locators **never** depend on localized UI copy (`"Get Pass"`, `"Next"`, `"Отримати"`) or semantic HTML tags (`table`, `h2`) that break during copy edits or design refactors. At the same time, `data-testid` attributes (`guest-pass-dialog`, `guest-pass-submit-btn`, `leaderboard-table`, etc.) are added **strictly** to elements actually queried by tests—never sprayed speculatively across production JSX.
2. **Structured Monitoring with `test.step(...)`:** Every scenario splits actions into crisp telemetry steps (`Navigate to protected Knowledge Base route triggers GuestPassModal`, `Submit GuestPass form unlocks HttpOnly JWT session and article content`, `Inspect /system-status capabilities matrix, leaderboard pagination, and live telemetry events`), turning CI HTML reports and IDE traces into readable step-by-step timelines.
3. **Scalable Workers + Serial Stateful Suites:** `playwright.config.ts` enables `fullyParallel: true` (`...(process.env.CI ? { workers: 2 } : {})`), allowing independent read-only specs to scale automatically across CPU cores as the suite grows, while `test.describe.configure({ mode: 'serial' })` keeps stateful auth -> event-log verification strictly ordered without sharing global state across files.
4. **Windows Node 24 Happy Eyeballs & Next.js Proxy (`NODE_OPTIONS`):** When `playwright.config.ts` spawns `next start` (`localhost:3000`) + NestJS `apps/api` (`0.0.0.0:4000`), **Node 24's IPv6-first DNS (`::1`) + Happy Eyeballs** can trigger concurrent proxy `AggregateError` (`ECONNREFUSED ::1:4000`) when Next.js rewrites forward `/api/*` requests to an IPv4-bound API. Passing `NODE_OPTIONS: '--dns-result-order=ipv4first --no-network-family-autoselection'` inside Next.js's `webServer.env` resolves `localhost` deterministically to `127.0.0.1` across both Windows and Linux.

## 5. Monorepo IDE Testing Sidebar (`vitest.config.ts`) & CI Integration

### Root Workspace Discovery for IDE Test Explorer

Running `Vitest` in each workspace package keeps `Turborepo --affected` fast, **but** VS Code / Cursor Testing extensions scan only the workspace root by default. Adding a lightweight root `vitest.config.ts`:

```ts title="vitest.config.ts"
import { defineConfig } from 'vitest/config'

export default defineConfig({
  test: {
    projects: ['packages/*', 'apps/*'],
  },
})
```

Paired with `"vitest.explorer"` + `"ms-playwright.playwright"` in `.vscode/extensions.json` and `.vscode/settings.json` (`"playwright.config": "apps/web/playwright.config.ts"`), both the **Vitest tree** and **Playwright specs** appear side-by-side in the IDE Testing sidebar—while Turborepo continues caching package tests independently.

### GitHub Actions CI Integration

- **Stage 1 (`unit-tests`):** runs in parallel alongside `lint`, `security`, and `typecheck` with `prepare-codegen: "true"` and `fetch-depth: '0'` + `TURBO_SCM_BASE` on PRs (`turbo run test --affected` + `pnpm --filter @repo/api test:e2e`).
- **Stage 2 (`e2e`):** waits for `needs: [ lint, typecheck, build ]`, restores `.turbo` build outputs and `~/.cache/ms-playwright` keyed to the locked Playwright version in `pnpm-lock.yaml`, runs `pnpm --filter @repo/web test:e2e`, and uploads HTML reports/traces via `actions/upload-artifact@v7` exclusively on `failure()`.
