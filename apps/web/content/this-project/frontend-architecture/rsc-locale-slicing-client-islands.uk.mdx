## 1. Серверна нарізка локалей і розділення неймспейсів через `pickIntlMessages()`

У багатомовних застосунках (`EN / UK / RU`) до роздування початкового завантаження найчастіше призводять два приховані витоки:
1. Імпорт тримовних TypeScript-словників (`author-profile.ts`, `tech-radar`, `engineering-roadmap`) усередині `'use client'` пакує всі 3 мови в браузерний JS-чанк.
2. Передача повного об'єкта `getMessages()` в один кореневий `<NextIntlClientProvider>` серіалізує переклади всіх сторінок застосунку в SSR HTML кожного маршруту.

Обидві проблеми вирішено на сервері:
- **Нарізка типізованих даних:** основні секції головної (`WorkfolioHeroSection`, `WorkfolioProjectsSection`, `WorkfolioExperienceSection`, `WorkfolioFooter`) та `CvDocumentShowcase` є **Server Components**, обирають лише активну локаль через `pickLocalized(field, locale)` і передають у тонкі клієнтські острови готові рядки або `ReactNode`.
- **Нарізка словників через `pickIntlMessages()` (`apps/web/src/shared/i18n/pick-messages.ts`):**
  - Кореневий `apps/web/src/app/[locale]/layout.tsx` передає **лише** `['Header', 'GuestPassModal', 'KnowledgeBase', 'ErrorPage']`.
  - Окремі сторінки обгортають свої клієнтські піддерева точковими `<NextIntlClientProvider>`: головна (`['TechRadar', 'Roadmap']`), `/cv` (`['CvPage']`) та `/system-status` (`['SystemStatusPage']`).

### Серверний острів `CvDocumentShowcase` + `CvViewTabs` (`forceMount`)
На маршруті `/[locale]/cv` серверний компонент `CvDocumentShowcase` (`apps/web/src/entities/workfolio-profile/cv-document-showcase.tsx`) рендерить повне структуроване ATS-резюме на сервері й передає його через слот `structuredSlot={structuredResumeNode}` у клієнтський острів `CvViewTabs` (`cv-view-tabs.tsx`). Вкладка структурованого резюме використовує Radix `forceMount` та приховування через CSS:

```tsx title="apps/web/src/entities/workfolio-profile/cv-view-tabs.tsx"
<TabsContent value="structured" forceMount className="mt-0 data-[state=inactive]:hidden">
  {structuredSlot}
</TabsContent>
```

Пошукові краулери завжди отримують повний семантичний HTML резюме під час SSR навіть за активної вкладки `'pdf'`, а тримовний словник `author-profile.ts` займає рівно `0 КБ` у клієнтському JS.

## 2. Клієнтські мікро-острови, ліниві завантажувачі модалок і синглтон SSE із `bfcache`

Кожна інтерактивна точка ізольована у власний легковаговий компонент:

| Мікро-острів / Завантажувач | Файл | Призначення й актуальні пропси |
| :--- | :--- | :--- |
| **`HeroActionRow`** | `workfolio-client-islands.tsx` | Перехід на `/knowledge-base`, `/cv` та плавний скрол до `#tech-radar` / `#roadmap` (`ctaUnlocked`, `ctaLocked`, `ctaCvPdf`, `ctaTechRadar`, `ctaRoadmap`) |
| **`CaseStudyReadButton`** | `workfolio-client-islands.tsx` | Збирає `/knowledge-base/${category}/${slug}`, перевіряє `isUnlocked \|\| isPublicKnowledgeBasePath(targetUrl)` і або переходить, або викликає `openGuestPassModal(targetUrl)` (`category`, `slug`, `readUnlockedLabel`, `readLockedLabel`) |
| **`EarlierRolesDisclosure`** | `workfolio-client-islands.tsx` | Акордеон раннього досвіду роботи (`showLabel`, `hideLabel`, серверний `children: ReactNode`) |
| **`FooterSseStatus`** | `footer-sse-status.tsx` | Живий індикатор телеметрії з посиланням на `/system-status` (`waitingLabel`, `inspectLabel = 'Inspect Live API'`) поверх `useTelemetryStream()` |

| **`CommandPaletteLoader`** | `command-palette-loader.tsx` | Слухає глобальне поєднання `Cmd+K` / `Ctrl+K` і ліниво завантажує `CommandPaletteModal` через `next/dynamic(..., { ssr: false })` |

### Ref-Counted синглтон `EventSource` і гігієна `bfcache` (`use-telemetry-stream.ts`)
Замість відкриття окремих сокетів `EventSource` у `FooterSseStatus` та `SystemStatusDashboard` модуль `apps/web/src/features/telemetry-stream/use-telemetry-stream.ts` інкапсулює єдиний `SharedTelemetryStreamManager`, підключений до React через `useSyncExternalStore`:

- **Одне з'єднання на вкладку:** ведеться підрахунок посилань активних підписників (`this.listeners.size === 1` відкриває з'єднання, `0` — закриває), що дотримується бекенд-ліміту `MAX_SSE_STREAMS_PER_IP = 2` та обмеження браузера в 6 HTTP/1.1 з'єднань на origin.
- **Обмежений експоненційний backoff:** після `EventSource.CLOSED` (наприклад, через `429`/`500` або 15-хвилинний серверний TTL потоку) виконує перепідключення від `2с` до `30с` (максимум `6` спроб, лічильник скидається за подіями `online` / `pageshow`).
- **Гігієна `bfcache`:** закриває потік на `pagehide` і відновлює його за `event.persisted === true` на `pageshow`:

```typescript title="apps/web/src/features/telemetry-stream/use-telemetry-stream.ts"
private readonly handlePageHide = (): void => {
  this.clearReconnectTimer()
  this.closeSource()
  if (this.snapshot.sseConnected) {
    this.emitSnapshot({ ...this.snapshot, sseConnected: false })
  }
}

private readonly handlePageShow = (event: PageTransitionEvent): void => {
  if (event.persisted && this.listeners.size > 0) {
    this.reconnectAttempts = 0
    this.connect()
  }
}
```

## 3. `React 19 Compiler` та атомарні межі стану (`useState` проти `Zustand`)

В `apps/web/next.config.ts` активовано `reactCompiler` (`compilationMode: 'infer'`, `panicThreshold: 'none'`). Клієнтський стан розділено суворо за областю життя:
- **Локальний `useState`:** використовується всередині інтерактивних симуляцій `D3.js` (`d3-architecture-flow.tsx`, `d3-react-render-graph.tsx`) та вкладок `CvViewTabs`, щоб локальні перемикання не викликали ререндер сусідніх гілок.
- **Атомарний `Zustand` (`apps/web/src/shared/store/use-ui-store.ts`):** базовий хук `useUIStoreBase` прихований, а назовні експортуються лише явні атомарні хуки (`useIsGuestPassModalOpen`, `useIsCommandPaletteOpen`, `useTechRadarCategoryFilter`, `useExpandedKbFolders`, `usePalette` тощо) і стабільний `useUIActions()` — без проксі `createSelectors`, без зберігання серверних/auth-даних у Zustand і з SSR-безпечною синхронізацією `sessionStorage` / `localStorage`.

## 4. Enterprise-шар запитів: `apiClient`, allowlist IndexedDB та `AuthCrossTabSyncBridge`

Клієнтська робота з API (`'use client'` + `TanStack Query v5`) спроєктована з акцентом на офлайн-безпеку, крос-вкладкову синхронізацію та чистоту обробки помилок:

1. **Єдині реєстри `API_ENDPOINTS` та `APP_ROUTES`:**
   - Контракти API описані в `@repo/shared-schemas` (`API_ENDPOINTS` + `resolveEndpoint`), а маршрути та предикати гібридного доступу до БЗ (`isPublicKnowledgeBasePath`, `isProtectedKnowledgeBasePath`) — в `apps/web/src/shared/i18n/app-routes.ts`.
2. **Типізований Axios `apiClient` (`apps/web/src/shared/lib/api-client.ts`):**
   - Ізольований інстанс `axios.create({ withCredentials: true, allowAbsoluteUrls: false, timeout: 16_000 })` із рантайм-валідацією `Zod`, витягуванням `X-Request-Id` у `ApiClientError`, фільтрацією порожніх query-параметрів та підтримкою `AbortSignal`.
3. **Суворий allowlist персистенції IndexedDB (`apps/web/src/shared/providers/query-provider.tsx`):**
   - `QueryProvider` передає в `persistQueryClientSubscribe` опцію `dehydrateOptions: { shouldDehydrateQuery: shouldPersistQueryToIndexedDb }`, де `PERSISTABLE_QUERY_ROOT_KEYS = new Set(['knowledge'])`.
   - **Захист свіжості й безпеки:** в IndexedDB зберігаються лише офлайн-безпечні запити `['knowledge', ...]`; сесія `['auth', 'me']` (щоб не воскрешати прострочені/відкликані токени на 24 години) та волатильні запити спостережуваності (`['telemetry', ...]`, `['system', ...]`) ніколи не записуються на диск.
   - Глобальний `QueryCache({ onError })` фільтрує `AbortError` / скасування React 19 `StrictMode` і очікувані `4xx` відповіді, передаючи в `captureClientException` лише реальні мережеві/5xx збої.
4. **Єдиний крос-вкладковий міст `AuthCrossTabSyncBridge` (`apps/web/src/features/auth/auth-cross-tab-sync-bridge.tsx`):**
   - Монтується рівно один раз у кореневому `[locale]/layout.tsx` усередині `QueryProvider`, відкриваючи **один** канал `BroadcastChannel('workfolio_auth_sync')` на всю вкладку браузера (замість окремої підписки в кожному `useVisitorProfile()`) для миттєвої інвалідації `VISITOR_PROFILE_QUERY_KEY` та `['knowledge']` під час входу за Guest Pass або виходу.
