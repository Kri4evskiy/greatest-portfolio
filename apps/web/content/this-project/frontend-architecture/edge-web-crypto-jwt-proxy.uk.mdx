## 1. Єдине джерело констант безпеки в `@repo/shared-schemas`

Щоб фронтенд (`apps/web`) та бекенд (`apps/api`) ніколи не розсинхронізувалися в назві `HttpOnly`-куки, часі її життя або правилах читання `JWT_SECRET`, ці примітиви експортуються зі спільного пакета `@repo/shared-schemas`:

```typescript title="packages/shared-schemas/src/auth.schema.ts"
export const KB_ACCESS_COOKIE_NAME = 'kb_access_token'
export const KB_COOKIE_MAX_AGE_MS = 1000 * 60 * 60 * 24 * 7 // 7 days
export const DEFAULT_DEV_JWT_SECRET = 'workfolio-super-secret-jwt-key-2026'

export function resolveJwtSecret(envSecret?: string): string {
  const trimmed = envSecret?.trim()
  return trimmed && trimmed.length > 0 ? trimmed : DEFAULT_DEV_JWT_SECRET
}
```

У локальній розробці обидва сервіси підхоплюють спільний фолбек без обов'язкового ручного налаштування `.env`, а в продакшені єдина функція `resolveJwtSecret` гарантує ідентичне читання `JWT_SECRET` для підпису в NestJS та перевірки в Next.js.

## 2. Верифікація `HS256` через нативний Web Crypto API (`crypto.subtle`)

Оскільки сторінки Бази Знань передгенеруються в статику (`SSG`), перевірка доступу має виконуватися просто на межі мережі в Edge Runtime до віддачі HTML. Замість підключення сторонніх бібліотек модуль `apps/web/src/lib/edge-jwt.ts` використовує вбудований стандарт **Web Crypto API**:

```typescript title="apps/web/src/lib/edge-jwt.ts"
let cachedSecretString: string | null = null
let cachedHmacKeyPromise: Promise<CryptoKey> | null = null

function getHmacKey(secret: string): Promise<CryptoKey> {
  if (cachedSecretString === secret && cachedHmacKeyPromise !== null) {
    return cachedHmacKeyPromise
  }
  cachedSecretString = secret
  cachedHmacKeyPromise = crypto.subtle.importKey(
    'raw',
    new TextEncoder().encode(secret),
    { name: 'HMAC', hash: 'SHA-256' },
    false,
    ['verify'],
  )
  return cachedHmacKeyPromise
}
```

Функція `verifyEdgeJwtHs256(token, secret)` за `< 0.2 мс` виконує 4 перевірки:
1. Розбиває токен на 3 сегменти (`header.payload.signature`) та декодує Base64URL у `Uint8Array`.
2. Переконується, що заголовок явно вказує `alg === 'HS256'` (захист від підміни алгоритму `alg: "none"`).
3. Викликає константну за часом перевірку підпису `crypto.subtle.verify('HMAC', key, signatureBytes, signingInput)`.
4. Перевіряє термін дії `payload.exp * 1000 > Date.now()`.

## 3. Чиста композиція в `apps/web/src/proxy.ts`

Уся криптографічна математика прихована в `edge-jwt.ts`, тому сам `proxy.ts` відповідає виключно за маршрутизацію:

```typescript title="apps/web/src/proxy.ts"
export async function proxy(request: NextRequest): Promise<NextResponse> {
  const { pathname } = request.nextUrl
  const kbMatch = pathname.match(PROTECTED_KB_REGEX)

  if (kbMatch) {
    const token = request.cookies.get(KB_ACCESS_COOKIE_NAME)?.value
    const isValid = await verifyEdgeJwtHs256(token)

    if (!isValid) {
      const matchedLocale = kbMatch[1]
      const homePath = matchedLocale && matchedLocale !== routing.defaultLocale ? `/${matchedLocale}` : '/'
      const redirectUrl = new URL(homePath, request.url)
      redirectUrl.searchParams.set('unlock', 'knowledge-base')
      redirectUrl.searchParams.set('redirect', pathname)

      const response = NextResponse.redirect(redirectUrl)
      if (token) {
        response.cookies.delete(KB_ACCESS_COOKIE_NAME)
      }
      return response
    }
  }

  return handleI18nRouting(request)
}
```
