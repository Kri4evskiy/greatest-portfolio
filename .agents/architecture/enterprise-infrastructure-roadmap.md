# 🏛️ Enterprise Infrastructure & Cloud Architecture Roadmap

Этот документ представляет собой прагматичный архитектурный план инфраструктуры монорепозитория, контейнеризации, распределенного кэширования, хостинга бэкенда и сравнения облачных платформ (Cloudflare vs AWS).

---

## 1. Где и как живут сервисы: Фронтенд, Бэкенд и Микросервисы

В классической Serverless-модели (например, Vercel) отлично живет фронтенд, но бэкенд с долгоживущими соединениями требует отдельного подхода.

### Архитектурная дилемма:

1. **Фронтенд (`apps/web` Next.js 16):**
   - Развернут на **Vercel** ($0, Hobby).
   - Выполняет SSG/SSR, рендерит React Server Components, отдает статику и MDX.
   - Vercel автоматически дает глобальный CDN, бесплатный SSL-сертификат и домен.
2. **Бэкенд (`apps/api` NestJS 12) и Микросервис (`apps/telemetry-ms`):**
   - **Не могут жить на Serverless Vercel:** у нас есть постоянный SSE-поток (`@Sse('stream')`), который держит открытое HTTP-соединение с браузером часами, и внутренний микросервис телеметрии, слушающий сырой TCP-сокет (`порт 4001`). Serverless-функции Vercel принудительно засыпают через 10–15 секунд.
   - **Где крутится бэкенд-машинка?** Есть 2 практических сценария:

| Сценарий                                      | Стек хостинга                                                   | Стоимость    | Роль Nginx                                                  |
| :-------------------------------------------- | :-------------------------------------------------------------- | :----------- | :---------------------------------------------------------- |
| **Сценарий 1: Облачный PaaS (Рекомендуемый)** | **Vercel** (web) + **Render.com / Koyeb** (api + ms в Docker)   | **$0.00**    | **Не нужен:** Render и Vercel сами дают HTTPS и роутинг     |
| **Сценарий 2: Собственный VPS (Self-Hosted)** | **1 VPS Linux** (1 vCPU, 2GB RAM: Hetzner / Timeweb / FirstVDS) | **$2–3/мес** | **Нужен как Reverse Proxy:** принимает 80/443 и раздает SSL |

> [!NOTE] Почему нам НЕ нужен балансировщик нагрузки (Load Balancer)
> Проект не является терабайтным хайлоадом с десятками серверов. У нас один оптимизированный процесс Node.js / Docker. Балансировщик нагрузки здесь был бы избыточным усложнением (over-engineering). Nginx рассматривается **исключительно как Reverse Proxy** (для Сценария 2 на VPS) для привязки домена и сквозного проксирования портов.

## 2. Сравнение Cloudflare vs Amazon Web Services (AWS)

Для хранения файлов (PDF-резюме, диаграммы, ассеты) и интерактивных функций мы сравнили двух облачных гигантов:

| Критерий                      | Amazon Web Services (AWS S3 + Lambda)                        | Cloudflare (R2 + Workers)                                      | Победитель для проекта |
| :---------------------------- | :----------------------------------------------------------- | :------------------------------------------------------------- | :--------------------- |
| **Хранилище (Объем)**         | 5 ГБ бесплатно (только первые 12 месяцев)                    | **10 ГБ бесплатно навсегда**                                   | 🏆 **Cloudflare R2**   |
| **Исходящий трафик (Egress)** | **Платно!** После лимита ~$0.09 за каждый скачанный гигабайт | **$0.00 (Zero Egress Fees)** — трафик полностью бесплатен!     | 🏆 **Cloudflare R2**   |
| **Запросы на чтение (GET)**   | 20 000 в месяц                                               | **10 000 000 (10 млн) в месяц бесплатно**                      | 🏆 **Cloudflare R2**   |
| **Совместимость с кодом**     | Родной AWS SDK (`@aws-sdk/client-s3`)                        | **100% S3-совместимый API** (работает через тот же `@aws-sdk`) | 🤝 **Ничья**           |
| **Сложность настройки**       | Высокая (IAM, политики доступа, ARNs, сложный биллинг)       | Низкая (создание бакета в 2 клика, простой API токен)          | 🏆 **Cloudflare R2**   |
| **Изолированный запуск кода** | AWS Lambda (1 млн вызовов бесплатно)                         | Cloudflare Workers (100k запросов/день бесплатно)              | 🤝 **Ничья**           |

### Итоговый вердикт:

- **Для объектного хранилища (PDF, диаграммы):** Однозначно **Cloudflare R2**. В AWS S3 существует риск случайных списаний за трафик, если кто-то запустит парсер или скачает резюме сотни раз. Cloudflare R2 гарантирует **$0 за трафик навсегда**. При этом в TypeScript мы используем стандартный `@aws-sdk/client-s3`, просто указывая `endpoint: cloudflare_r2_url`.
- **Локальная альтернатива:** Для полной автономности без интернета в `docker-compose.yml` подключается контейнер `minio/minio` (тот же S3 API, работающий локально).

## 3. Интерактивные статьи и песочницы технологий (Interactive Showcases)

Ключевая идея развития базы знаний: **переход от простого чтения текста к интерактивному взаимодействию («потрогать технологию руками»)**.

Статьи делятся на два типа:
1. **Теоретический Deep-Dive:** фундаментальные разборы концепций архитектуры, ADR и стандартов.
2. **Interactive Tech Showcase:** статьи со встроенными живыми виджетами и песочницами.

### 3 уровня реализации интерактивных песочниц:

```text
┌────────────────────────────────────────────────────────────────────────┐
│                   3 Уровня Интерактивных Песочниц                      │
├──────────────────────────┬─────────────────────────┬───────────────────┤
│ Уровень 1: Client Island │ Интерактив в браузере   │ Zod JSON Editor,  │
│ (0 мс, $0 затрат)        │ через React 19 State    │ JWT WebCrypto AST │
├──────────────────────────┼─────────────────────────┼───────────────────┤
│ Уровень 2: Live Backend  │ Реальный вызов нашего   │ SSE Telemetry,    │
│ (Экосистема монорепо)    │ NestJS API и TCP-сокета │ Redis Cache Test  │
├──────────────────────────┼─────────────────────────┼───────────────────┤
│ Уровень 3: Cloud Sandbox │ Изолированный запуск    │ Безопасный запуск │
│ (Serverless Worker)      │ кода через Cloudflare   │ кода пользователя │
└──────────────────────────┴─────────────────────────┴───────────────────┘
```

#### Примеры интерактивных модулей в статьях:

- **В статье про Zod Contracts:** Интерактивное поле ввода JSON, где читатель может ввести некорректные данные и в реальном времени увидеть ошибки форматирования Zod v4.
- **В статье про Edge Web Crypto:** Живой генератор подписи HMAC-SHA256, проверяющий валидность токена прямо в браузере через нативный `crypto.subtle`.
- **В статье про SSE и Микросервисы:** Кнопка _«Сгенерировать событие телеметрии»_. При нажатии запрос летит в `apps/api`, оттуда по TCP `:4001` в `apps/telemetry-ms`, и читатель видит, как в живом индикаторе футера мгновенно мигает статус и отображается его событие!
- **В статье про Redis:** Интерактивный замер задержки: читатель делает запрос и видит плашку: _«Cache Miss: 42ms (PostgreSQL)»_, а при повторном клике: _«Cache Hit: 0.8ms (Redis RAM)»_.

## 4. Пакетная архитектура Redis: `@repo/redis`

Вместо хаотичной установки библиотек в разные сервисы, создается переиспользуемый воркспейс-пакет:

```text
packages/redis/
├── package.json          # "@repo/redis", dependencies: ioredis, zod
├── tsconfig.json
└── src/
    ├── index.ts          # Экспорт готового модуля
    ├── redis.client.ts   # Клиент с автоматическим реконнектом
    ├── cache-aside.ts    # Декларативный хелпер: getOrSet(key, ttl, fetcher)
    └── keys.contract.ts  # Строгие Zod-схемы генерации ключей кэша
```

И `apps/api`, и `apps/telemetry-ms` подключают кэш через единый контракт `"@repo/redis": "workspace:*"`.

## 5. Архитектурный паттерн: "The Big Toggle" (Автономный офлайн-режим)

Возможность в любой момент отключить все внешние облака и запустить 100% функционала локально:

| Сервис               | Облачный режим (Cloud Hybrid, $0)     | Локальный офлайн-режим (Air-Gapped Local, $0)  |
| :------------------- | :------------------------------------ | :--------------------------------------------- |
| **База данных**      | Neon.tech PostgreSQL (Serverless TLS) | Локальный `postgres:16-alpine` (Docker Volume) |
| **Кэш / Throttler**  | Upstash Redis (Serverless TCP/REST)   | Локальный `redis:7-alpine` или In-Memory RAM   |
| **Хранилище файлов** | Cloudflare R2 (S3 API, $0 Egress)     | Локальный `minio:alpine` (Docker)              |
| **Телеметрия**       | Sentry Cloud + PostHog Cloud          | Локальный fallback (Console Logger / No-op)    |
| **Фронтенд & MDX**   | Vercel Edge Network                   | Локальный `next start` (чтение файлов с диска) |
| **Микросервис**      | Приватная сеть Render/Koyeb           | Внутренний контейнер `telemetry-ms` (TCP 4001) |

### Команда автономного пуска:

```bash
# Поднимает локальные контейнеры и запускает проект без внешних зависимостей:
docker compose up -d
# или нативно через Turborepo:
pnpm turbo dev
```
Если в `.env` отсутствуют внешние ключи, приложение автоматически переключается на встроенные In-Memory хранилища и локальные MDX-файлы. Ни цента расходов и нулевая зависимость от интернета.
