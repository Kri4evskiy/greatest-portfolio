## 1. Multi-Stage Build Pipeline (`pruner -> builder -> runner`)

To keep source files, compilers, and unrelated workspace packages out of production images, every Dockerfile in `docker/` separates container construction into three deterministic stages:

1. **`pruner`:** runs `turbo prune @repo/<app> --docker` to emit the minimal subgraph (`out/json/`, `out/full/`, `out/pnpm-lock.yaml`) needed by the target service.
2. **`builder`:** activates `pnpm@12.21.0`, runs `pnpm install --frozen-lockfile --ignore-scripts` with a shared BuildKit cache mount, and runs `pnpm turbo run build --filter=@repo/<app>...`. Backend containers (`api`, `telemetry-ms`) then run `pnpm prune --prod --ignore-scripts`; the frontend container (`web`) sets `DOCKER_STANDALONE=true` so Next.js `output: 'standalone'` traces only the runtime files needed by `server.js` (no `pnpm prune` step required).
3. **`runner`:** copies only compiled runtime artifacts and executes under a non-root user (`USER node` for `api`/`telemetry-ms`, `USER nextjs` UID `1001` for `web`).

## 2. `turbo prune` & Shared BuildKit Cache Mount

When building multiple containers from one monorepo, `out/json/` keeps the dependency installation layer cached across code changes, while mounting `/root/.local/share/pnpm/store` with BuildKit `type=cache,id=pnpm` downloads shared packages once and reuses them across all service builds:

```dockerfile title="docker/api.Dockerfile"
FROM node:22-alpine AS pruner
RUN apk add --no-cache libc6-compat openssl
ENV DO_NOT_TRACK=1
ENV TURBO_TELEMETRY_DISABLED=1
RUN npm install -g turbo@^2
WORKDIR /app
COPY . .
RUN turbo prune @repo/api --docker

FROM node:22-alpine AS builder
RUN apk add --no-cache libc6-compat openssl
ENV DO_NOT_TRACK=1
ENV TURBO_TELEMETRY_DISABLED=1
RUN corepack enable && corepack prepare pnpm@12.21.0 --activate && pnpm --version
WORKDIR /app

COPY --from=pruner /app/out/json/ .
COPY --from=pruner /app/out/pnpm-lock.yaml ./pnpm-lock.yaml
RUN --mount=type=cache,id=pnpm,target=/root/.local/share/pnpm/store \
    pnpm install --frozen-lockfile --ignore-scripts
```

## 3. Two Slimming Strategies: `pnpm prune` (Backend) vs `output: 'standalone'` (Web)

### Backend (`api` & `telemetry-ms`): `pnpm prune --prod` with Rust-Free Prisma 7

In `docker/api.Dockerfile` (and identically without `openssl` in `docker/telemetry-ms.Dockerfile`), `pnpm turbo run build --filter=@repo/api...` generates the Prisma 7 ESM client (`prisma-client`) into `apps/api/src/generated/prisma/` and compiles it via `tsc` into `apps/api/dist/generated/prisma/`. Because Prisma 7 replaces the legacy `.prisma/client` Rust binary engine with a Wasm query compiler bundled inside production `@prisma/client` (paired with `@prisma/adapter-pg` and `pg`), `pnpm prune --prod --ignore-scripts` needs no `/tmp` staging hack and the `runner` stage does not even install `openssl`:

```dockerfile title="docker/api.Dockerfile"
RUN --mount=type=cache,id=pnpm,target=/root/.local/share/pnpm/store \
    pnpm turbo run build --filter=@repo/api... && \
    pnpm prune --prod --ignore-scripts

# Stage 3: Production non-root runner
FROM node:22-alpine AS runner
WORKDIR /app
ENV NODE_ENV=production
ENV PORT=4000
```

### Frontend (`web`): `turbo prune @repo/web --docker` + Next.js `output: 'standalone'`

`docker/web.Dockerfile` does **not** run `pnpm prune`. Instead, `builder` passes `ENV DOCKER_STANDALONE=true` and `ENV API_INTERNAL_URL=http://api:4000` into `pnpm turbo run build --filter=@repo/web...`. Next.js emits a self-contained `.next/standalone` bundle, and `runner` copies only the standalone server, static chunks, `public/`, and `apps/web/content/` (for runtime MDX reading):

```dockerfile title="docker/web.Dockerfile"
COPY --from=pruner /app/out/full/ .
COPY tsconfig.base.json ./tsconfig.base.json
ENV DOCKER_STANDALONE=true
ENV API_INTERNAL_URL=http://api:4000
RUN pnpm turbo run build --filter=@repo/web...

# Stage 3: Production non-root runner
FROM node:22-alpine AS runner
...
COPY --from=builder --chown=nextjs:nodejs /app/apps/web/.next/standalone ./
COPY --from=builder --chown=nextjs:nodejs /app/apps/web/.next/static ./apps/web/.next/static
COPY --from=builder --chown=nextjs:nodejs /app/apps/web/public ./apps/web/public
COPY --from=builder --chown=nextjs:nodejs /app/apps/web/content ./apps/web/content

USER nextjs
EXPOSE 3000
CMD ["node", "apps/web/server.js"]
```

### Production Image Profiles

| Container | Base Image | Runtime Slimming | Port Scope | Runtime User |
| :--- | :---: | :--- | :---: | :---: |
| `workfolio-telemetry-ms` | `node:22-alpine` | `turbo prune` + `pnpm prune --prod --ignore-scripts` | `4001` (internal only) | `node` (non-root) |
| `workfolio-api` | `node:22-alpine` | `turbo prune` + `pnpm prune --prod --ignore-scripts` | `4000` | `node` (non-root) |
| `workfolio-web` | `node:22-alpine` | `turbo prune` + Next.js `output: 'standalone'` | `3000` | `nextjs` (`UID 1001`) |

> [!TIP]
> Because the production `api` image excludes `Prisma CLI`, database schema migrations (`prisma migrate deploy`) run as a dedicated CI/CD step before rolling out new containers.

## 4. `docker-compose.yml` (Zero-Friction Demo) vs `docker-compose.prod.yml` (Hardened Production)

Orchestration is deliberately split so a reviewing Team Lead or CTO can launch the entire stack in one command (`docker compose up --build -d`) with zero `.env` setup, while cloud/VPS deployments enforce strict container hardening and fail-fast secrets:

| Parameter | `docker-compose.yml` (Local Reviewer Demo) | `docker-compose.prod.yml` (Hardened Production) |
| :--- | :--- | :--- |
| **Launch Command** | `docker compose up --build -d` | `docker compose -f docker-compose.prod.yml --env-file .env.prod up --build -d` |
| **`WORKFOLIO_DEMO_MODE`** | `${WORKFOLIO_DEMO_MODE:-true}` on **both `api` and `web`** (shared fallback to `DEFAULT_DEV_JWT_SECRET` + warning) | Omitted (`"false"` — fail-fast validation in `loadAppConfig`) |
| **Host Port Bindings** | Loopback-only & overridable: `127.0.0.1:${POSTGRES_HOST_PORT:-5432}:5432`, `127.0.0.1:${API_HOST_PORT:-4000}:4000`, `127.0.0.1:${WEB_HOST_PORT:-3000}:3000` | `postgres` & `telemetry-ms` **unpublished** (`backend-network` only); `api` (`127.0.0.1:4000:4000`) & `web` (`127.0.0.1:3000:3000`) loopback-only behind reverse proxy |
| **Secret & Origin Enforcement** | `${JWT_SECRET:-}` (auto-resolved via `resolveJwtSecret()` without `.env`) | Hard fail-fast `${POSTGRES_PASSWORD:?}`, `${JWT_SECRET:?}` (on `api` & `web`), `${ADMIN_SECRET_PASSCODE:?}`, `${WEB_ORIGIN:?}`, `${NEXT_PUBLIC_SITE_URL:?}` |
| **Reverse Proxy Trust** | Direct localhost (`TRUST_PROXY_HOPS` unset) | `TRUST_PROXY_HOPS: ${TRUST_PROXY_HOPS:-1}` on `api` for accurate client IP rate limiting behind Nginx/Caddy/ALB |
| **`Secure` Flag on `kb_access_token`** | `false` (`isProduction && !isDemoMode` — works on `http://localhost:3000`) | `true` (enforced strictly over HTTPS / TLS) |

### Production Container Hardening & Healthcheck Matrix (`docker-compose.prod.yml`)

Every production service applies least-privilege Linux kernel constraints and explicit readiness probes (`depends_on` uses `condition: service_healthy` across `postgres -> api`, `telemetry-ms -> api`, and `api -> web`):

```yaml title="docker-compose.prod.yml (excerpt)"
  web:
    restart: always
    read_only: true
    tmpfs:
      - /tmp
      - /app/apps/web/.next/cache
    security_opt:
      - no-new-privileges:true
    cap_drop:
      - ALL
    pids_limit: 256
    healthcheck:
      test: ["CMD", "node", "-e", "fetch('http://127.0.0.1:3000/robots.txt').then((r)=>process.exit(r.ok?0:1)).catch(()=>process.exit(1))"]
```

| Service | Kernel Hardening Directives | Read-Only Root FS + `tmpfs` | Healthcheck Probe |
| :--- | :--- | :--- | :--- |
| **`postgres`** | `no-new-privileges:true`, `pids_limit: 256` | Data persisted in `postgres_prod_data` volume | `pg_isready -U ${POSTGRES_USER:-postgres} -d ${POSTGRES_DB:-workfolio_db}` |
| **`telemetry-ms`** | `no-new-privileges:true`, `cap_drop: [ALL]`, `pids_limit: 256` | `read_only: true`, `tmpfs: [/tmp]` | Node `node:net` TCP socket connect to `127.0.0.1:4001` |
| **`api`** | `no-new-privileges:true`, `cap_drop: [ALL]`, `pids_limit: 256` | `read_only: true`, `tmpfs: [/tmp]` | `wget -qO- http://127.0.0.1:4000/api/health \|\| exit 1` |
| **`web`** | `no-new-privileges:true`, `cap_drop: [ALL]`, `pids_limit: 256` | `read_only: true`, `tmpfs: [/tmp, /app/apps/web/.next/cache]` | Node `fetch('http://127.0.0.1:3000/robots.txt')` |
