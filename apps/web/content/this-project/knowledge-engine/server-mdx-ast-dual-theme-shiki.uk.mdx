## 1. Архітектура маршруту `/[locale]/knowledge-base/[...slug]`

Конспекти зберігаються у файловій системі за шаблоном `apps/web/content/<topic>/<subtopic>/<slug>.<locale>.mdx`. Щоб масштабувати базу знань на будь-яку глибину вкладеності без дублювання `page.tsx`, використовується єдиний catch-all маршрут `app/[locale]/knowledge-base/[...slug]/page.tsx`:

| Глибина `slug` | Приклад URL | Що рендерить `page.tsx` |
| :--- | :--- | :--- |
| **1 сегмент (`[topic]`)** | `/uk/knowledge-base/this-project` | **Хаб теми:** вкладки підтем (`TopicSubtopicTabs`), картки підрозділів та список усіх статей розділу |
| **2 сегменти (`[topic, subtopic]`)** | `/uk/knowledge-base/this-project/knowledge-engine` | **Хаб підтеми:** активна вкладка підтеми та відфільтровані картки конспектів цієї папки |
| **3 сегменти (`[...path, article]`)** | `/uk/knowledge-base/this-project/knowledge-engine/server-mdx-ast-dual-theme-shiki` | **Сторінка статті:** `TL;DR`, рендер `MdxArticleRenderer`, правий `TOC` і навігація `Prev / Next` |

На етапі збірки `generateStaticParams()` перемножує `SUPPORTED_LOCALES` (`en`, `uk`, `ru`) на всі шляхи папок і статей (`getAllStaticKnowledgeSlugArrays()`), передгенеруючи 100% маршрутів у `SSG`:

```typescript title="apps/web/src/app/[locale]/knowledge-base/[...slug]/page.tsx"
export function generateStaticParams() {
  const slugArrays = getAllStaticKnowledgeSlugArrays()
  return SUPPORTED_LOCALES.flatMap((locale) =>
    slugArrays.map((slug) => ({
      locale,
      slug,
    })),
  )
}
```

При запиті сторінки сервер спершу перевіряє, чи є шлях кінцевою статтею (`getArticleByPathSegments`, який запускає парсинг HAST точково лише для однієї запитаної статті), а якщо ні — шукає вузол директорії (`getFolderByPathSegments`) у полегшеному фронтматер-дереві `getKnowledgeTree(locale)`. Для типобезпечних переходів між локалями використовується `Link` із `@/shared/i18n/navigation`.

## 2. Серверний Zero-Eval HAST-конвеєр (`remark-directive` ➔ `remark-rehype` ➔ `toJsxRuntime`)

Парсинг `.mdx`-файлів виконується виключно на сервері в модулях `apps/web/src/entities/knowledge-content/lib/mdx-ast-parser.ts` та `mdx-fs-loader.ts`:

1. **`parseFrontmatterOnly` (`gray-matter`)** витягує YAML-фронтматер (`title`, `sidebarLabel`, `summary`, `category`, `format`, `tags`, `readingTime`, `order`, `tldr`) із міжзапитним кешуванням за `mtimeMs`, тому для побудови дерева сайдбару та хабів розділів парсинг тіла статей узагалі не запускається.
2. **`unified().use(remarkParse).use(remarkGfm).use(remarkDirective)`** будує синтаксичне дерево `mdast`, розмічає заголовки `h2–h4`, GitHub Alerts і блоки коду, а також перетворює теги `<Widget />` і директиви `::sandbox{name="..."}` / `:::sandbox{name="..."}` на типізовані вузли `div[data-mdx-widget]`, вирізаючи будь-який довільний сирий HTML (`Zero-Eval CSP`).
3. **`unified().use(remarkRehype)`** переводить `mdast` у стандартне дерево `HastRoot`, яке в серверному компоненті напряму конвертується в React-елементи через `toJsxRuntime` із `hast-util-to-jsx-runtime`:

```typescript title="apps/web/src/entities/knowledge-content/lib/mdx-ast-parser.ts"
const markdownParser = unified().use(remarkParse).use(remarkGfm).use(remarkDirective)
const mdastToHastProcessor = unified().use(remarkRehype)

export function parseRawMdx(
  raw: string,
  fallbackCategory: KnowledgeCategory,
  leafSlug: string,
  relativeSubSegments: readonly string[],
  locale: SupportedLocale,
  isFallback: boolean,
): MdxArticleDocument {
  const { frontmatter, content } = parseFrontmatterOnly(
    raw,
    fallbackCategory,
    leafSlug,
    relativeSubSegments,
    locale,
    isFallback,
  )

  const mdastRoot = markdownParser.parse(content) as MdastRoot
  const toc: ArticleTocEntry[] = []
  const codeBlocks: MdxCodeBlockMeta[] = []
  const usedHeadingIds = new Map<string, number>()

  transformMdastChildren(mdastRoot.children, usedHeadingIds, toc, codeBlocks, false)
  const hast = mdastToHastProcessor.runSync(mdastRoot) as HastRoot

  return { ...frontmatter, toc, hast, codeBlocks }
}
```

Завдяки стандартному конвеєру `mdast` ➔ `HAST` рушій нативно підтримує:
- Вкладені блоки коду та чеклісти всередині GitHub-style плашок `> [!TIP]`, `> [!IMPORTANT]`, `> [!WARNING]`.
- Вкладене інлайн-форматування (`**жирний текст із `кодом` усередині посилання**`) та фігури зображень `![Підпис](/path.webp)`.
- Декларативне вбудовування інтерактивних клієнтських островів (`::sandbox{name="NestAiMcpDiagram" defaultMode="ai"}` або `<ReactRenderGraphD3 />`) через реєстр `MDX_WIDGET_REGISTRY` в `apps/web/src/features/kb-sandboxes/ui/mdx-client-widgets.tsx`.

## 3. Dual-Theme підсвічування коду `Shiki v4` (`0 КБ` клієнтського JS)

Серверний компонент `MdxArticleRenderer` (`apps/web/src/entities/knowledge-article/ui/mdx-article-renderer.tsx`) підсвічує всі блоки коду статті паралельно через `Promise.all` та `highlightCodeServer` (`apps/web/src/entities/knowledge-content/lib/shiki-highlighter.ts`) перед викликом `toJsxRuntime(hast, { Fragment, jsx, jsxs, components })`:

```typescript title="apps/web/src/entities/knowledge-content/lib/shiki-highlighter.ts"
const html = await highlighter.codeToHtml(trimmed, {
  lang: safeLang,
  themes: {
    light: 'github-light-default',
    dark: 'github-dark-default',
  },
  defaultColor: false,
})
```

Опція `defaultColor: false` змушує `Shiki` записувати в кожен `<span>` лише дві CSS-змінні (`--shiki-light` і `--shiki-dark`). У `globals.css` перемикання теми відбувається миттєво силами браузерного CSS-каскаду без перемальовування DOM і з `0 КБ` JavaScript на клієнті:

```css title="packages/ui/src/styles/globals.css"
.shiki span {
  color: var(--shiki-light);
}

.dark .shiki span {
  color: var(--shiki-dark);
}
```
