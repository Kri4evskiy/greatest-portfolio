## 1. Миграция с pnpm 10 на pnpm 12

В **pnpm 12** устаревшее поле `onlyBuiltDependencies` в `package.json` полностью удалено. Все разрешения на выполнение `postinstall`-скриптов перенесены в строгий словарь `allowBuilds` внутри `pnpm-workspace.yaml`, иначе срабатывает защита `ERR_PNPM_IGNORED_BUILDS`.

### Конфигурация allowBuilds в воркспейсе

```yaml title="pnpm-workspace.yaml"
packages:
  - "apps/*"
  - "packages/*"

allowBuilds:
  "@biomejs/biome": true
  "@parcel/watcher": true
  "@prisma/client": true
  "@prisma/engines": true
  "@swc/core": true
  esbuild: true
  lefthook: true
  prisma: true
  sharp: true
```

> [!IMPORTANT]
> Никогда не добавляйте секцию `"pnpm"` в `package.json` на **pnpm 12+**. И локальное окружение, и облачный билдер Vercel Corepack читают `allowBuilds` строго из `pnpm-workspace.yaml`.

## 2. Единый BuildKit Cache Mount для всех 3 сервисов

Раньше контейнеры `web`, `api` и `telemetry-ms` скачивали одни и те же **100+ МБ** нативных пакетов с нуля при каждом изменении `pnpm-lock.yaml`.

### Прогрев Corepack и монтирование стора

Монтирование `/root/.local/share/pnpm/store` как персистентного кэша BuildKit шарит пакеты между всеми тремя Dockerfile:

```dockerfile title="docker/api.Dockerfile"
RUN corepack enable && corepack prepare pnpm@12.16.1 --activate && pnpm --version
RUN --mount=type=cache,id=pnpm,target=/root/.local/share/pnpm/store \
    pnpm install --frozen-lockfile --ignore-scripts
```

## 3. Замеры продакшен-образов и сохранение Prisma Client

Вызов `pnpm prune --prod --ignore-scripts` сразу после `turbo run build` вычищает **Biome**, **Turbo**, **TypeScript** и **Prisma CLI** из финальных продакшен-образов, сохраняя сгенерированный рантайм-клиент `.prisma/client`.

### Сравнительная таблица До и После

| Контейнер | До оптимизации | После (`pnpm prune --prod`) | Экспорт слоёв |
| :--- | :---: | :---: | :---: |
| `workfolio-telemetry-ms` | ~215 MB | **64.3 MB** | 1.8 с |
| `workfolio-api` | ~260 MB | **78.2 MB** | 2.4 с |
| `workfolio-web` (standalone) | ~140 MB | **85.6 MB** | 2.1 с |

> [!TIP]
> Так как продакшен-контейнер `api` очищен от `devDependencies`, миграции схемы БД (`prisma migrate deploy`) запускаются из CI/CD или локального терминала напрямую в **Neon.tech**.

### Чеклист продакшен-готовности

- [x] Непривилегированный пользователь (`nestjs` / `nextjs`, UID `1001`) во всех runner-образах
- [x] Отключена фоновая телеметрия при сборке (`DO_NOT_TRACK=1`, `TURBO_TELEMETRY_DISABLED=1`)
- [x] Нулевое влияние на облачный хостинг **Vercel** (`apps/web`) и **Neon.tech** (`DATABASE_URL`)
