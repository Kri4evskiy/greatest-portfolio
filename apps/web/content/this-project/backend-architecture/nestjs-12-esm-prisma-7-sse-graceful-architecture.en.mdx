## 1. The 4-Tier Enterprise Structure (`common`, `config`, `migrations`, `modules`)

To keep `apps/api` (running on Native ESM `"type": "module"` under Node.js 22+) strictly modular as new backend capabilities are added, the codebase is partitioned into 4 distinct boundaries:

| Tier in `apps/api/src/` | Architectural Responsibility | Core Modules |
| :--- | :--- | :--- |
| **`common/`** | Cross-cutting framework mechanics independent of business domains (no horizontal imports between sibling folders; shared helpers live in `common/utils/*`) | `middleware/{logging,csrf-origin}.middleware.ts`, `utils/{request-id,log-sanitizer,express-request}.util.ts`, `interceptors/{logging,timeout}.interceptor.ts`, `filters/sentry-exception.filter.ts`, `pipes/zod-validation.pipe.ts`, `decorators/` (`@Public`, `@SkipTimeout`) |
| **`config/`** | Fail-fast `process.env` Zod validation at startup (direct `process.env` reads inside services are prohibited) | `app.config.ts` (`loadAppConfig`, `TRUST_PROXY_HOPS`, `WORKFOLIO_DEMO_MODE`), `database.config.ts` |
| **`migrations/` & `prisma/`** | Data access layer (`Prisma 7` + `@prisma/adapter-pg`), bounded In-Memory fallback, and CLI seeding | `prisma.service.ts`, `migrations/scripts/seed.ts`, `seed-data.ts` |
| **`modules/`** | Self-contained domain modules with controllers, services, guards, and DTOs | `auth/` (`JwtRolesGuard`, `AuthService`, `@Roles`), `knowledge/` (article metrics & Offset pagination), `telemetry/` (TCP client `:4001`, `@Sse('stream')`, Cursor pagination, and `@Roles('ADMIN')` diagnostics) |

## 2. Request Lifecycle, `TRUST_PROXY_HOPS`, `100kb` JSON Limit & CRLF-Safe `X-Request-Id`

Every incoming HTTP request passes through 6 deterministic stages:

```text
Incoming HTTP Request
  │
  ▼ 1. Express Hardening (main.ts): JSON-only body parser (100kb) ➔ trust proxy (TRUST_PROXY_HOPS)
       ➔ strict helmet() (CSP default-src 'none') ➔ cookieParser() ➔ CORS (exposedHeaders: X-Request-Id)
  ▼ 2. Middleware ('{*path}'): LoggingMiddleware (X-Request-Id) ➔ CsrfOriginMiddleware (JSON + Origin + Sec-Fetch-Site)
  ▼ 3. Guards: ThrottlerGuard (60/min global; shared 5/min auth bucket; 5/min SSE connect) ➔ JwtRolesGuard
  ▼ 4. Interceptors: LoggingInterceptor ➔ TimeoutInterceptor (15s; bypasses @Sse() and @SkipTimeout())
  ▼ 5. Pipes: ZodValidationPipe(Schema) — validates Body / Query / Param against @repo/shared-schemas
  ▼ 6. Controller ➔ Service ➔ Prisma 7 / TCP :4001 (or SentryExceptionFilter with headersSent guard & requestId)
```

### Proxy Hop Topology, Body DoS Prevention & Log Injection Defense
1. **Validated `TRUST_PROXY_HOPS` (`apps/api/src/config/app.config.ts` & `main.ts`):**
   `AppEnvSchema` validates `TRUST_PROXY_HOPS` as an integer in `0..5` (default `1`). In production, when `appConfig.trustProxyHops > 0`, `main.ts` calls `app.set('trust proxy', appConfig.trustProxyHops)` so Express and `ThrottlerGuard` extract the real client IP from `X-Forwarded-For` without IP spoofing or proxy bucket collisions across topologies (Render/Koyeb = `1`, Nginx + Next.js rewrite = `2`).
2. **Strict JSON-Only `100kb` Body Limit (`apps/api/src/main.ts`):**
   `NestFactory.create(..., { bodyParser: false })` followed by `app.useBodyParser('json', { limit: '100kb' })` removes Express's default `urlencoded` parser completely (closing classic HTML `<form>` CSRF vectors) and caps JSON payload parsing to protect V8 memory and event-loop latency.
3. **Validating `X-Request-Id` in `apps/api/src/common/utils/request-id.util.ts`:**
   Blindly logging client-supplied `X-Request-Id` headers opens a **CRLF / Log Injection** vector. `resolveCorrelationRequestId()` accepts incoming IDs only when they match `/^[A-Za-z0-9_-]{8,64}$/`, falling back to a fresh `randomUUID()`:

```typescript title="apps/api/src/common/utils/request-id.util.ts"
export const REQUEST_ID_HEADER = 'X-Request-Id'
const SAFE_REQUEST_ID_REGEX = /^[A-Za-z0-9_-]{8,64}$/

export type RequestWithCorrelationId = Request & { requestId?: string }

export function resolveCorrelationRequestId(incomingHeaderValue?: string): string {
  const trimmed = incomingHeaderValue?.trim()
  return trimmed && SAFE_REQUEST_ID_REGEX.test(trimmed) ? trimmed : randomUUID()
}
```

This `requestId` is exposed to browser clients via CORS `exposedHeaders: ['X-Request-Id']`, logged with request latency, and returned in `SentryExceptionFilter` JSON payloads (while `sanitizeLogValue()` strips ANSI escapes and control characters from URLs and headers before logging).

## 3. Shared `Zod v4` Contracts, Capabilities Matrix, Dual Pagination & Admin Diagnostics

Instead of duplicating validation across backend `class-validator` classes and frontend `Zod` schemas, the monorepo enforces a **Single Source of Truth** in `@repo/shared-schemas` validated via `ZodValidationPipe`:

- **`GET /api/capabilities` (`SystemCapabilitiesSchema`):**
  Exposes sanitized runtime flags for the Capability-Gated UI on `/[locale]/system-status` without leaking secrets or internal ports:

```json title="GET /api/capabilities — SystemCapabilities shape"
{
  "status": "ok",
  "mode": "demo",
  "persistence": "postgresql",
  "rateLimiter": "in-memory",
  "telemetryTcpConnected": true,
  "integrations": {
    "redisCache": false,
    "s3ObjectStorage": false,
    "telegramBotAuth": false,
    "sentryObservability": false
  },
  "timestamp": "2026-11-24T12:00:00.000Z"
}
```

- **`GET /api/knowledge/metrics/paginated` (Offset Pagination):**
  Public read-only leaderboard (`@Public()`, global `ThrottlerGuard` `60 req/min`) validated with `OffsetPaginationQuerySchema` (`limit: 1..100`, `offset: 0..500`, optional `category`, `sortBy: 'viewsCount' | 'helpfulCount'`). Returns `{ items, total, limit, offset, hasMore, nextOffset }`, where `nextOffset` is `offset + items.length` when `hasMore` is `true` and `null` on the final page.
- **`GET /api/telemetry/events` (Cursor Pagination):**
  Validated with `CursorPaginationQuerySchema` (`limit: 1..50`, optional UUID `cursor`, optional `eventType`) using `take: limit + 1` and `orderBy: [{ createdAt: 'desc' }, { id: 'desc' }]`, returning `{ items, limit, hasMore, nextCursor }` with zero page drift under live telemetry writes.
- **`GET /api/telemetry/admin-diagnostics` (`@Roles('ADMIN')` Operational Stub):**
  Protected by `@UseGuards(JwtRolesGuard)` and `@Roles('ADMIN')`, validating its output against `TelemetryAdminDiagnosticsSchema` (`activeSseStreams`, `maxSseStreamsGlobal`, `maxSseStreamsPerIp`, `trackedSessionsInMemory`, `trackedMetricsInMemory`, `totalEventsProcessed`, `databaseConnected`, `uptimeSeconds`, `timestamp`). It serves as the verified RBAC anchor for future operational endpoints such as Redis cache flush or moderation controls.

## 4. Rust-Free `Prisma 7` (`@prisma/adapter-pg`), Bounded Fallback & Event UUID Deduplication

In `Prisma 7.10.1`, we replaced the legacy Rust binary query engine with the Wasm query compiler and `@prisma/adapter-pg` over `pg.Pool`:

1. **Startup `SELECT 1` Probe & Bounded In-Memory Fallback (`PrismaService`):**
   When `DATABASE_URL` is unset or PostgreSQL is unreachable, `PrismaService` cleanly closes `pg.Pool` and operates on a deterministic, memory-bounded fallback store seeded with `INITIAL_ARTICLE_SEEDS`:
   - `MAX_MEMORY_SESSIONS = 200` — prunes expired sessions first, then evicts the oldest map entry so high-churn guest passes cannot leak heap memory.
   - `MAX_MEMORY_METRICS = 200` — evicts non-seeded entries first while preserving `SEEDED_METRIC_SLUGS`.
   - `MAX_MEMORY_SYSTEM_EVENTS = 200` — maintains a bounded FIFO window for cursor pagination.
2. **Explicit `id: eventId` Persistence for SSE/REST Deduplication:**
   In `PrismaService.logSystemEvent()`, `systemEventLog.create` persists the exact UUID broadcast over SSE (`data: { id: eventId, eventType, payload: jsonPayload }`). Because both the live SSE push and `GET /api/telemetry/events` carry the identical `id`, client-side `seenIds` deduplication eliminates duplicate timeline rows seamlessly.
3. **Docker Build Optimization (`docker/api.Dockerfile`):**
   The generated ESM client compiles via `tsc` directly into `apps/api/dist/generated/prisma/`, letting `pnpm prune --prod --ignore-scripts` strip dev dependencies cleanly without runtime `openssl` packages.

## 5. Bounded SSE Streams, Async TCP Emit, Graceful Shutdown & Loopback `telemetry-ms`

Long-lived **Server-Sent Events (`@Sse('stream')`)** introduce three classic production failure modes: reconnect storms/FD exhaustion, unhandled async TCP errors when a sidecar microservice is offline, and 10-second `SIGTERM` hangs during deploys.

### 1. Reconnect Throttle, Concurrency Caps & Max Stream TTL
In `TelemetryController`, `streamEvents()` pairs `@Throttle({ default: { limit: 5, ttl: 60000 } })` (blocking reconnect storms at `5 req/min/IP`) with `@SkipTimeout()` (so `TimeoutInterceptor`'s 15s HTTP deadline never kills open streams). Inside `TelemetryService`, every stream acquires a tracked slot with strict Free-Tier bounds and releases it deterministically in `finalize()`:

```typescript title="apps/api/src/modules/telemetry/telemetry.service.ts"
export const MAX_SSE_STREAMS_GLOBAL = 50
export const MAX_SSE_STREAMS_PER_IP = 2
export const MAX_SSE_STREAM_LIFETIME_MS = 15 * 60 * 1000 // 15 minutes

getEventStream(clientIp = 'unknown'): Observable<MessageEvent> {
  this.acquireSseSlot(clientIp) // 503 if >= 50 global; 429 if >= 2 per IP

  // ... welcomeEvent + interval(15000) heartbeat$
  return merge(of(welcomeEvent), this.events$.asObservable(), heartbeat$).pipe(
    takeUntil(this.shutdown$),
    takeUntil(timer(MAX_SSE_STREAM_LIFETIME_MS)),
    finalize(() => {
      this.releaseSseSlot(clientIp)
    }),
    map((event) => ({ id: event.id, type: 'message', data: event })),
  )
}
```

### 2. Monotonic Counter & Safe Async Microservice `emit()`
In `TelemetryService.publishEvent()`, a dedicated monotonic `localEventsCounter` increments on every event (even though `recentEvents` is capped at 25 items) so `getMicroserviceStats()` reports accurate cumulative counts in local fallback mode. Because NestJS `ClientProxy.emit()` returns a hot Observable whose TCP `ECONNREFUSED` failures occur asynchronously, it is explicitly piped and subscribed with an error handler:

```typescript title="apps/api/src/modules/telemetry/telemetry.service.ts"
this.localEventsCounter += 1
this.events$.next(rawEvent)
await this.prisma.logSystemEvent(rawEvent.type, rawEvent)

this.telemetryClient
  .emit('telemetry.event', rawEvent)
  .pipe(takeUntil(this.shutdown$))
  .subscribe({
    error: (err: unknown) => {
      this.logger.debug(`Telemetry MS emit skipped (local mode): ${String(err)}`)
    },
  })
```

### 3. Graceful Shutdown (`< 200ms`) & Loopback `apps/telemetry-ms` (`127.0.0.1:4001`)
- When `SIGTERM` triggers `app.enableShutdownHooks()`, `TelemetryService.onModuleDestroy()` fires `this.shutdown$.next()`, completes `shutdown$` and `events$`, clears SSE slot maps, and closes `telemetryClient`. Every active SSE observable completes immediately, `PrismaService` drains `pg.Pool`, and the container exits in **`< 200ms`** instead of waiting for `SIGKILL`.
- On the microservice side, `apps/telemetry-ms/src/config/telemetry-ms.config.ts` validates `TELEMETRY_MS_HOST` and `TELEMETRY_MS_PORT` via Zod (`loadTelemetryMsConfig`), defaulting strictly to loopback **`127.0.0.1:4001`** so local runs never expose unauthenticated TCP on a developer's LAN. Only inside Docker Compose's isolated `backend-network` is `TELEMETRY_MS_HOST=0.0.0.0` explicitly injected.
