## Проблема ручной мемоизации в React 18

В `React 18` любое обновление состояния в родительском компоненте по умолчанию вызывает каскадный ререндер всего поддерева, если разработчик вручную не расставил барьеры `React.memo`, `useMemo` и `useCallback`. Малейший инлайн-объект или коллбэк в пропсах ломает мемоизацию дочерних узлов.

## Как меняет правила игры React 19 и React Compiler

1. **Автоматическая мемоизация на этапе сборки:** Компилятор анализирует граф потока данных (CFG) и автоматически мемоизирует как вычисляемые значения, так и JSX-узлы, пропускающие ререндер при неизменных зависимостях.
2. **Первоклассный примитив `use(Promise | Context)`:** В отличие от классических хуков, `use()` можно вызывать внутри условных веток (`if`), интегрируя потоковый `Suspense` и `ErrorBoundary` без каскадов `useEffect + useState`.
3. **Устранение сетевых водопадов (Vercel `async-parallel`):** В сочетании с `React Server Components` и `React.cache()` серверные деревья запрашивают данные параллельно за один проход.
