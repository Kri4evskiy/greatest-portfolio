## 1. Единые 1-дневные контракты и Fail-Closed резолвинг секрета в продакшене

Чтобы фронтенд (`apps/web`) и бэкенд (`apps/api`) никогда не рассинхронизировались в названии `HttpOnly`-куки, времени её жизни или базовых правилах секрета, общие auth-примитивы вынесены в `@repo/shared-schemas`:

```typescript title="packages/shared-schemas/src/auth.schema.ts"
export const KB_ACCESS_COOKIE_NAME = 'kb_access_token'
export const KB_COOKIE_MAX_AGE_MS = 1000 * 60 * 60 * 24 // 1 day
export const DEFAULT_DEV_JWT_SECRET = 'workfolio-super-secret-jwt-key-2026'

export function resolveJwtSecret(envSecret?: string): string {
  const trimmed = envSecret?.trim()
  return trimmed && trimmed.length > 0 ? trimmed : DEFAULT_DEV_JWT_SECRET
}
```

Однако на Edge-периметре автоматический откат на публичный dev-секрет в продакшене стал бы критической уязвимостью. Поэтому в `apps/web/src/shared/config/env.ts` поверх базового контракта работает строгий `resolveEdgeJwtSecretStrict()`:

```typescript title="apps/web/src/shared/config/env.ts"
const MIN_PROD_JWT_SECRET_LENGTH = 32

export function resolveEdgeJwtSecretStrict(env: NodeJS.ProcessEnv = process.env): string | null {
  const parsed = WebEnvSchema.safeParse(env)
  const nodeEnv = parsed.success ? parsed.data.NODE_ENV : process.env.NODE_ENV
  const isProduction = nodeEnv === 'production'
  const isDemoMode = (parsed.success ? parsed.data.WORKFOLIO_DEMO_MODE : env.WORKFOLIO_DEMO_MODE) === 'true'
  const rawSecret = (parsed.success ? parsed.data.JWT_SECRET : env.JWT_SECRET)?.trim() ?? ''

  if (isProduction && !isDemoMode) {
    if (rawSecret.length < MIN_PROD_JWT_SECRET_LENGTH || rawSecret === DEFAULT_DEV_JWT_SECRET) {
      return null
    }
    return rawSecret
  }

  return resolveJwtSecret(rawSecret || undefined)
}
```

- **Продакшен (`NODE_ENV=production` без `WORKFOLIO_DEMO_MODE=true`):** строгая **fail-closed** политика — если `JWT_SECRET` не задан, короче `32` символов или совпадает с `DEFAULT_DEV_JWT_SECRET`, функция возвращает `null`, и Edge Proxy гарантированно отклоняет любой токен (`false`).
- **Локальная разработка / тесты / Docker-демо (`WORKFOLIO_DEMO_MODE=true`):** сохраняется бесшовный старт без ручной настройки `.env` через делегирование в `resolveJwtSecret()`.

## 2. Верификация `HS256` через нативный Web Crypto API (`crypto.subtle`)

Так как страницы Базы Знаний предгенерируются в статику (`SSG`), проверка доступа выполняется на границе сети в Edge Runtime до отдачи HTML. Вместо сторонних JWT-библиотек `apps/web/src/shared/lib/edge-jwt.ts` использует встроенный **Web Crypto API** с кэшированием `CryptoKey` на уровне изолята и сбросом отклонённого промиса:

```typescript title="apps/web/src/shared/lib/edge-jwt.ts"
let cachedSecretValue: string | null = null
let cachedHmacKeyPromise: Promise<CryptoKey> | null = null

const ALLOWED_JWT_ROLES = new Set(['USER', 'ADMIN'])

function getHmacKey(secret: string): Promise<CryptoKey> {
  if (cachedSecretValue === secret && cachedHmacKeyPromise) {
    return cachedHmacKeyPromise
  }

  cachedSecretValue = secret
  cachedHmacKeyPromise = crypto.subtle
    .importKey('raw', new TextEncoder().encode(secret), { name: 'HMAC', hash: 'SHA-256' }, false, ['verify'])
    .catch((error: unknown) => {
      // Сбрасываем отклонённый промис, чтобы временный сбой Web Crypto не отравил изолят навсегда
      cachedSecretValue = null
      cachedHmacKeyPromise = null
      throw error
    })
  return cachedHmacKeyPromise
}
```

### Точный порядок проверок в `verifyEdgeJwtHs256(token)`

Функция `verifyEdgeJwtHs256(token: string | undefined): Promise<boolean>` за `< 0.2 мс` выполняет многоступенчатую валидацию, отсекая невалидные токены до криптографических вычислений:

1. **Структура и строгий Base64URL:** разбивает токен ровно на 3 непустых сегмента (`header.payload.signature`) и декодирует их через `decodeBase64UrlToBytes()` (отбрасывая посторонние символы и некорректную длину `length % 4 === 1`) в `Uint8Array<ArrayBuffer>`.
2. **Фиксация алгоритма в заголовке:** парсит JSON заголовка и полезной нагрузки как plain-объекты (`isPlainObject`) и требует строго `headerJson.alg === 'HS256'` (защита от `alg: "none"` и подмены алгоритма).
3. **Валидация временных и ролевых claims:**
   - Проверяет `typeof payloadJson.exp === 'number'` и `payloadJson.exp * 1000 > nowMs` (в соответствии с `1d` JWT TTL).
   - Если указан `payloadJson.nbf`, требует `typeof payloadJson.nbf === 'number'` и `payloadJson.nbf * 1000 <= nowMs`.
   - Проверяет наличие непустой строки `payloadJson.sub` (`sub.trim().length > 0`).
   - Проверяет, что `payloadJson.role` входит в белый список `ALLOWED_JWT_ROLES` (`'USER' | 'ADMIN'`).
4. **Fail-Closed секрет и константная проверка подписи:** вызывает `resolveEdgeJwtSecretStrict()` (в продакшене при `null` логирует ошибку и возвращает `false`), получает кэшированный ключ через `getHmacKey(secret)` и выполняет `crypto.subtle.verify('HMAC', hmacKey, signatureBytes, signingInput)`.

## 3. Гибридная граница Базы Знаний и явный matcher статики в `apps/web/src/proxy.ts`

Политика доступа централизована в `apps/web/src/shared/i18n/app-routes.ts`, поэтому Edge Proxy, генератор `sitemap.xml`, `robots.ts` и клиентские кнопки опираются на единую логику:

```typescript title="apps/web/src/shared/i18n/app-routes.ts"
export const PUBLIC_KB_ROOT_SEGMENTS = ['this-project'] as const

export function isPublicKnowledgeBasePath(pathname: string): boolean {
  const normalized = stripLocalePrefix(pathname).replace(/\/+$/, '') || '/'
  if (normalized === APP_ROUTES.knowledgeBase) {
    return true
  }
  return PUBLIC_KB_ROOT_SEGMENTS.some(
    (segment) =>
      normalized === `${APP_ROUTES.knowledgeBase}/${segment}` ||
      normalized.startsWith(`${APP_ROUTES.knowledgeBase}/${segment}/`),
  )
}

export function isProtectedKnowledgeBasePath(pathname: string): boolean {
  const normalized = stripLocalePrefix(pathname).replace(/\/+$/, '') || '/'
  if (!isRouteActive(normalized, APP_ROUTES.knowledgeBase, true)) {
    return false
  }
  return !isPublicKnowledgeBasePath(normalized)
}
```

- **Публичные и индексируемые SEO-маршруты:** хаб `/knowledge-base` и ветка `/knowledge-base/this-project/**` (прозрачная архитектурная спецификация, открытая для краулеров, рекрутеров и тимлидов без `307`-редиректов).
- **Защищённые Edge JWT маршруты:** все остальные доменные конспекты (например, `/knowledge-base/react/**`, `/knowledge-base/backend/**`, `/knowledge-base/others/**`) во всех локалях (`''`, `/ua`, `/ru`).

Благодаря инкапсуляции криптографии и правил доступа `apps/web/src/proxy.ts` остаётся компактным и прозрачным:

```typescript title="apps/web/src/proxy.ts"
const LOCALE_PREFIX_MATCH_REGEX = /^\/(en|ua|ru)(?=\/|$)/

export async function proxy(request: NextRequest): Promise<NextResponse> {
  const { pathname } = request.nextUrl

  if (isProtectedKnowledgeBasePath(pathname)) {
    const token = request.cookies.get(KB_ACCESS_COOKIE_NAME)?.value
    const isValid = await verifyEdgeJwtHs256(token)

    if (!isValid) {
      const matchedLocale = pathname.match(LOCALE_PREFIX_MATCH_REGEX)?.[1]
      const homePath = matchedLocale && matchedLocale !== routing.defaultLocale ? `/${matchedLocale}` : '/'
      const redirectUrl = new URL(homePath, request.url)
      redirectUrl.searchParams.set('unlock', 'knowledge-base')
      redirectUrl.searchParams.set('redirect', pathname)

      const response = NextResponse.redirect(redirectUrl)
      if (token) {
        response.cookies.delete(KB_ACCESS_COOKIE_NAME)
      }
      return response
    }
  }

  return handleI18nRouting(request)
}

// Явно исключаем известные расширения статики вместо широкого `.*\..*`,
// чтобы слаги Базы Знаний с точкой (например, `next.js-16`) никогда не обходили Edge Auth.
export const config = {
  matcher: [
    '/((?!api|search-index|icon|apple-icon|_next|_vercel|.*opengraph-image.*|.*\\.(?:ico|png|jpg|jpeg|gif|svg|webp|avif|pdf|css|js|mjs|map|woff|woff2|ttf|otf|txt|xml|json|webmanifest)$).*)',
  ],
}
```

> [!IMPORTANT]
> Замена шаблонного исключения `.*\..*` на **явный перечень расширений статических файлов** закрывает классический вектор обхода Next.js middleware: любые будущие слаги Базы Знаний с точками (например, `next.js-16` или `node.js-streams`) гарантированно проходят через `proxy()` и Edge JWT-валидацию.

## 4. Интеграция в комплексный контур безопасности

Edge-валидация не работает изолированно: она является вторым рубежом в эшелонированной обороне монорепозитория. Подробнее о полной связке заголовков `Content-Security-Policy`, `Strict-Transport-Security`, `Helmet` и защите эндпоинтов от брутфорса через `@nestjs/throttler` читайте в архитектурном разборе [Production Security Hardening](/knowledge-base/this-project/security/production-security-hardening-csp-helmet-throttler) и манифесте [Zero-Trust безопасность в эпоху ИИ](/knowledge-base/others/security/zero-trust-web-security-in-ai-agent-era).
