## 1. Two-Dimensional Semantic Token Matrix (`Light/Dark` × `Palette`)

Instead of coupling components to raw Tailwind palette classes (`slate-*`, `emerald-*`, `amber-*`), the entire color system is defined as semantic HSL CSS variables (supporting alpha modifiers via native `color-mix()` in Tailwind v4 as well as SVG attributes like `hsl(var(--chart-1))`):

- **Surface Hierarchy:** `--background`, `--surface-subtle`, `--surface-elevated`, `--card`, `--popover`.
- **Semantic Statuses:** `--success`, `--warning`, `--info`, `--destructive` (paired with `*-foreground`).
- **Visualization & Code:** `--chart-1..4` for SVG/D3 diagrams and `--code-bg`, `--code-header`, `--code-border` for code blocks.

```css title="packages/ui/src/styles/theme.css"
@custom-variant dark (&:where(.dark, .dark *));

:root {
  --background: 40 20% 99%;
  --surface-subtle: 40 16% 96.5%;
  --surface-elevated: 0 0% 100%;
  --primary: 24 10% 12%;
  --success: 158 64% 32%;
  --warning: 32 92% 38%;
  --info: 214 84% 44%;
}

:root.dark,
.dark {
  --background: 24 10% 8%;
  --surface-subtle: 24 9% 10%;
  --surface-elevated: 24 9% 13%;
  --primary: 40 15% 95%;
  --success: 156 68% 54%;
}

@theme inline {
  --color-background: hsl(var(--background));
  --color-surface-subtle: hsl(var(--surface-subtle));
  --color-primary: hsl(var(--primary));
  --color-success: hsl(var(--success));
  --radius-sm: calc(var(--radius) - 4px);
  --radius-md: calc(var(--radius) - 2px);
  --radius-lg: var(--radius);
}
```

> [!TIP]
> Separating `.dark` from `data-palette` and wrapping runtime tokens in `@theme inline` makes adding a new theme or `multi-tenant / white-label` brand a pure ~20-variable CSS override with zero changes to React components.

## 2. CSS-First Dependency Inversion (`@repo/ui/theme.css` + `@source`)

To keep `@repo/ui` self-contained and agnostic of `apps/web`, the UI package exports a pure token-and-base stylesheet `@repo/ui/theme.css` (without `@import "tailwindcss";` inside it) and keeps its own Storybook entry (`packages/ui/src/styles/globals.css`) powered by `@tailwindcss/vite`.

In `apps/web`, PostCSS runs `@tailwindcss/postcss` and declares `@source` boundaries in its own entry CSS:

```css title="apps/web/src/app/globals.css"
@import "tailwindcss";
@import "@repo/ui/theme.css";

@source "../";
@source "../../content";
@source "../../../../packages/ui/src";
```

Both `apps/web/package.json` and `packages/ui/package.json` declare modern browser targets (`"browserslist": ["Chrome >= 111", "Edge >= 111", "Firefox >= 128", "Safari >= 16.4"]`) so `Lightning CSS` and `Next.js SWC` emit zero legacy polyfills for `@property` and `color-mix()`.

This architecture provides three advantages:
1. A single CSS-first source of truth mapping CSS variables to utility classes (`bg-surface-subtle`, `text-warning`, `border-code-border`) across both `apps/web` and `Storybook 10`.
2. Zero upward `../../apps/*` imports inside the shared design system package.
3. Instant onboarding for any new frontend app in the monorepo via `@import "@repo/ui/theme.css";` + `@source`.

## 3. Responsive Data Views (`< md` Cards vs `>= md` Tables)

For information-dense components, rather than squeezing wide tables onto `360px` screens, the UI switches representation patterns by breakpoint:

| Component | Smartphones (`< md`) | Tablets & Desktop (`>= md`) |
| :--- | :--- | :--- |
| **`TechRadarTable`** | Stacked card list (`md:hidden`) with direct `ADR` action buttons | Full 6-column `TanStack Table` (`hidden md:block`) with sorting and filtering |
| **`D3.js` / `SVG` Graphs** | Horizontal scroll container `overflow-x-auto` with `min-w-[540px]` | Full-width interactive vector simulation |
| **`Storybook 10` (`@repo/ui`)** | Viewport presets for `360px` and `768px` contrast verification | Live toolbar switcher for `Warm Paper / Dark / Graphite / Sepia` |
