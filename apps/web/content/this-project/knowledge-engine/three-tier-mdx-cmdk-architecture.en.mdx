## 1. 3-Tier Content Taxonomy for 100+ Engineering Notes

Flat lists break down as soon as a personal knowledge base grows beyond 15–20 notes. To keep both daily recall and technical interview navigation effortless, we organized `apps/web/content/` into a recursive multi-slug folder tree mapped to `/[locale]/knowledge-base/[...slug]`:

| Hierarchy Level | Filesystem Path Example | UI Representation |
| :--- | :--- | :--- |
| **1. Topic** | `content/react/` | Folded-by-default accordion branch in `KnowledgeSidebar` |
| **2. Subtopic** | `content/react/compiler/` | Horizontal filter tabs (`TopicSubtopicTabs`) on hub pages |
| **3. Leaf Note** | `auto-memoization-rules.en.mdx` | Clean distraction-free article with `TL;DR`, right `TOC`, and `Prev / Next` |

> [!TIP]
> Clicking any Topic or Subtopic row in the left sidebar simultaneously expands its children and opens the corresponding Hub overview, while clicking the chevron toggles the branch in-place without leaving your current note.

## 2. Zero-Client-JS Shiki & Lightweight RSC Search Index

Syntax highlighters are notoriously heavy when shipped to the browser. Instead of hydrating Prism or Highlight.js on the client, our `MdxArticleRenderer` invokes `Shiki` asynchronously inside React Server Components (`RSC`) with dual CSS-variable themes (`github-light` / `github-dark`).

Similarly, to power instant `< 5ms` global `Cmd+K` search across titles, `#tags`, and `h2 / h3` anchors without bloating HTML hydration payloads, `getKnowledgeSearchIndex` strips all Markdown AST blocks on the server before passing props to `CommandPaletteModal`:

```typescript title="apps/web/src/lib/mdx-content.ts"
export function getKnowledgeSearchIndex(locale: SupportedLocale): KnowledgeSearchItem[] {
  return getAllArticlesForLocale(locale).map((article) => ({
    routePath: article.routePath,
    title: article.title,
    sidebarLabel: article.sidebarLabel,
    topicLabel: formatKnowledgeSegmentLabel(article.category, locale),
    subtopicLabel: article.slugSegments[0]
      ? formatKnowledgeSegmentLabel(article.slugSegments[0], locale)
      : '',
    format: article.format,
    tags: article.tags,
    headings: article.toc
      .filter((h) => h.level === 2 || h.level === 3)
      .map(({ id, text }) => ({ id, text })),
  }))
}
```

## 3. Architecture-First Execution & Explicit Trade-offs Log

Rather than mixing visual experimentation with core routing and security plumbing, we executed Phases 1–5 in strict architectural order and surfaced an interactive **Engineering Backlog, Tech Debt & Trade-offs** board (`/#roadmap`) directly on the Workfolio home page:

- **Planned Next (`P1`):** Authentic **Notion Workfolio Visual Redesign (UI v2)** — applying warmer paper/ink aesthetics and borderless Notion views safely on top of our completed routing and state foundation.
- **Tracked Tech Debt:** `EventSource` `pagehide/pageshow` lifecycle for mobile `bfcache`, plus `CSP / HSTS` headers and `@nestjs/throttler` before public cloud deployment.
- **Consciously Deferred (`Trade-offs`):** Rejecting a database-backed WYSIWYG CMS and paid LLM RAG vector search while deterministic `Cmd+K` over Git-versioned `.mdx` delivers `0ms` offline reads at `$0/month`.
