## 1. Offline-First кешування в браузерній БД `IndexedDB`

Щоб повторні переходи по статтях і таблиці технологій відбувалися за **0 мс** (навіть при повній втраті мережі в режимі `Offline`), ми підключили `PersistQueryClientProvider` із `@tanstack/react-query-persist-client` з асинхронним адаптером `idb-keyval`.

На відміну від синхронного `LocalStorage` (який блокує основний потік рендеру при серіалізації JSON і обмежений 5 МБ), `IndexedDB` працює асинхронно та зберігає кеш `TanStack Query v5` із політикою `gcTime: 24h`.

## 3. Триступенева контейнеризація (`Docker` + `turbo prune`)

Усі три сервіси (`web`, `api`, `telemetry-ms`) упаковані в multi-stage `Dockerfile` у папці `docker/`:
1. **Stage 1 (`pruner`):** Виконує `turbo prune @repo/<app> --docker`, вирізаючи лише потрібні пакети монорепозиторію.
2. **Stage 2 (`builder`):** Кешує шари `pnpm install --frozen-lockfile` та збирає проєкт через `turbo build`.
3. **Stage 3 (`runner`):** Чистий `node:22-alpine` під непривілейованим користувачем (`non-root`), що запускається єдиною командою `docker compose up --build`.
