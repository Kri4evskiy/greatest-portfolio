## 1. Чому сучасний Full-Stack застосунок потребує ешелонованого захисту

У монорепозиторії, що об’єднує публічний інтерфейс Next.js, API на NestJS, внутрішній TCP-мікросервіс і PostgreSQL, компрометація одного вузла може каскадно зачепити всю систему. Наша архітектура реалізує принцип **Defense-in-Depth (Глибокоешелонована оборона)** на п’яти незалежних рівнях:

```text
[ Браузер ]
    │
    ├── (1) HTTP Security Headers (Next.js): звужений CSP, HSTS, COOP, CORP: same-origin, X-Frame-Options
    │
    ├── (2) Edge Auth Barrier (proxy.ts + edge-jwt.ts): гібридна БЗ + Fail-Closed HS256 Web Crypto JWT
    │
    ├── (3) API Gateway Hardening (NestJS): JSON-only парсер 100kb + суворий Helmet CSP + CsrfOriginMiddleware
    │
    ├── (4) Rate Limiting та RBAC: спільний Throttler (60/хв база, 5/хв auth і SSE) + HS256 1d JWT + Roles
    │
    └── (5) Ізоляція контейнерів і мереж (docker-compose.prod.yml): read_only, cap_drop ALL, 127.0.0.1, приватний TCP :4001
```

Кожен шар автономний: обхід клієнтської валідації зупиняється `CsrfOriginMiddleware`, `ZodValidationPipe` та `ThrottlerGuard` на API, а спроба вбудувати сайт у сторонній `<iframe>` блокується `frame-ancestors 'none'`.

## 2. HTTP Security Headers у Next.js 16 (`apps/web/config/security-headers.config.ts`)

Щоб `apps/web/next.config.ts` залишався компактним і не змішував інфраструктурний конфіг із шарами FSD, генерацію всіх заголовків винесено в `apps/web/config/security-headers.config.ts`. У продакшені з `connect-src` навмисно прибрано широкий `https:` — дозволені лише `'self'` і явно провалідовані через `parseSafeHttpOrigin` домени (`NEXT_PUBLIC_API_URL`, `NEXT_PUBLIC_POSTHOG_HOST`, `NEXT_PUBLIC_SENTRY_DSN`):

```typescript title="apps/web/config/security-headers.config.ts"
export function buildContentSecurityPolicy(
  isProduction: boolean,
  publicApiUrl = '',
  options: ContentSecurityPolicyOptions = {},
): string {
  const { allowSameOriginFraming = false } = options
  const allowedConnectOrigins = new Set<string>()
  const safeApiOrigin = parseSafeHttpOrigin(publicApiUrl)
  if (safeApiOrigin) allowedConnectOrigins.add(safeApiOrigin)

  const posthogOrigin = parseSafeHttpOrigin(process.env.NEXT_PUBLIC_POSTHOG_HOST)
  if (posthogOrigin) allowedConnectOrigins.add(posthogOrigin)
  const sentryOrigin = parseSafeHttpOrigin(process.env.NEXT_PUBLIC_SENTRY_DSN)
  if (sentryOrigin) allowedConnectOrigins.add(sentryOrigin)

  const extraConnectSrc = allowedConnectOrigins.size > 0 ? ` ${Array.from(allowedConnectOrigins).join(' ')}` : ''

  // У продакшені внутрішні порти та широкий `https:` НІКОЛИ не потрапляють до connect-src.
  const connectSrc = isProduction
    ? `'self'${extraConnectSrc}`
    : `'self' http://localhost:4000 http://localhost:4001 http://127.0.0.1:4000 http://127.0.0.1:4001 ws: wss:${extraConnectSrc}`

  // У продакшені 'unsafe-eval' повністю вимкнений (MDX компілюється в HAST без eval).
  const scriptSrc = isProduction ? "'self' 'unsafe-inline'" : "'self' 'unsafe-inline' 'unsafe-eval'"
  const frameAncestors = allowSameOriginFraming ? "'self'" : "'none'"

  const directives: string[] = [
    "default-src 'self'",
    `script-src ${scriptSrc}`,
    "style-src 'self' 'unsafe-inline'",
    "img-src 'self' blob: data: https:",
    "font-src 'self' data:",
    `connect-src ${connectSrc}`,
    "frame-src 'self'",
    `frame-ancestors ${frameAncestors}`,
    "form-action 'self'",
    "base-uri 'self'",
    "object-src 'self'",
    ...(isProduction ? ['upgrade-insecure-requests'] : []),
  ]

  return directives.join('; ').trim()
}
```

### Ключові директиви `getSecurityHeaders()`
- **Звужений `connect-src` і Zero Eval у продакшені:** видалені порти `:4000`, `:4001`, `localhost`, широкий `https:` і `'unsafe-eval'`.
- **`Cross-Origin-Opener-Policy: same-origin` та `Cross-Origin-Resource-Policy: same-origin`:** ізолюють контекст вікна та блокують крос-доменне читання фронтенд-ресурсів (захист від XS-Leaks і Spectre).
- **Clickjacking і точковий скоуп для `/cv/:path+`:** `next.config.ts` вимикає `poweredByHeader`, застосовує `frame-ancestors 'none'` + `X-Frame-Options: DENY` до всіх маршрутів `/(.*)` і послаблює їх до `'self'` / `SAMEORIGIN` **виключно** для `/cv/:path+`, щоб SPA-перехід `<Link href="/cv">` рендерив `<object type="application/pdf">` без послаблення решти сайту.
- **`Strict-Transport-Security` (лише прод), `nosniff`, `Referrer-Policy`, `Permissions-Policy`:** `max-age=63072000; includeSubDomains; preload`, `X-Content-Type-Options: nosniff`, `strict-origin-when-cross-origin` і `camera=(), microphone=(), geolocation=(), browsing-topics=()`.

## 3. Гібридний доступ до БЗ, явний `matcher` статики та Fail-Closed Edge JWT (`proxy.ts` і `edge-jwt.ts`)

У Next.js 16 `apps/web/src/proxy.ts` реалізує **гібридну політику доступу** до Бази Знань через `isProtectedKnowledgeBasePath()`:
- **Публічні та індексовані (SEO):** хаб `/knowledge-base` і вся гілка `/knowledge-base/this-project/**` відкриваються напряму без редиректів для пошукових систем, рекрутерів і тімлідів.
- **Захищені Edge Web Crypto JWT:** решта доменних категорій конспектів (`/knowledge-base/react/**` тощо) вимагають валідну куку `kb_access_token`, що перевіряється через `verifyEdgeJwtHs256()`.

```typescript title="apps/web/src/proxy.ts"
// Явно виключаємо лише відомі розширення статики замість широкого `.*\..*`,
// щоб майбутні слаги Бази Знань із крапками (наприклад, `next.js-16`) не обходили Edge Auth.
export const config = {
  matcher: [
    '/((?!api|search-index|icon|apple-icon|_next|_vercel|.*opengraph-image.*|.*\\.(?:ico|png|jpg|jpeg|gif|svg|webp|avif|pdf|css|js|mjs|map|woff|woff2|ttf|otf|txt|xml|json|webmanifest)$).*)',
  ],
}
```

Функція `verifyEdgeJwtHs256()` у `apps/web/src/shared/lib/edge-jwt.ts` працює суворо за принципом **fail-closed**:
1. Перевіряє `header.alg === 'HS256'`, `exp`, опційний `nbf`, непорожній `sub` і `role` із `{'USER', 'ADMIN'}`.
2. Викликає `resolveEdgeJwtSecretStrict()`, який повертає `null` у продакшені (поза явним `WORKFOLIO_DEMO_MODE=true`), якщо `JWT_SECRET` відсутній, коротший за 32 символи або дорівнює `DEFAULT_DEV_JWT_SECRET` — Edge Auth ніколи не відкочується на публічний dev-ключ.
3. Кешує імпортований Web Crypto `CryptoKey` за значенням секрету й очищає відхилений проміс при помилці, щоб транзиентний збій не «отруїв» Edge-ізолят.

## 4. Захист API-шлюзу (`main.ts`), JWT `1d` із `HS256` та безпечні фільтри помилок

У `apps/api/src/main.ts` Express запускається з `bodyParser: false` і реєструє **лише** JSON-парсер `100kb` (парсер `urlencoded` повністю видалено), налаштовує `trust proxy` через валідований `appConfig.trustProxyHops` (`0..5`, за замовчуванням `1`) та вмикає **суворий Helmet JSON CSP** разом із cross-origin CORP для авторизованих крос-доменних запитів Vercel ➔ Render:

```typescript title="apps/api/src/main.ts"
async function bootstrap(): Promise<void> {
  const app = await NestFactory.create<NestExpressApplication>(AppModule, {
    bodyParser: false,
  })
  app.useBodyParser('json', { limit: '100kb' })

  if (appConfig.isProduction && appConfig.trustProxyHops > 0) {
    app.set('trust proxy', appConfig.trustProxyHops)
  }

  app.setGlobalPrefix('api')
  app.use(
    helmet({
      crossOriginResourcePolicy: { policy: 'cross-origin' },
      contentSecurityPolicy: {
        directives: {
          defaultSrc: ["'none'"],
          frameAncestors: ["'none'"],
        },
      },
    }),
  )
  app.use(cookieParser())
  app.useGlobalFilters(new SentryExceptionFilter())
  app.useGlobalInterceptors(new LoggingInterceptor())

  app.enableCors({
    origin: appConfig.allowedOrigins,
    credentials: true,
    methods: ['GET', 'POST', 'PUT', 'PATCH', 'DELETE', 'OPTIONS'],
    exposedHeaders: ['X-Request-Id'],
  })
  app.enableShutdownHooks()
}
```

### Посилення автентифікації та безпечна серіалізація помилок
- **TTL `1d`, закріплення `HS256` та відмова при хибному `adminPasscode` (`AuthService`):**
  `KB_COOKIE_MAX_AGE_MS` скорочено до **1 дня** (`expiresIn: '1d'`), підпис жорстко фіксує `algorithm: 'HS256'`, а верифікація — `algorithms: ['HS256']`. При передачі непорожнього `adminPasscode` метод `isPasscodeMatch()` порівнює SHA-256 геші через `crypto.timingSafeEqual()` і при розбіжності викидає **`403 ForbiddenException`** без тихого пониження до `USER`.
- **Захист `headersSent` та санітизація логів (`SentryExceptionFilter`):**
  При обриві активного SSE-потоку HTTP-заголовки вже надіслані клієнту — перевірка `if (response.headersSent) return` запобігає неперехопленому падінню воркера з `ERR_HTTP_HEADERS_SENT`. Усі користувацькі URL і заголовки проходять через `sanitizeLogValue()` (видалення ANSI-послідовностей, `\r\n` і керуючих символів) проти Log Forging.
- **Zero-Eval санітизація MDX (`apps/web/src/entities/knowledge-content/lib/`):**
  `mdx-ast-parser.ts` вимикає legacy eval-рушії `js`/`javascript` у `gray-matter` і вирізає довільні сирі HTML-блоки, а `link-sanitizer.ts` (`classifySafeMarkdownLink` / `isSafeMarkdownImageSrc`) блокує `javascript:`, `data:` та protocol-relative посилання `//` / `/\`.

## 5. `CsrfOriginMiddleware` і безпечні патерни для майбутніх завантажень медіа

Оскільки куки `SameSite=Lax` не закривають усі крос-сайтові вектори (наприклад, атаки із сусідніх піддоменів або прості HTML `<form>`-запити), `AppModule` застосовує `CsrfOriginMiddleware` на `'{*path}'` до всіх мутуючих методів (`POST`, `PUT`, `PATCH`, `DELETE`):

1. **JSON-only бар’єр `Content-Type` (`415 Unsupported Media Type`):** відхиляє будь-який мутуючий запит із тілом, чий `Content-Type` не містить `application/json` — блокуючи всі три типи CORS «simple requests» (`application/x-www-form-urlencoded`, `text/plain`, `multipart/form-data`), які крос-сайтова HTML-форма може надіслати без preflight.
2. **Білий список `Origin` (`403 Forbidden`):** за наявності заголовка `Origin` він зобов’язаний входити до `appConfig.allowedOrigins`.
3. **Перевірка `Sec-Fetch-Site` (`403 Forbidden`):** відхиляє будь-які значення `Sec-Fetch-Site`, відмінні від `same-origin` і `none`, якщо `Origin` не перебуває в явному білому списку (зберігаючи крос-доменні запити Vercel ➔ Render при налаштованому `WEB_ORIGIN`).

### Архітектурні патерни розширення для майбутніх завантажень файлів
Якщо в платформі з’являться завантаження аватарів, вкладень або медіафайлів, у `CsrfOriginMiddleware` зафіксовано два безпечні патерни:
- **Патерн A (Рекомендований — Presigned URLs для S3/R2):** клієнт викликає JSON-ендпоінт (`POST /api/storage/presign`), який проходить `CsrfOriginMiddleware` без змін, отримує короткоживуче підписане посилання і завантажує бінарник напряму до Cloudflare R2 / MinIO — API залишається суворо JSON-only без навантаження на RAM Node.js.
- **Патерн B (Точковий Multipart Proxy):** якщо окремому маршруту NestJS усе ж знадобиться `multipart/form-data`, із JSON-перевірки виключається **суворо** цей конкретний шлях за вузьким allowlist з обов’язковим збереженням перевірок `Origin`, `Sec-Fetch-Site` та кастомного заголовка для preflight (наприклад, `X-Requested-With`).
- **Обов’язкове правило проти Stored XSS:** ніколи не приймати й не віддавати користувацькі `.svg` інлайн із домену застосунку; дозволяти лише растрові формати (`PNG`, `WebP`, `AVIF`, `JPEG`), перевірені за magic bytes і роздавані з ізольованого CDN/R2-домену або під пісочницею CSP.

## 6. Захист від брутфорсу та DoS: спільний бакет `@nestjs/throttler` та обмежений SSE

`AppModule` встановлює глобальний ліміт **`60 req/min`** і кастомний `generateKey`, щоб `/api/auth/guest-pass` (`issueGuestPass`) та його аліас `/api/auth/login` (`login`) ділили **єдиний бакет `5 req/min`** — зловмисник не зможе подвоїти кількість спроб підбору пароля через два маршрути:

```typescript title="apps/api/src/app.module.ts"
const SHARED_AUTH_THROTTLE_HANDLERS = new Set(['issueGuestPass', 'login'])

ThrottlerModule.forRoot({
  throttlers: [{ ttl: 60000, limit: 60 }],
  generateKey: (context, trackerString, throttlerName) => {
    const className = context.getClass().name
    const handlerName = context.getHandler().name
    if (className === 'AuthController' && SHARED_AUTH_THROTTLE_HANDLERS.has(handlerName)) {
      return `AuthController:issuePass:${trackerString}:${throttlerName}`
    }
    return `${className}:${handlerName}:${trackerString}:${throttlerName}`
  },
})
```

### Обмежений SSE замість `@SkipThrottle()`
Замість повного зняття ліміту метод `TelemetryController.streamEvents()` використовує **`@Throttle({ default: { limit: 5, ttl: 60000 } })`** (не більше 5 перепідключень за хвилину з одного IP) у парі з **`@SkipTimeout()`**, щоб `TimeoutInterceptor` не обривав відкритий потік. Одночасно `TelemetryService` обмежує активні стріми квотами **`2/IP`**, **`50` глобально** і максимальним часом життя **`15 хвилин`** (`finalize()` звільняє слот при розриві).

### Еволюція: In-Memory ➔ розподілений Redis Throttler
На одному інстансі працюють безкоштовні In-Memory лічильники. При горизонтальному масштабуванні `apps/api` підключення `ThrottlerStorageRedisService` поверх `REDIS_URL` синхронізує ковзні вікна між репліками з автоматичним відкатом на локальну пам’ять за відсутності `REDIS_URL`.

## 7. Чек-лист захищеності, ізоляція контейнерів та усвідомлені компроміси

У `docker-compose.prod.yml` усі контейнери застосунку (`web`, `api`, `telemetry-ms`) запускаються з `read_only: true`, `cap_drop: [ALL]`, `no-new-privileges:true`, `pids_limit: 256`, біндингом портів суворо на `127.0.0.1`, обов’язковими секретами `${JWT_SECRET:?...}`, а PostgreSQL і TCP `:4001` ізольовані всередині `backend-network`.

| Вектор загрози | Механізм захисту в монорепозиторії | Статус |
| :--- | :--- | :--- |
| **Крадіжка сесії через XSS** | `HttpOnly` куки + Zero-Eval HAST (вимкнені JS-рушії `gray-matter`) + `classifySafeMarkdownLink` | 🛡️ Захищено |
| **CSRF (Login/Logout/мутації)** | `SameSite=Lax` + `CsrfOriginMiddleware` (JSON-only `415`, `Origin` + `Sec-Fetch-Site` `403`) + видалено `urlencoded` | 🛡️ Захищено |
| **Clickjacking та XS-Leaks** | `X-Frame-Options: DENY`, CSP `frame-ancestors 'none'` (scoped `/cv/:path+`), `COOP: same-origin`, `CORP: same-origin` | 🛡️ Захищено |
| **Брутфорс і SSE-флуд** | Глобально `60/хв`, спільний `5/хв` на auth, `403` на хибний `adminPasscode`, SSE `5/хв` + `2/IP` / `50` глобально / `15m` TTL | 🛡️ Захищено |
| **Log Forging і падіння на стрімі** | `resolveCorrelationRequestId` + `sanitizeLogValue` + перевірка `response.headersSent` у `SentryExceptionFilter` | 🛡️ Захищено |
| **Втеча з контейнера / витік TCP** | Loopback `127.0.0.1:4001` за замовчуванням + `docker-compose.prod.yml` (`read_only`, `cap_drop: ALL`, `backend-network`) | 🛡️ Захищено |

### Усвідомлені архітектурні компроміси (Engineering Trade-offs)
1. **Статична генерація `SSG` (`'unsafe-inline'`) проти динамічного `CSP Nonce`:**
   - *Компроміс:* Відмова від `'unsafe-inline'` у `script-src` вимагає генерації унікального `nonce` на кожен запит, що примусово переводить усі **199** статичних маршрутів з **SSG** у динамічний `SSR` і позбавляє CDN-кешування.
   - *Компенсація:* Платформа не рендерить користувацький UGC HTML (усі `.mdx` лежать у репозиторії, компілюються Zero-Eval HAST із вирізанням сирого HTML і санітизацією посилань), а JWT-сесії ізольовані в `HttpOnly` куках.
2. **Гібридне діскавері (`/search-index/[locale]` і `/knowledge-base/this-project/**`) проти захищених конспектів:**
   - *Компроміс:* `proxy.ts` навмисно залишає публічними `/search-index/[locale]`, `/knowledge-base` і `/knowledge-base/this-project/**` заради SEO й миттєвої оцінки архітектури рекрутерами, закриваючи решту категорій БЗ fail-closed Edge `HS256` JWT-перевіркою.
3. **Stateless-перевірка `1d` JWT на Edge проти миттєвого відкликання сесій (до Redis):**
   - *Компроміс:* `verifyEdgeJwtHs256` перевіряє підпис і `exp` за `< 0.2 мс` без походу до БД, тому токен на **`1d`** не можна відкликати індивідуально до завершення терміну без ротації `JWT_SECRET`.
   - *Компенсація:* Скорочення TTL токена із 7 днів до **`1d`** радикально звужує вікно ризику, а Post-MVP Roadmap передбачає зв’язку **Redis** + короткий `Access` (`15m`) + ротований `HttpOnly Refresh` на базі `VisitorSession`.
