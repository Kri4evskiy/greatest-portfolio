## 1. Двовимірна матриця семантичних токенів (`Light/Dark` × `Palette`)

Замість прив'язки компонентів до конкретних палітр Tailwind (`slate-*`, `emerald-*`, `amber-*`) уся колірна система винесена в семантичні CSS-змінні у форматі `H S% L%` (сумісному як із нативним `color-mix()` для модифікаторів прозорості в Tailwind v4, так і з SVG-атрибутами `hsl(var(--chart-1))`):

- **Ієрархія поверхонь:** `--background`, `--surface-subtle`, `--surface-elevated`, `--card`, `--popover`.
- **Семантичні статуси:** `--success`, `--warning`, `--info`, `--destructive` (із парними `*-foreground`).
- **Візуалізація та код:** `--chart-1..4` для SVG/D3-діаграм і `--code-bg`, `--code-header`, `--code-border` для блоків коду.

```css title="packages/ui/src/styles/theme.css"
@custom-variant dark (&:where(.dark, .dark *));

:root {
  --background: 40 20% 99%;
  --surface-subtle: 40 16% 96.5%;
  --surface-elevated: 0 0% 100%;
  --primary: 24 10% 12%;
  --success: 158 64% 32%;
  --warning: 32 92% 38%;
  --info: 214 84% 44%;
}

:root.dark,
.dark {
  --background: 24 10% 8%;
  --surface-subtle: 24 9% 10%;
  --surface-elevated: 24 9% 13%;
  --primary: 40 15% 95%;
  --success: 156 68% 54%;
}

@theme inline {
  --color-background: hsl(var(--background));
  --color-surface-subtle: hsl(var(--surface-subtle));
  --color-primary: hsl(var(--primary));
  --color-success: hsl(var(--success));
  --radius-sm: calc(var(--radius) - 4px);
  --radius-md: calc(var(--radius) - 2px);
  --radius-lg: var(--radius);
}
```

> [!TIP]
> Розділення осей `.dark` і `data-palette` у зв'язці з `@theme inline` дозволяє підключити будь-яку нову тему або брендинг клієнта (`multi-tenant / white-label`) перевизначенням ~20 змінних у CSS без жодної правки в React-компонентах.

## 2. CSS-first інверсія залежностей (`@repo/ui/theme.css` + `@source`)

Щоб пакет `@repo/ui` залишався повністю незалежним і не знав про файлову структуру `apps/web`, він експортує чистий шар токенів і базових стилів `@repo/ui/theme.css` (без `@import "tailwindcss";`), а вітрина Storybook у `packages/ui/src/styles/globals.css` збирається нативним плагіном `@tailwindcss/vite`.

У `apps/web` підключається `@tailwindcss/postcss`, а вхідний CSS-файл явно вказує межі сканування `@source`:

```css title="apps/web/src/app/globals.css"
@import "tailwindcss";
@import "@repo/ui/theme.css";

@source "../";
@source "../../content";
@source "../../../../packages/ui/src";
```

Обидва пакети (`apps/web/package.json` і `packages/ui/package.json`) фіксують сучасні таргети `"browserslist": ["Chrome >= 111", "Edge >= 111", "Firefox >= 128", "Safari >= 16.4"]`, щоб `Lightning CSS` і `Next.js SWC` не генерували зайві поліфіли під `@property` і `color-mix()`.

Така схема дає три архітектурні переваги:
1. Єдине CSS-first джерело мапінгу змінних у класи Tailwind (`bg-surface-subtle`, `text-warning`, `border-code-border`) як для `apps/web`, так і для ізольованого `Storybook 10`.
2. Відсутність зворотних шляхів `../../apps/*` усередині пакета дизайн-системи.
3. Можливість підключити другий фронтенд-сервіс до тієї самої дизайн-системи двома рядками: `@import "@repo/ui/theme.css";` і `@source`.

## 3. Адаптивні подання щільних даних (`< md` проти `>= md`)

У компонентах із високою щільністю інформації замість горизонтального стискання таблиць на вузьких екранах (`360px`) застосовується зміна патерну відображення:

| Компонент | Смартфони (`< md`) | Планшети та десктоп (`>= md`) |
| :--- | :--- | :--- |
| **`TechRadarTable`** | Стек карток (`md:hidden`) зі швидким переходом до `ADR` | 6-колонкова таблиця `TanStack Table` (`hidden md:block`) із сортуванням і фільтрами |
| **`D3.js` / `SVG` графи** | Горизонтальний скрол-контейнер `overflow-x-auto` з `min-w-[540px]` | Повна інтерактивна векторна сцена на всю ширину колонки |
| **`Storybook 10` (`@repo/ui`)** | Перевірка контрасту та переносів у в'юпортах `360px` і `768px` | Інтерактивне перемикання тем `Warm Paper / Dark / Graphite / Sepia` в тулбарі |
