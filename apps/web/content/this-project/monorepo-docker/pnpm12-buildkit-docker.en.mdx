## 1. Migrating from pnpm 10 to pnpm 12

In **pnpm 12**, legacy `package.json` build fields (`pnpm.onlyBuiltDependencies`) were completely removed in favor of a strict `allowBuilds` map inside `pnpm-workspace.yaml`. Any unlisted native package with `postinstall` scripts triggers `ERR_PNPM_IGNORED_BUILDS`.

### Workspace allowBuilds Configuration

```yaml title="pnpm-workspace.yaml"
packages:
  - "apps/*"
  - "packages/*"

allowBuilds:
  "@biomejs/biome": true
  "@parcel/watcher": true
  "@prisma/client": true
  "@prisma/engines": true
  "@swc/core": true
  esbuild: true
  lefthook: true
  prisma: true
  sharp: true
```

> [!IMPORTANT]
> Never add `"pnpm"` configuration blocks inside `package.json` when targeting **pnpm 12+**. Both local developers and Vercel Corepack read `allowBuilds` exclusively from `pnpm-workspace.yaml`.

## 2. Shared BuildKit Cache Mounts Across Microservices

Previously, `web`, `api`, and `telemetry-ms` downloaded **100+ MB** of identical Linux binaries from scratch whenever `pnpm-lock.yaml` changed.

### Pre-Warming Corepack & Mounting the Store

Mounting `/root/.local/share/pnpm/store` as a persistent BuildKit cache shares downloaded tarballs across all 3 Dockerfiles:

```dockerfile title="docker/api.Dockerfile"
RUN corepack enable && corepack prepare pnpm@12.16.1 --activate && pnpm --version
RUN --mount=type=cache,id=pnpm,target=/root/.local/share/pnpm/store \
    pnpm install --frozen-lockfile --ignore-scripts
```

## 3. Production Image Benchmarks & Prisma Preservation

Running `pnpm prune --prod --ignore-scripts` right after `turbo run build` removes **Biome**, **Turbo**, **TypeScript**, and **Prisma CLI** from production runner layers while preserving the generated `.prisma/client` runtime engine.

### Before vs After Optimization Matrix

| Container | Before (`node_modules` full) | After (`pnpm prune --prod`) | Layer Export Time |
| :--- | :---: | :---: | :---: |
| `workfolio-telemetry-ms` | ~215 MB | **64.3 MB** | 1.8s |
| `workfolio-api` | ~260 MB | **78.2 MB** | 2.4s |
| `workfolio-web` (standalone) | ~140 MB | **85.6 MB** | 2.1s |

> [!TIP]
> Because `api` runs `pnpm prune --prod`, schema migrations (`prisma migrate deploy`) are executed from CI/CD or a local terminal against **Neon.tech**, keeping the production container attack surface minimal.

### Production Hardening Checklist

- [x] Non-root user (`nestjs` / `nextjs`, UID `1001`) in every runner stage
- [x] Telemetry disabled in CI builds (`DO_NOT_TRACK=1`, `TURBO_TELEMETRY_DISABLED=1`)
- [x] Zero impact on **Vercel** (`apps/web`) and **Neon.tech** (`DATABASE_URL`) cloud deployments
