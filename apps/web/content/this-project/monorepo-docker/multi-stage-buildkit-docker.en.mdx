## 1. Multi-Stage Build Pipeline (`pruner -> builder -> runner`)

To keep source files, compilers, and unrelated workspace packages out of production images, every Dockerfile in `docker/` separates container construction into three deterministic stages:

1. **`pruner`:** runs `turbo prune @repo/<app> --docker` to emit the minimal subgraph (`out/json/`, `out/full/`, `out/pnpm-lock.yaml`) needed by the target service.
2. **`builder`:** activates `pnpm@12.21.0`, runs `pnpm install --frozen-lockfile --ignore-scripts` with a shared BuildKit cache mount, runs `pnpm turbo run build --filter=@repo/<app>...`, and prunes `devDependencies`.
3. **`runner`:** copies only compiled artifacts (`dist/` or `.next/standalone`) and executes under a non-root user (`USER node` / `USER nextjs`).

---

## 2. `turbo prune` & Shared BuildKit Cache Mount

When building multiple containers from one monorepo, `out/json/` keeps the dependency installation layer cached across code changes, while mounting `/root/.local/share/pnpm/store` with BuildKit `type=cache,id=pnpm` downloads shared packages once and reuses them across all service builds:

```dockerfile title="docker/api.Dockerfile"
FROM node:22-alpine AS pruner
RUN apk add --no-cache libc6-compat openssl
ENV DO_NOT_TRACK=1
ENV TURBO_TELEMETRY_DISABLED=1
RUN npm install -g turbo@^2
WORKDIR /app
COPY . .
RUN turbo prune @repo/api --docker

FROM node:22-alpine AS builder
RUN apk add --no-cache libc6-compat openssl
ENV DO_NOT_TRACK=1
ENV TURBO_TELEMETRY_DISABLED=1
RUN corepack enable && corepack prepare pnpm@12.21.0 --activate && pnpm --version
WORKDIR /app

COPY --from=pruner /app/out/json/ .
COPY --from=pruner /app/out/pnpm-lock.yaml ./pnpm-lock.yaml
RUN --mount=type=cache,id=pnpm,target=/root/.local/share/pnpm/store \
    pnpm install --frozen-lockfile --ignore-scripts
```

## 3. Pruning `devDependencies` with Rust-Free Prisma 7

In the `builder` stage, `pnpm turbo run build --filter=@repo/api...` generates the Prisma 7 ESM client (`prisma-client`) directly into `apps/api/src/generated/prisma/` and compiles it with `tsc` into `apps/api/dist/generated/prisma/`. Because Prisma 7 replaces the legacy `.prisma/client` Rust binary engine with a Wasm query compiler bundled inside production `@prisma/client` (paired with `@prisma/adapter-pg` and `pg`), `pnpm prune --prod --ignore-scripts` requires no `/tmp` staging workaround and the `runner` stage no longer needs `openssl`:

```dockerfile title="docker/api.Dockerfile"
RUN --mount=type=cache,id=pnpm,target=/root/.local/share/pnpm/store \
    pnpm turbo run build --filter=@repo/api... && \
    pnpm prune --prod --ignore-scripts

# Stage 3: Production non-root runner
FROM node:22-alpine AS runner
WORKDIR /app
ENV NODE_ENV=production
ENV PORT=4000
```

### Production Image Profiles

| Container | Base Image | Port Scope | Runtime User |
| :--- | :---: | :---: | :---: |
| `workfolio-telemetry-ms` | `node:22-alpine` | `4001` (internal network only) | `node` (non-root) |
| `workfolio-api` | `node:22-alpine` | `4000` | `node` (non-root) |
| `workfolio-web` (`standalone`) | `node:22-alpine` | `3000` | `nextjs` (`UID 1001`) |

> [!TIP]
> Because the production `api` image excludes `Prisma CLI`, database schema migrations (`prisma migrate deploy`) run as a dedicated CI/CD step before rolling out new containers.

## 4. Separating `docker-compose.yml` (Zero-Friction Reviewer Demo) from `docker-compose.prod.yml` (Strict Production)

To let a reviewing Team Lead or CTO spin up the entire topology in a single command (`docker compose up --build`) without manually creating an `.env` file while keeping real cloud/VPS deployments strictly locked down, orchestration is split into two Compose definitions:

| Parameter | `docker-compose.yml` (Local Reviewer Demo) | `docker-compose.prod.yml` (Strict Production) |
| :--- | :--- | :--- |
| **Launch Command** | `docker compose up --build -d` | `docker compose -f docker-compose.prod.yml --env-file .env.prod up --build -d` |
| **`WORKFOLIO_DEMO_MODE`** | `"true"` (permits fallback to the shared `DEFAULT_DEV_JWT_SECRET` in `@repo/shared-schemas` and logs an explicit warning) | Omitted (`"false"` — enforces strict fail-fast validation in `loadAppConfig`) |
| **Compose-Level Secret Enforcement** | `${JWT_SECRET:-}` (auto-resolved via `resolveJwtSecret()` without `.env`) | Hard fail-fast interpolation `${JWT_SECRET:?}`, `${ADMIN_SECRET_PASSCODE:?}`, `${POSTGRES_PASSWORD:?}` |
| **`Secure` Flag on `HttpOnly` `kb_access_token` Cookie** | `false` (`appConfig.isProduction && !appConfig.isDemoMode` — works over `http://localhost:3000`) | `true` (enforced strictly over HTTPS / TLS) |
| **PostgreSQL Port (`5432`)** | `127.0.0.1:5432:5432` (bound to host loopback for DBeaver / DataGrip inspection) | **Unpublished from host** (100% isolated inside the private `backend-network`) |
