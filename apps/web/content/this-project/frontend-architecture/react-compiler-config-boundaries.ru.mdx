## 1. Конфигурация `reactCompiler` и оптимизация бандла в `apps/web/next.config.ts`

В Next.js 16 настройка `reactCompiler` принимает типизированный объект `ReactCompilerOptions` в связке с оптимизацией импортов из barrel-пакетов:

```typescript title="apps/web/next.config.ts"
const nextConfig: NextConfig = {
  ...(process.env.DOCKER_STANDALONE === 'true' ? { output: 'standalone' } : {}),
  ...(process.env.NEXT_DIST_DIR ? { distDir: process.env.NEXT_DIST_DIR } : {}),
  poweredByHeader: false,
  reactStrictMode: true,
  reactCompiler: {
    compilationMode: 'infer',
    panicThreshold: 'none',
  },
  transpilePackages: ['@repo/ui', '@repo/shared-schemas'],
  experimental: {
    optimizePackageImports: ['lucide-react', 'd3', '@repo/ui', '@repo/shared-schemas'],
  },
}
```

### Почему выбраны именно эти параметры

| Параметр | Значение | Инженерное обоснование |
| :--- | :---: | :--- |
| **`compilationMode`** | `'infer'` | Next.js применяет быстрые эвристики на Rust/SWC до вызова `babel-plugin-react-compiler`: компилятор запускается только для файлов с PascalCase-компонентами (JSX) и хуками `use*`, не тратя время сборки на утилиты (`mdx-ast-parser.ts`, `edge-jwt.ts`) |
| **`panicThreshold`** | `'none'` | При встрече со сложным мутабельным SDK компилятор безопасно пропускает оптимизацию конкретной функции вместо аварийной остановки `next build` в CI/CD |
| **`optimizePackageImports`** | `['lucide-react', 'd3', '@repo/ui', '@repo/shared-schemas']` | Переписывает barrel-импорты в прямые пути подмодулей на этапе сборки, чтобы клиентские чанки включали только фактически используемые иконки, функции D3, UI-компоненты и схемы |

## 2. Внутренняя таблица `knownIncompatible` и `React Hook Form`

Внутри `babel-plugin-react-compiler` (`DefaultModuleTypeProvider`) зашит список хуков сторонних библиотек, возвращающих нестабильные или мутабельные объекты:

1. **`react-hook-form` (`useForm().watch`)**: метод `watch()` мутирует внутренние подписки без смены ссылки, поэтому компилятор помечает его как `knownIncompatible`. В `apps/web/src/features/auth/guest-pass-modal.tsx` мы используем совместимый хук **`useWatch({ control, name: 'visitorType' })`**, благодаря чему вся модалка `GuestPassModal` успешно проходит авто-мемоизацию.
2. **`@tanstack/react-table` (`useReactTable`)**: возвращает стабильную ссылку на объект таблицы и мутирует его поля на месте (`interior mutability`). При обнаружении `useReactTable` компилятор отключает оптимизацию для **всей функции-компонента**, в которой вызван этот хук.

## 3. Вынесенные границы изоляции `'use no memo'` для таблиц

### А. `TechRadarTable` и вынесенные подмодули `table/`
Компонент `TechRadarTable` (`apps/web/src/entities/engineering-roadmap/tech-radar-table.tsx`) объединяет поиск, фильтр категорий, мобильный стек карточек (`< md`), десктопную таблицу (`>= md`) и модальное окно инспектора `ADR`. Чтобы родительский компонент оставался скомпилированным, слой TanStack Table вынесен в два отдельных файла внутри `apps/web/src/entities/engineering-roadmap/table/`:

- **`table/tech-radar-columns.tsx`** — чистая фабрика `createTechRadarColumns({ labels, onInspectAdr })`, возвращающая типизированный массив `ColumnDef<TechRadarItem>[]`.
- **`table/tech-radar-data-table.tsx`** — тонкая обёртка с директивой `'use no memo'`, инкапсулирующая `useReactTable` и локальный стейт `sorting`:

```tsx title="apps/web/src/entities/engineering-roadmap/table/tech-radar-data-table.tsx"
export function DesktopTechRadarDataTable({ data, columns, emptyResultLabel }: DesktopTechRadarDataTableProps) {
  'use no memo'

  const [sorting, setSorting] = useState<SortingState>([{ id: 'adrNumber', desc: false }])

  const table = useReactTable({
    data,
    columns,
    state: { sorting },
    onSortingChange: setSorting,
    getCoreRowModel: getCoreRowModel(),
    getSortedRowModel: getSortedRowModel(),
  })

  return (
    <div className="hidden overflow-x-auto rounded-lg border border-border bg-card shadow-xs md:block">
      {/* Рендер заголовков и строк TanStack Table */}
    </div>
  )
}
```

В родительском `TechRadarTable` значения `filteredData` и `columns` (создаваемые через `createTechRadarColumns`) осознанно обернуты в `useMemo`, а `handleInspectAdr` — в `useCallback`: это стабилизирует ссылки, пересекающие границу `'use no memo'` в `DesktopTechRadarDataTable`, чтобы открытие модалки ADR не вызывало пересчёт модели строк TanStack Table. Фильтры, мобильные карточки, `activeDialogItem` и JSX модального окна `Dialog` при этом полностью оптимизируются React Compiler.

### Б. Универсальная `ObservabilityDataTable` с типизацией `ColumnMeta`
Для таблиц телеметрии и лидерборда на `/system-status` модуль `apps/web/src/features/telemetry-stream/ui/table/observability-data-table.tsx` предоставляет обобщённый `'use no memo'` компонент поверх TanStack Table v8 для серверной пагинации (`manualPagination: true`, `manualSorting: true`, опциональный `getRowId`), дополненный строгим module augmentation для `ColumnMeta`:

```tsx title="apps/web/src/features/telemetry-stream/ui/table/observability-data-table.tsx"
declare module '@tanstack/react-table' {
  interface ColumnMeta<TData extends RowData, TValue> {
    headerClassName?: string
    cellClassName?: string
  }
}

export function ObservabilityDataTable<TData>({
  data,

  getRowId,
  getRowClassName,
  minTableWidthClass = 'min-w-[560px]',
  isDimmed = false,

  'use no memo'

  const table = useReactTable({
    data,
    columns,
    manualPagination: true,
    manualSorting: true,
    ...(getRowId ? { getRowId } : {}),
    getCoreRowModel: getCoreRowModel(),
  })
  // ...
}
```

## 4. Совместимая с React Compiler архитектура Zustand (`use-ui-store.ts`)

Хелперы вроде `createSelectors` (создающие динамические геттеры `.use.field()` на объекте стора) маскируют вызовы хуков от статического анализа React Compiler и могут приводить к лишним отключениям оптимизации.

Вместо этого `apps/web/src/shared/store/use-ui-store.ts` построен на явных атомарных хуках:
- **Приватный базовый стор:** `useUIStoreBase` не экспортируется наружу — подписаться на весь стор целиком без селектора невозможно на уровне типов.
- **Разделение `UIState` и `UIActions`:** все экшены собраны в единый ссылочно-стабильный объект `actions`, доступный через `useUIActions()`.
- **Явные атомарные хуки:** каждый реактивный срез экспортирует собственный хук `use*` (`useIsGuestPassModalOpen`, `useTechRadarCategoryFilter`, `useTechRadarSearch`, `useSelectedAdrItem`, `useExpandedKbFolders`, `usePalette`, `useHasHydratedPalette`), плюс минимальный императивный хендл `uiStore` (`getState` / `subscribe`) для не-React контекстов и тестов:

```typescript title="apps/web/src/shared/store/use-ui-store.ts"
export const useUIActions = () => useUIStoreBase((s) => s.actions)
export const useIsGuestPassModalOpen = () => useUIStoreBase((s) => s.isGuestPassModalOpen)
export const useSelectedAdrItem = () => useUIStoreBase((s) => s.selectedAdrItem)
export const useTechRadarCategoryFilter = () => useUIStoreBase((s) => s.techRadarCategoryFilter)
export const useTechRadarSearch = () => useUIStoreBase((s) => s.techRadarSearch)
```
