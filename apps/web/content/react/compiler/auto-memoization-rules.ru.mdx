## 1. Что делает React Compiler под капотом

До появления компилятора любое изменение локального стейта родителя вызывало каскадный ререндер всего поддерева, если разработчик забыл обернуть хотя бы один коллбэк или объект в `useCallback` / `useMemo`.

**React Compiler** (`babel-plugin-react-compiler`) переводит компонент во внутреннее представление HIR и автоматически мемоизирует каждое реактивное выражение и возвращаемый JSX.

### Чистый код без бойлерплейта мемоизации

```tsx title="Компонент без ручного useMemo"
export function ProjectFilterList({ items, query }: { items: Project[]; query: string }) {
  const visible = items.filter((item) => item.name.toLowerCase().includes(query.toLowerCase()))
  return (
    <ul>
      {visible.map((item) => (
        <ProjectRow key={item.id} item={item} />
      ))}
    </ul>
  )
}
```

На этапе сборки компилятор кэширует и массив `visible`, и дерево `<ul>` независимо друг от друга: если у родителя обновилась соседняя переменная, ни `.filter()`, ни `<ProjectRow />` не выполняются заново.

## 2. Когда всё ещё нужны ручные `useMemo` и `useCallback`?

| Сценарий | Нужен ручной хук? | Почему |
| :--- | :---: | :--- |
| Передача функций и объектов в дочерние компоненты | **Нет** | Компилятор стабилизирует ссылки автоматически |
| Сортировка и фильтрация списков внутри рендера | **Нет** | Кэшируется в слоте до изменения входных зависимостей |
| Жесткий контроль перезапуска сложного `useEffect` | **Редко** | Только для тонкой ручной привязки жизненного цикла |
| Кэширование данных между *разными* компонентами | **Да** | Для этого используется `TanStack Query` + `IndexedDB` |

> [!IMPORTANT]
> Никогда не мутируйте пропсы или стейт во время рендера (`items.sort()` вместо `items.toSorted()`). Мутировать можно только локальные массивы и объекты, созданные внутри того же рендера.
