## 1. Архитектура маршрута `/[locale]/knowledge-base/[...slug]`

Конспекты хранятся в файловой системе по шаблону `apps/web/content/<topic>/<subtopic>/<slug>.<locale>.mdx`. Чтобы масштабировать базу знаний на любую глубину вложенности без дублирования `page.tsx`, используется единый catch-all маршрут `app/[locale]/knowledge-base/[...slug]/page.tsx`:

| Глубина `slug` | Пример URL | Что рендерит `page.tsx` |
| :--- | :--- | :--- |
| **1 сегмент (`[topic]`)** | `/ru/knowledge-base/this-project` | **Хаб темы:** вкладки подтем (`TopicSubtopicTabs`), карточки подразделов и список всех статей раздела |
| **2 сегмента (`[topic, subtopic]`)** | `/ru/knowledge-base/this-project/knowledge-engine` | **Хаб подтемы:** активная вкладка подтемы и отфильтрованные карточки конспектов этой папки |
| **3 сегмента (`[...path, article]`)** | `/ru/knowledge-base/this-project/knowledge-engine/server-mdx-ast-dual-theme-shiki` | **Страница статьи:** `TL;DR`, рендер `MdxArticleRenderer`, правый `TOC` и навигация `Prev / Next` |

На этапе сборки `generateStaticParams()` перемножает `SUPPORTED_LOCALES` (`en`, `uk`, `ru`) на все пути папок и статей (`getAllStaticKnowledgeSlugArrays()`), предгенерируя 100% маршрутов в `SSG`:

```typescript title="apps/web/src/app/[locale]/knowledge-base/[...slug]/page.tsx"
export function generateStaticParams() {
  const slugArrays = getAllStaticKnowledgeSlugArrays()
  return SUPPORTED_LOCALES.flatMap((locale) =>
    slugArrays.map((slug) => ({
      locale,
      slug,
    })),
  )
}
```

При запросе страницы сервер сначала проверяет, является ли путь конечной статьёй (`getArticleByPathSegments`, который запускает парсинг HAST точечно только для одной запрошенной статьи), а если нет — ищет узел директории (`getFolderByPathSegments`) в облегчённом фронтматтер-дереве `getKnowledgeTree(locale)`. Для типобезопасных переходов между локалями используется `Link` из `@/shared/i18n/navigation`.

## 2. Серверный Zero-Eval HAST-конвейер (`remark-directive` ➔ `remark-rehype` ➔ `toJsxRuntime`)

Парсинг `.mdx`-файлов выполняется исключительно на сервере в модулях `apps/web/src/entities/knowledge-content/lib/mdx-ast-parser.ts` и `mdx-fs-loader.ts`:

1. **`parseFrontmatterOnly` (`gray-matter`)** извлекает YAML-фронтматтер (`title`, `sidebarLabel`, `summary`, `category`, `format`, `tags`, `readingTime`, `order`, `tldr`) с межзапросным кэшированием по `mtimeMs`, поэтому для построения дерева сайдбара и хабов разделов парсинг тела статей вообще не запускается.
2. **`unified().use(remarkParse).use(remarkGfm).use(remarkDirective)`** строит синтаксическое дерево `mdast`, размечает заголовки `h2–h4`, GitHub Alerts и блоки кода, а также преобразует теги `<Widget />` и директивы `::sandbox{name="..."}` / `:::sandbox{name="..."}` в типизированные узлы `div[data-mdx-widget]`, вырезая любой произвольный сырой HTML (`Zero-Eval CSP`).
3. **`unified().use(remarkRehype)`** переводит `mdast` в стандартное дерево `HastRoot`, которое в серверном компоненте напрямую конвертируется в React-элементы через `toJsxRuntime` из `hast-util-to-jsx-runtime`:

```typescript title="apps/web/src/entities/knowledge-content/lib/mdx-ast-parser.ts"
const markdownParser = unified().use(remarkParse).use(remarkGfm).use(remarkDirective)
const mdastToHastProcessor = unified().use(remarkRehype)

export function parseRawMdx(
  raw: string,
  fallbackCategory: KnowledgeCategory,
  leafSlug: string,
  relativeSubSegments: readonly string[],
  locale: SupportedLocale,
  isFallback: boolean,
): MdxArticleDocument {
  const { frontmatter, content } = parseFrontmatterOnly(
    raw,
    fallbackCategory,
    leafSlug,
    relativeSubSegments,
    locale,
    isFallback,
  )

  const mdastRoot = markdownParser.parse(content) as MdastRoot
  const toc: ArticleTocEntry[] = []
  const codeBlocks: MdxCodeBlockMeta[] = []
  const usedHeadingIds = new Map<string, number>()

  transformMdastChildren(mdastRoot.children, usedHeadingIds, toc, codeBlocks, false)
  const hast = mdastToHastProcessor.runSync(mdastRoot) as HastRoot

  return { ...frontmatter, toc, hast, codeBlocks }
}
```

Благодаря стандартному конвейеру `mdast` ➔ `HAST` движок нативно поддерживает:
- Вложенные блоки кода и чеклисты внутри GitHub-style плашек `> [!TIP]`, `> [!IMPORTANT]`, `> [!WARNING]`.
- Вложенное инлайн-форматирование (`**жирный текст с `кодом` внутри ссылки**`) и фигуры изображений `![Подпись](/path.webp)`.
- Декларативное встраивание интерактивных клиентских островов (`::sandbox{name="NestAiMcpDiagram" defaultMode="ai"}` или `<ReactRenderGraphD3 />`) через реестр `MDX_WIDGET_REGISTRY` в `apps/web/src/features/kb-sandboxes/ui/mdx-client-widgets.tsx`.

## 3. Dual-Theme подсветка кода `Shiki v4` (`0 КБ` клиентского JS)

Серверный компонент `MdxArticleRenderer` (`apps/web/src/entities/knowledge-article/ui/mdx-article-renderer.tsx`) подсвечивает все блоки кода статьи параллельно через `Promise.all` и `highlightCodeServer` (`apps/web/src/entities/knowledge-content/lib/shiki-highlighter.ts`) перед вызовом `toJsxRuntime(hast, { Fragment, jsx, jsxs, components })`:

```typescript title="apps/web/src/entities/knowledge-content/lib/shiki-highlighter.ts"
const html = await highlighter.codeToHtml(trimmed, {
  lang: safeLang,
  themes: {
    light: 'github-light-default',
    dark: 'github-dark-default',
  },
  defaultColor: false,
})
```

Опция `defaultColor: false` заставляет `Shiki` записывать в каждый `<span>` только две CSS-переменные (`--shiki-light` и `--shiki-dark`). В `globals.css` переключение темы происходит мгновенно силами браузерного CSS-каскада без перерисовки DOM и с `0 КБ` JavaScript на клиенте:

```css title="packages/ui/src/styles/globals.css"
.shiki span {
  color: var(--shiki-light);
}

.dark .shiki span {
  color: var(--shiki-dark);
}
```
