## 1. Міграція з pnpm 10 на pnpm 12

Починаючи з **pnpm 12**, блок налаштувань у `package.json` (`onlyBuiltDependencies`) більше не читається — усі дозволи на `postinstall`-скрипти живуть виключно у словнику `allowBuilds` усередині `pnpm-workspace.yaml`, інакше спрацьовує захист `ERR_PNPM_IGNORED_BUILDS`.

### Конфігурація allowBuilds у воркспейсі

```yaml title="pnpm-workspace.yaml"
packages:
  - "apps/*"
  - "packages/*"

allowBuilds:
  "@biomejs/biome": true
  "@parcel/watcher": true
  "@prisma/client": true
  "@prisma/engines": true
  "@swc/core": true
  esbuild: true
  lefthook: true
  prisma: true
  sharp: true
```

> [!IMPORTANT]
> Ніколи не додавайте секцію `"pnpm"` у `package.json` у проєктах на **pnpm 12+**. І локальне середовище, і Vercel Corepack читають `allowBuilds` суворо з `pnpm-workspace.yaml`.

## 2. Спільний BuildKit Cache Mount для 3 мікросервісів

Раніше сервіси `web`, `api` та `telemetry-ms` завантажували **100+ МБ** однакових бінарників з нуля при кожній зміні `pnpm-lock.yaml`.

### Прогрів Corepack та монтування кешу

Монтування `/root/.local/share/pnpm/store` як персистентного кешу BuildKit дозволяє перевикористовувати пакети між усіма образами:

```dockerfile title="docker/api.Dockerfile"
RUN corepack enable && corepack prepare pnpm@12.16.1 --activate && pnpm --version
RUN --mount=type=cache,id=pnpm,target=/root/.local/share/pnpm/store \
    pnpm install --frozen-lockfile --ignore-scripts
```

## 3. Заміри продакшен-образів та збереження Prisma Client

Виклик `pnpm prune --prod --ignore-scripts` одразу після `turbo run build` прибирає **Biome**, **Turbo**, **TypeScript** і **Prisma CLI** з фінальних runner-шарів, залишаючи згенерований рантайм `.prisma/client`.

### Порівняльна таблиця До та Після

| Контейнер | До оптимізації | Після (`pnpm prune --prod`) | Час експорту шарів |
| :--- | :---: | :---: | :---: |
| `workfolio-telemetry-ms` | ~215 MB | **64.3 MB** | 1.8 с |
| `workfolio-api` | ~260 MB | **78.2 MB** | 2.4 с |
| `workfolio-web` (standalone) | ~140 MB | **85.6 MB** | 2.1 с |

> [!TIP]
> Оскільки продакшен-образ `api` очищений від `devDependencies`, міграції схеми (`prisma migrate deploy`) виконуються з CI/CD або локального термінала напряму в **Neon.tech**.
