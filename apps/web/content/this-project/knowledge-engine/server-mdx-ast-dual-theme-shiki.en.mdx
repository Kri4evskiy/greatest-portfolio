## 1. `/[locale]/knowledge-base/[...slug]` Catch-All Routing

Articles are organized on disk as `apps/web/content/<topic>/<subtopic>/<slug>.<locale>.mdx`. To support arbitrary hierarchy depth without duplicating route files, a single catch-all route `app/[locale]/knowledge-base/[...slug]/page.tsx` resolves both folders and leaf notes:

| `slug` Depth | Example URL | Rendered View in `page.tsx` |
| :--- | :--- | :--- |
| **1 segment (`[topic]`)** | `/en/knowledge-base/this-project` | **Topic Hub:** `TopicSubtopicTabs`, subfolder cards, and full section article list |
| **2 segments (`[topic, subtopic]`)** | `/en/knowledge-base/this-project/knowledge-engine` | **Subtopic Hub:** active subtopic tab and filtered article cards for that folder |
| **3 segments (`[...path, article]`)** | `/en/knowledge-base/this-project/knowledge-engine/server-mdx-ast-dual-theme-shiki` | **Article Page:** `TL;DR` summary, `MdxArticleRenderer`, sticky `TOC`, and `Prev / Next` links |

At build time, `generateStaticParams()` computes the Cartesian product of `SUPPORTED_LOCALES` (`en`, `uk`, `ru`) and `getAllStaticKnowledgeSlugArrays()`, statically generating every folder hub and article page:

```typescript title="apps/web/src/app/[locale]/knowledge-base/[...slug]/page.tsx"
export function generateStaticParams() {
  const slugArrays = getAllStaticKnowledgeSlugArrays()
  return SUPPORTED_LOCALES.flatMap((locale) =>
    slugArrays.map((slug) => ({
      locale,
      slug,
    })),
  )
}
```

When rendering a request, `page.tsx` checks `getArticleByPathSegments` first and falls back to `getFolderByPathSegments` against the recursive `buildKnowledgeTree(locale)` tree, while locale-aware links use `createNavigation(routing)` from `next-intl/navigation`.

## 2. Server-Side AST Pipeline (`gray-matter` + `unified` + `remark-gfm`)

All `.mdx` parsing executes strictly on the server inside `apps/web/src/lib/mdx-content.ts`:

1. **`gray-matter`** extracts typed YAML frontmatter (`title`, `sidebarLabel`, `summary`, `category`, `format`, `tags`, `readingTime`, `order`, `tldr`).
2. **`unified().use(remarkParse).use(remarkGfm).parse(content)`** constructs a standard `mdast` syntax tree.
3. A recursive AST transformer maps `mdast` nodes into serializable `MdxBlock` containers and `MdxInlineNode` trees:

```typescript title="apps/web/src/lib/mdx-content.ts"
function parseMdxAstBlocks(content: string): {
  blocks: MdxBlock[]
  toc: MdxTocHeading[]
} {
  const tree = unified().use(remarkParse).use(remarkGfm).parse(content)
  const toc: MdxTocHeading[] = []
  const blocks = transformMdastChildren(tree.children, toc, true)
  return { blocks, toc }
}
```

Because transformation is recursive, the engine natively supports:
- Nested code blocks and lists inside GitHub-style `> [!TIP]`, `> [!IMPORTANT]`, and `> [!WARNING]` callouts.
- Arbitrarily nested inline formatting (`**bold text with `inline code` inside links**`) and Markdown images `![Caption](/path.webp)`.
- Embedded interactive client widgets (`<D3ReactRenderGraph />`, `<D3ArchitectureFlow />`, `<NestAiMcpDiagram />`) with parsed JSX props.

## 3. Dual-Theme `Shiki v4` Syntax Highlighting (`0 KB` Client JS)

The Server Component `MdxArticleRenderer` collects all code blocks in an article (including nested callout/list blocks) and highlights them concurrently via `Promise.all` and `Shiki v4` `codeToHtml`:

```typescript title="apps/web/src/components/knowledge/mdx-article-renderer.tsx"
const html = await codeToHtml(code, {
  lang: normalizedLang,
  themes: {
    light: 'github-light-default',
    dark: 'github-dark-default',
  },
  defaultColor: false,
})
```

Setting `defaultColor: false` instructs `Shiki` to output `--shiki-light` and `--shiki-dark` CSS variables on each token `<span>`. Theme switching happens purely via CSS cascade in `globals.css` with zero DOM re-rendering and `0 KB` of browser JavaScript:

```css title="packages/ui/src/styles/globals.css"
.shiki span {
  color: var(--shiki-light);
}

.dark .shiki span {
  color: var(--shiki-dark);
}
```
