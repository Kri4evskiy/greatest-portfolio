## 1. 3-рівнева таксономія під 100+ інженерних шпаргалок

Пласкі списки перестають працювати, щойно база знань переростає 15–20 нотаток. Щоб миттєво знаходити конспекти щодня та наочно демонструвати системне мислення, каталог `apps/web/content/` побудований як рекурсивне мультислаг-дерево за маршрутом `/[locale]/knowledge-base/[...slug]`:

| Рівень ієрархії | Приклад шляху у файловій системі | Відображення в інтерфейсі |
| :--- | :--- | :--- |
| **1. Тема** | `content/react/` | Згорнута за замовчуванням гілка-акордеон у `KnowledgeSidebar` |
| **2. Підтема** | `content/react/compiler/` | Горизонтальні вкладки підтем (`TopicSubtopicTabs`) на хаб-сторінках |
| **3. Стаття** | `auto-memoization-rules.uk.mdx` | Чиста сторінка конспекту з `TL;DR`, правим змістом `TOC` і `Prev / Next` |

> [!TIP]
> Клік по назві Темы або Підтеми в лівому сайдбарі одночасно розгортає гілку та відкриває хаб-огляд розділу, а клік по стрілочці зліва перемикає дерево на місці без переходу зі поточної статті.

## 2. Серверний Shiki (0 КБ JS) та легкий RSC-індекс пошуку Cmd+K

Замість завантаження важких клієнтських бібліотек підсвічування синтаксису наш `MdxArticleRenderer` викликає `Shiki` асинхронно всередині React Server Components (`RSC`) із подвійними CSS-змінними для світлої та темної тем.

Аналогічно, щоб глобальний пошук `Cmd+K` миттєво шукав по назвах, `#тегах` і підзаголовках `h2 / h3` без роздування HTML-гідрації, функція `getKnowledgeSearchIndex` відсікає важке тіло AST на сервері перед передачею пропсів у `CommandPaletteModal`:

```typescript title="apps/web/src/lib/mdx-content.ts"
export function getKnowledgeSearchIndex(locale: SupportedLocale): KnowledgeSearchItem[] {
  return getAllArticlesForLocale(locale).map((article) => ({
    routePath: article.routePath,
    title: article.title,
    sidebarLabel: article.sidebarLabel,
    topicLabel: formatKnowledgeSegmentLabel(article.category, locale),
    subtopicLabel: article.slugSegments[0]
      ? formatKnowledgeSegmentLabel(article.slugSegments[0], locale)
      : '',
    format: article.format,
    tags: article.tags,
    headings: article.toc
      .filter((h) => h.level === 2 || h.level === 3)
      .map(({ id, text }) => ({ id, text })),
  }))
}
```

## 3. Підхід Architecture-First та відкрита дошка компромісів

Замість змішування візуальних експериментів із базовою архітектурою ми послідовно закрили Етапи 1–5 і винесли інтерактивний реєстр **Engineering Backlog, Tech Debt & Trade-offs** (`/#roadmap`) прямо на головну сторінку:

- **Наступний крок (`P1`):** Візуальний редизайн в автентичній естетиці **Notion Workfolio (UI v2)** поверх уже готового та типізованого ядра.
- **Прозорий Tech Debt:** керування `EventSource` на `pagehide/pageshow` для мобільного `bfcache`, а також `CSP / HSTS` і `@nestjs/throttler` перед публічним деплоєм.
- **Усвідомлені компроміси (`Deferred`):** аргументована відмова від БД-адмінки (CMS) та платного векторного RAG-чату на користь миттєвого безкоштовного пошуку `Cmd+K` по версіонованих у Git файлах `.mdx`.
