## 1. Zero Initial HTML & JS Overhead in the Root `layout.tsx`

If the root `apps/web/src/app/[locale]/layout.tsx` serialized a full `searchIndex` array as props—or imported `CommandPaletteModal` and its Radix `Dialog` + `MiniSearch` code eagerly—every visitor would pay for the entire Knowledge Base index in HTML/RSC payloads and modal UI JavaScript on initial page load, even if they never press `Cmd+K`.

We eliminate both costs with a modular split inside `apps/web/src/features/search/`:

- `command-palette-loader.tsx` — tiny global `Cmd+K` / `Ctrl+K` listener mounted in `layout.tsx`.
- `search-index-client.ts` — client fetch, deduplication, Zod validation, and in-memory cache.
- `lib/filter-command-entries.ts` — pure `MiniSearch` engine, `#tag` mode, and Public/Protected grouping (unit-tested in `__tests__/filter-command-entries.test.ts`).
- `ui/command-palette-modal.tsx` & `ui/command-palette-item.tsx` — lazy-loaded Radix `Dialog` shell and result row atoms.

```tsx title="apps/web/src/features/search/command-palette-loader.tsx"
'use client'

import type { SupportedLocale } from '@repo/shared-schemas'
import dynamic from 'next/dynamic'
import { useEffect, useState } from 'react'
import { useIsCommandPaletteOpen, useUIActions } from '@/shared/store/use-ui-store'

const LazyCommandPaletteModal = dynamic(
  () => import('./ui/command-palette-modal').then((m) => m.CommandPaletteModal),
  { ssr: false },
)

export function CommandPaletteLoader({ locale }: { locale: SupportedLocale }) {
  const isOpen = useIsCommandPaletteOpen()
  const { openCommandPalette: openPalette, closeCommandPalette: closePalette } = useUIActions()
  const [hasLoaded, setHasLoaded] = useState(false)

  useEffect(() => {
    const handleKeyDown = (event: KeyboardEvent) => {
      if ((event.metaKey || event.ctrlKey) && event.key.toLowerCase() === 'k') {
        event.preventDefault()
        if (isOpen) closePalette()
        else openPalette('')
      }
    }
    window.addEventListener('keydown', handleKeyDown)
    return () => window.removeEventListener('keydown', handleKeyDown)
  }, [isOpen, openPalette, closePalette])

  useEffect(() => {
    if (isOpen && !hasLoaded) setHasLoaded(true)
  }, [hasLoaded, isOpen])

  if (!isOpen && !hasLoaded) return null
  return <LazyCommandPaletteModal locale={locale} />
}
```

## 2. Static SSG Route Handler (`/search-index/[locale]`) & Shared Zod Contract

In Next.js App Router, HTTP Route Handlers are mapped by folder structure: `apps/web/src/app/search-index/[locale]/route.ts` serves `GET /search-index/en`, `/search-index/uk`, and `/search-index/ru` (explicitly excluded from `next-intl` redirects inside `apps/web/src/proxy.ts` `config.matcher`).

With `export const dynamic = 'force-static'` and `generateStaticParams()`, `next build` pre-renders all three localized JSON payloads at build time—zero runtime disk reads or database queries:

```typescript title="apps/web/src/app/search-index/[locale]/route.ts"
import { DEFAULT_LOCALE, SUPPORTED_LOCALES, SupportedLocaleEnum } from '@repo/shared-schemas'
import { NextResponse } from 'next/server'
import { getAllKnowledgeTags, getKnowledgeSearchIndex } from '@/entities/knowledge-content'

export const dynamic = 'force-static'

export function generateStaticParams() {
  return SUPPORTED_LOCALES.map((locale) => ({ locale }))
}

export async function GET(_request: Request, context: { params: Promise<{ locale: string }> }) {
  const { locale } = await context.params
  const parsed = SupportedLocaleEnum.safeParse(locale)
  const resolvedLocale = parsed.success ? parsed.data : DEFAULT_LOCALE

  return NextResponse.json(
    {
      items: getKnowledgeSearchIndex(resolvedLocale),
      topTags: getAllKnowledgeTags(resolvedLocale),
    },
    {
      headers: {
        'Cache-Control': 'public, max-age=3600, stale-while-revalidate=86400',
      },
    },
  )
}
```

Both the server projection (`mdx-types.ts` re-exporting `KnowledgeSearchItem`) and the browser validator import `KnowledgeSearchPayloadSchema` from `@repo/shared-schemas/src/knowledge.schema.ts`. Sharing a single Zod schema prevents silent structural drift between server JSON and client validation.

## 3. Bounded Module-Scope Cache, Deduplication & Zero-Flash Hydration

In `apps/web/src/features/search/search-index-client.ts`, two module-scope `Map` instances (`resolvedCache` and `inflightCache`) cache fetched indexes across SPA route transitions and deduplicate concurrent requests:

```typescript title="apps/web/src/features/search/search-index-client.ts"
import { type KnowledgeSearchPayload, KnowledgeSearchPayloadSchema, type SupportedLocale } from '@repo/shared-schemas'

const resolvedCache = new Map<SupportedLocale, KnowledgeSearchPayload>()
const inflightCache = new Map<SupportedLocale, Promise<KnowledgeSearchPayload>>()

export function getCachedKnowledgeSearchIndex(locale: SupportedLocale): KnowledgeSearchPayload | null {
  return resolvedCache.get(locale) ?? null
}

export function loadKnowledgeSearchIndex(locale: SupportedLocale): Promise<KnowledgeSearchPayload> {
  const existingResolved = resolvedCache.get(locale)
  if (existingResolved) return Promise.resolve(existingResolved)

  const existingInflight = inflightCache.get(locale)
  if (existingInflight) return existingInflight

  const requestPromise = fetch(`/search-index/${locale}`, {
    method: 'GET',
    credentials: 'same-origin',
  })
    .then(async (res): Promise<KnowledgeSearchPayload> => {
      if (!res.ok) {
        if (process.env.NODE_ENV !== 'production') {
          console.error(`[search-index-client] Failed to load /search-index/${locale}: HTTP ${res.status}`)
        }
        return EMPTY_PAYLOAD
      }

      const rawJson: unknown = await res.json()
      const parsed = KnowledgeSearchPayloadSchema.safeParse(rawJson)
      if (!parsed.success) {
        if (process.env.NODE_ENV !== 'production') {
          console.error(`[search-index-client] Invalid /search-index/${locale} payload:`, parsed.error.issues)
        }
        return EMPTY_PAYLOAD
      }

      resolvedCache.set(locale, parsed.data)
      return parsed.data
    })
    .catch(() => EMPTY_PAYLOAD)
    .finally(() => {
      inflightCache.delete(locale)
    })

  inflightCache.set(locale, requestPromise)
  return requestPromise
}
```

> [!TIP]
> **Why this module-scope cache never leaks memory and never flashes a spinner:**
> - **Bounded footprint:** `inflightCache` deletes its `Promise` in `.finally()` (size `0` at rest), and `resolvedCache` is keyed strictly by `SupportedLocale` (`en | uk | ru` — at most `3` entries, ~45 KB total for the tab lifetime). It runs exclusively in the browser (`'use client'` + `typeof window === 'undefined'` guard in `prefetchKnowledgeSearchIndex`), never sharing state across SSR requests.
> - **Hover/focus prefetch + synchronous read:** Search triggers in both `WorkfolioHeader` and `KnowledgeSidebarPanel` call `prefetchKnowledgeSearchIndex(locale)` on `onMouseEnter` / `onFocus`. When `CommandPaletteModal` mounts, its `useState(() => getCachedKnowledgeSearchIndex(locale))` initializer reads the warm cache **synchronously** on frame 1—avoiding the 1-frame `<Loader2 />` spinner flash and extra re-render that an async `Promise` in `useEffect` would cause.

## 4. `MiniSearch` Fuzzy Engine, Stale-Locale Guard & Hybrid KB Soft-Lock UX

### Pure `MiniSearch` Filtering (`lib/filter-command-entries.ts`)

Instead of coupling substring scoring to React state, search indexing and ranking live in a pure TypeScript module powered by `MiniSearch`:

- **Prefix + Typo-Tolerant Fuzzy Search:** `prefix: true` matches partial words immediately (including English, Ukrainian, and Russian Cyrillic), while `fuzzy: (term) => (term.length >= 4 ? 0.2 : false)` catches typos like `compler -> compiler` without noisy false positives on short tokens (`js`, `ts`, `ui`).
- **Weighted Multi-Field Ranking & `AND -> OR` Fallback:** boosts prioritize `title (4) > sidebarLabel (3.5) > subtopicLabel (3) > tags (2.5) > topicLabel / headings (2) > summary (1.2)`. Multi-word queries try strict `combineWith: 'AND'` first and fall back to `'OR'` only when `AND` yields zero hits.
- **Dedicated `#tag` Mode & Deep-Link Heading Anchors:** queries prefixed with `#` filter tags directly (`#zod`, `#jwt`), and matched `h2/h3` headings attach `matchedHeading` so pressing `Enter` jumps straight to `/knowledge-base/...#section-id`.

### Stale-Locale Protection & Soft-Lock Grouping (`ui/command-palette-modal.tsx`)

1. **Stale-Locale Guard (`{ locale, payload }`):** pairing the loaded payload with its `locale` ensures switching languages (`en -> uk`) discards mismatched state immediately, shows `Loader2` while fetching the new locale, and uses an `active` cleanup flag to drop out-of-order responses.
2. **Hybrid KB Soft-Lock UX (`isPublicKnowledgeBasePath`):**
   - For unauthenticated guests with an empty query, articles split into **Public Notes (`This Project`)** and **Protected Notes • 1-Click Pass** with a horizontal divider and a compact 1-line unlock banner.
   - Protected rows render a `Lock` icon + `1-Click Unlock` badge, the keyboard hints footer switches dynamically from `↵ open` to `↵ unlock & open`, and selecting a locked result opens `GuestPassModal` in place (`openGuestPassModal(baseArticlePath)`) instead of triggering a jarring `307` redirect.

## 5. Architectural Decision (ADR): Why Git MDX + Static Search Instead of a PostgreSQL CMS?

A common Tech Lead question is: *"As the Knowledge Base grows across 3 locales (currently ~90 MDX files = 30 articles × 3 languages), why not move articles, sidebar taxonomy, and search into NestJS + PostgreSQL?"*

### Industry Context: Docs-as-Code

Keeping technical documentation in Git as Markdown/MDX and compiling it to static assets is a proven industry pattern (**Docs-as-Code**) used by large engineering documentation platforms—including **Cloudflare Docs** (`cloudflare/cloudflare-docs`), **Next.js Docs** (`vercel/next.js`), **Tailwind CSS Docs** (`tailwindlabs/tailwindcss.com`), and **Stripe Docs** (via its open-source **Markdoc** framework).

### Trade-Off Matrix

| Dimension | A. Git MDX + SSG (Current Choice) | B. Full PostgreSQL + NestJS CMS | C. Hybrid Evolution Path (Future) |
| :--- | :--- | :--- | :--- |
| **TTFB & SEO** | Instant static HTML/RSC (`0` DB queries per page) | Exposed to DB latency & Neon free-tier cold starts (300–800 ms) without heavy ISR/Redis caching | Instant SSG for public hubs + On-Demand ISR for deep notes |
| **Fault Isolation** | **100% resilient:** KB, sidebar & `Cmd+K` keep working even if API/DB restarts | DB/API outage breaks sidebar & articles unless fallback cache exists | Content stays decoupled; backend enhances search & interactive labs |
| **Authoring & AI Workflow** | Native IDE editing, `git diff`, PR review, direct AI-agent edits; trade-off: requires commit + deploy | Browser editing without redeploy, `draft/published` states; trade-off: loses `git diff` and requires building Admin UI + S3/R2 image upload | Static notes stay versioned in Git; mutable features live in DB |
| **Search Scope & Speed** | Client `MiniSearch`: `< 1 ms` fuzzy/prefix over metadata + `h2/h3` (~4 KB gzip at 30 articles; ~25–30 KB gzip at 300 articles) | PostgreSQL `tsvector` + `pg_trgm`: full-body paragraph search + strict server-side RBAC filtering | Sync MDX body into Postgres FTS at deploy time once index exceeds ~150–200 KB |
| **Interactive Widgets** | Zero-Eval HAST maps `<ReactRenderGraphD3 />` & `::sandbox{}` safely without DB XSS risk | Requires pre-compiling HAST on save + strict sanitization pipeline | Native MDX widgets + DB-backed interactive Lab state |
| **Implementation Cost** | Shipped & battle-tested | High (XL: Prisma schema, Admin CRUD, Shiki runtime cache, S3 media, ISR webhooks) | Incremental (S–M per milestone) |

### Explicit Scale Inflection Points

1. **Today through ~300 articles (~900 MDX files):** Git MDX + static `/search-index/[locale]` + client `MiniSearch` is the optimal sweet spot—fastest TTFB, zero cold-start risk, tiny gzipped index, and effortless Git/AI maintainability.
2. **At ~500–1,000+ MDX files (if `next build` Shiki time becomes noticeable):** keep Git as Source of Truth, but switch protected `[...slug]` routes to **On-Demand ISR** (pre-building only public `this-project` routes at build time).
3. **When full-body paragraph search or strict server-side search RBAC is required:** add a deploy-time sync job pushing MDX text into PostgreSQL (`tsvector` + `pg_trgm`) behind `GET /api/knowledge/search`, reusing the exact same `KnowledgeSearchPayloadSchema` from `@repo/shared-schemas`.
4. **Where NestJS + PostgreSQL delivers maximum value right now:** genuinely mutable runtime domains—article analytics/reactions, live SSE telemetry, user bookmarks/progress, and upcoming interactive **Engineering Lab** playgrounds.
