## 1. Серверна нарізка локалей (`Server Locale Slicing`)

У багатомовних проєктах (`EN / UK / RU`) імпорт типізованих словників (досвід роботи, кейси, Tech Radar) усередині `'use client'` компонента змушує бандлер пакувати тексти одразу трьома мовами в браузерний JS-чанк.

Щоб клієнт отримував лише одну активну локаль, великі секції рендеряться як **Server Components**, обирають потрібну мову через `pickLocalized(field, locale)` на сервері та передають готові рядки в точкові клієнтські острови:

```tsx title="apps/web/src/components/workfolio/workfolio-sections.tsx"
export async function WorkfolioExperienceSection({ locale }: { locale: SupportedLocale }) {
  const t = await getTranslations({ locale, namespace: 'Experience' })
  const featuredRoles = COMMERCIAL_EXPERIENCE.filter((role) => role.featured)
  const earlierRoles = COMMERCIAL_EXPERIENCE.filter((role) => !role.featured)

  return (
    <section id="experience" className="scroll-mt-20 space-y-4">
      {/* Основний список рендериться в статичний HTML на сервері (0 КБ JS) */}
      {featuredRoles.map((role) => (
        <ExperienceCard key={role.id} item={role} locale={locale} projectsLabel={t('projectsLabel')} />
      ))}

      {/* У клієнтський острів передаються лише готові HTML-вузли (ReactNode) */}
      <EarlierRolesDisclosure
        showLabel={t('showEarlierRoles', { count: earlierRoles.length })}
        hideLabel={t('hideEarlierRoles')}
      >
        {earlierRoles.map((role) => (
          <ExperienceCard key={role.id} item={role} locale={locale} projectsLabel={t('projectsLabel')} />
        ))}
      </EarlierRolesDisclosure>
    </section>
  )
}
```

## 2. Клієнтські мікро-острови та сумісність SSE з мобільним `bfcache`

Кожна інтерактивна точка ізольована у власний легковаговий клієнтський компонент:

| Мікро-острів | Призначення | Передавані пропси |
| :--- | :--- | :--- |
| **`HeroActionRow`** | Програмний скрол до `#roadmap` або відкриття модалки `Guest Pass` | Лише локалізовані підписи кнопок |
| **`CaseStudyReadButton`** | Перехід до статті кейса або виклик `openAuthModal(targetHref)` | `targetHref`, `readUnlockedLabel`, `readLockedLabel` |
| **`EarlierRolesDisclosure`** | Акордеон раннього досвіду роботи | Серверний `children: ReactNode` + текстові мітки |
| **`FooterSseStatus`** | Живий індикатор пульсу телеметрії `EventSource` | Рядки статусів (`Online`, `Standby`) |

Щоб відкрите з'єднання `EventSource` у `FooterSseStatus` не блокувало миттєве повернення кнопкою «Назад» (**Back/Forward Cache — `bfcache`**) у мобільних браузерах, компонент закриває потік на події `pagehide` і перепідключає його на `pageshow`:

```typescript title="apps/web/src/components/layout/footer-sse-status.tsx"
window.addEventListener('pagehide', closeStream)
window.addEventListener('pageshow', (event) => {
  if (event.persisted) connectStream()
})
```

## 3. `React 19 Compiler` та гігієна стану (`useState` проти `Zustand`)

В `apps/web/next.config.ts` увімкнено `reactCompiler` (`babel-plugin-react-compiler` у режимі `compilationMode: 'infer'`), який автоматично мемоїзує обчислення та JSX-вузли на етапі збірки без ручних обгорток `useMemo` та `useCallback`.

Для передбачуваної роботи компілятора клієнтський стан розділений за областю життя:
- **Локальний `useState`:** використовується всередині інтерактивних симуляцій `D3.js` (`d3-architecture-flow.tsx`, `d3-react-render-graph.tsx`), щоб перемикання режимів графа не викликало ререндер сусідніх компонентів сторінки.
- **Глобальний `Zustand` (`use-ui-store.ts`):** зберігає лише крос-компонентний стан UI (модалки `Cmd+K` / `Guest Pass` та розгорнуті папки дерева Бази Знань із SSR-безпечною синхронізацією в `sessionStorage`).
