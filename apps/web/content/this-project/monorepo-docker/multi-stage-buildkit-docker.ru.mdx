## 1. Трёхстадийный конвейер сборки (`pruner -> builder -> runner`)

Чтобы в продакшен-контейнеры не попадали исходники, компиляторы и чужие пакеты монорепозитория, каждый Dockerfile в папке `docker/` строит образ в три шага:

1. **`pruner`:** запускает `turbo prune @repo/<app> --docker`, формируя минимальный подграф (`out/json/`, `out/full/`, `out/pnpm-lock.yaml`) только для целевого сервиса.
2. **`builder`:** активирует `pnpm@12.18.0`, ставит зависимости через `--frozen-lockfile --ignore-scripts` с общим кэшем BuildKit, запускает `pnpm turbo run build --filter=@repo/<app>...` и очищает `devDependencies`.
3. **`runner`:** копирует только скомпилированные артефакты (`dist/` или `.next/standalone`) и запускает процесс от непривилегированного пользователя (`USER node` / `USER nextjs`).

## 2. `turbo prune` и общий BuildKit Cache Mount

При сборке нескольких микросервисов из одного монорепозитория `out/json/` стабилизирует Docker-слой зависимостей, а монтирование `/root/.local/share/pnpm/store` через BuildKit `type=cache,id=pnpm` позволяет скачать общие пакеты один раз и переиспользовать их во всех образах:

```dockerfile title="docker/api.Dockerfile"
FROM node:22-alpine AS pruner
RUN apk add --no-cache libc6-compat openssl
ENV DO_NOT_TRACK=1
ENV TURBO_TELEMETRY_DISABLED=1
RUN npm install -g turbo@^2
WORKDIR /app
COPY . .
RUN turbo prune @repo/api --docker

FROM node:22-alpine AS builder
RUN apk add --no-cache libc6-compat openssl
ENV DO_NOT_TRACK=1
ENV TURBO_TELEMETRY_DISABLED=1
RUN corepack enable && corepack prepare pnpm@12.18.0 --activate && pnpm --version
WORKDIR /app

COPY --from=pruner /app/out/json/ .
COPY --from=pruner /app/out/pnpm-lock.yaml ./pnpm-lock.yaml
RUN --mount=type=cache,id=pnpm,target=/root/.local/share/pnpm/store \
    pnpm install --frozen-lockfile --ignore-scripts
```

## 3. Очистка `devDependencies` и сохранение `.prisma/client`

В стадии `builder` команда `pnpm turbo run build --filter=@repo/api...` сначала генерирует Prisma-клиент и компилирует TypeScript. Перед вызовом `pnpm prune --prod --ignore-scripts` сгенерированные артефакты `.prisma` и `@prisma/client` временно сохраняются в `/tmp` и возвращаются обратно после очистки, чтобы бинарный движок Prisma точно остался в финальном образе:

```dockerfile title="docker/api.Dockerfile"
RUN --mount=type=cache,id=pnpm,target=/root/.local/share/pnpm/store \
    pnpm turbo run build --filter=@repo/api... && \
    cp -R /app/node_modules/.pnpm/@prisma+client*/node_modules/.prisma /tmp/.prisma && \
    cp -R /app/node_modules/.pnpm/@prisma+client*/node_modules/@prisma/client /tmp/prisma-client && \
    pnpm prune --prod --ignore-scripts && \
    cp -R /tmp/.prisma /app/node_modules/.pnpm/@prisma+client*/node_modules/ && \
    cp -R /tmp/prisma-client/* /app/node_modules/.pnpm/@prisma+client*/node_modules/@prisma/client/ && \
    rm -rf /tmp/.prisma /tmp/prisma-client
```

### Характеристики финальных продакшен-образов

| Контейнер | Базовый образ | Экспонируемый порт | Пользователь рантайма |
| :--- | :---: | :---: | :---: |
| `workfolio-telemetry-ms` | `node:22-alpine` | `4001` (только внутренняя сеть) | `node` (не-root) |
| `workfolio-api` | `node:22-alpine` | `4000` | `node` (не-root) |
| `workfolio-web` (`standalone`) | `node:22-alpine` | `3000` | `nextjs` (`UID 1001`) |

> [!TIP]
> Так как продакшен-образ `api` не содержит `Prisma CLI`, миграции схемы БД (`prisma migrate deploy`) выполняются отдельным шагом в CI/CD перед переключением трафика.
