## 1. Shared 1-Day Auth Contracts & Fail-Closed Production Secret Resolution

To guarantee that the frontend (`apps/web`) and backend (`apps/api`) never drift on `HttpOnly` cookie names, TTLs, or secret validation rules, core auth primitives live in `@repo/shared-schemas`:

```typescript title="packages/shared-schemas/src/auth.schema.ts"
export const KB_ACCESS_COOKIE_NAME = 'kb_access_token'
export const KB_COOKIE_MAX_AGE_MS = 1000 * 60 * 60 * 24 // 1 day
export const DEFAULT_DEV_JWT_SECRET = 'workfolio-super-secret-jwt-key-2026'

export function resolveJwtSecret(envSecret?: string): string {
  const trimmed = envSecret?.trim()
  return trimmed && trimmed.length > 0 ? trimmed : DEFAULT_DEV_JWT_SECRET
}
```

At the Edge boundary, however, falling back to a known development secret in production would be a critical vulnerability. Therefore, `apps/web/src/shared/config/env.ts` wraps secret resolution in `resolveEdgeJwtSecretStrict()`:

```typescript title="apps/web/src/shared/config/env.ts"
const MIN_PROD_JWT_SECRET_LENGTH = 32

export function resolveEdgeJwtSecretStrict(env: NodeJS.ProcessEnv = process.env): string | null {
  const parsed = WebEnvSchema.safeParse(env)
  const nodeEnv = parsed.success ? parsed.data.NODE_ENV : process.env.NODE_ENV
  const isProduction = nodeEnv === 'production'
  const isDemoMode = (parsed.success ? parsed.data.WORKFOLIO_DEMO_MODE : env.WORKFOLIO_DEMO_MODE) === 'true'
  const rawSecret = (parsed.success ? parsed.data.JWT_SECRET : env.JWT_SECRET)?.trim() ?? ''

  if (isProduction && !isDemoMode) {
    if (rawSecret.length < MIN_PROD_JWT_SECRET_LENGTH || rawSecret === DEFAULT_DEV_JWT_SECRET) {
      return null
    }
    return rawSecret
  }

  return resolveJwtSecret(rawSecret || undefined)
}
```

- **Production (`NODE_ENV=production` without `WORKFOLIO_DEMO_MODE=true`):** strictly **fail-closed** — if `JWT_SECRET` is missing, shorter than `32` characters, or equal to `DEFAULT_DEV_JWT_SECRET`, `resolveEdgeJwtSecretStrict()` returns `null` and every Edge verification immediately rejects (`false`).
- **Development / Test / Local Docker Demo (`WORKFOLIO_DEMO_MODE=true`):** preserves zero-friction local onboarding by delegating to `resolveJwtSecret()`.

## 2. Zero-Dependency `HS256` Verification via Web Crypto API (`crypto.subtle`)

Because Knowledge Base pages are statically pre-rendered (`SSG`), access checks must execute at the Edge before serving cached HTML. Rather than bundling third-party JWT libraries, `apps/web/src/shared/lib/edge-jwt.ts` uses the native **Web Crypto API** with isolate-level `CryptoKey` caching and automatic rejection eviction:

```typescript title="apps/web/src/shared/lib/edge-jwt.ts"
let cachedSecretValue: string | null = null
let cachedHmacKeyPromise: Promise<CryptoKey> | null = null

const ALLOWED_JWT_ROLES = new Set(['USER', 'ADMIN'])

function getHmacKey(secret: string): Promise<CryptoKey> {
  if (cachedSecretValue === secret && cachedHmacKeyPromise) {
    return cachedHmacKeyPromise
  }

  cachedSecretValue = secret
  cachedHmacKeyPromise = crypto.subtle
    .importKey('raw', new TextEncoder().encode(secret), { name: 'HMAC', hash: 'SHA-256' }, false, ['verify'])
    .catch((error: unknown) => {
      // Evict rejected key promise so a transient Web Crypto error never permanently poisons the Edge isolate
      cachedSecretValue = null
      cachedHmacKeyPromise = null
      throw error
    })
  return cachedHmacKeyPromise
}
```

### Exact Verification Pipeline in `verifyEdgeJwtHs256(token)`

`verifyEdgeJwtHs256(token: string | undefined): Promise<boolean>` executes a strict multi-step pipeline in `< 0.2 ms`, validating cheap structural and claim invariants before running cryptographic verification:

1. **Format & Strict Base64URL Decoding:** splits the token into exactly 3 non-empty segments (`header.payload.signature`) and decodes each via `decodeBase64UrlToBytes()` (rejecting invalid Base64URL alphabets or malformed `length % 4 === 1` inputs) into `Uint8Array<ArrayBuffer>`.
2. **Header Algorithm Pinning:** parses header and payload JSON as plain objects (`isPlainObject`) and enforces `headerJson.alg === 'HS256'` (preventing `alg: "none"` or asymmetric algorithm confusion attacks).
3. **Temporal & Identity Claims Validation:**
   - Confirms `typeof payloadJson.exp === 'number'` and `payloadJson.exp * 1000 > nowMs` (respecting the `1d` JWT TTL).
   - If `payloadJson.nbf` is present, enforces `typeof payloadJson.nbf === 'number'` and `payloadJson.nbf * 1000 <= nowMs`.
   - Requires non-empty string `payloadJson.sub` (`sub.trim().length > 0`).
   - Enforces `payloadJson.role` membership in `ALLOWED_JWT_ROLES` (`'USER' | 'ADMIN'`).
4. **Fail-Closed Secret & Constant-Time MAC Check:** calls `resolveEdgeJwtSecretStrict()` (logging an error and returning `false` if `null` in production), retrieves the cached HMAC key via `getHmacKey(secret)`, and runs `crypto.subtle.verify('HMAC', hmacKey, signatureBytes, signingInput)`.

## 3. Hybrid Knowledge Base Boundary & Explicit Asset Matcher in `apps/web/src/proxy.ts`

Access policy lives in `apps/web/src/shared/i18n/app-routes.ts` so Edge Proxy, sitemap generation, `robots.ts`, and client buttons share a single rule set:

```typescript title="apps/web/src/shared/i18n/app-routes.ts"
export const PUBLIC_KB_ROOT_SEGMENTS = ['this-project'] as const

export function isPublicKnowledgeBasePath(pathname: string): boolean {
  const normalized = stripLocalePrefix(pathname).replace(/\/+$/, '') || '/'
  if (normalized === APP_ROUTES.knowledgeBase) {
    return true
  }
  return PUBLIC_KB_ROOT_SEGMENTS.some(
    (segment) =>
      normalized === `${APP_ROUTES.knowledgeBase}/${segment}` ||
      normalized.startsWith(`${APP_ROUTES.knowledgeBase}/${segment}/`),
  )
}

export function isProtectedKnowledgeBasePath(pathname: string): boolean {
  const normalized = stripLocalePrefix(pathname).replace(/\/+$/, '') || '/'
  if (!isRouteActive(normalized, APP_ROUTES.knowledgeBase, true)) {
    return false
  }
  return !isPublicKnowledgeBasePath(normalized)
}
```

- **Public & SEO-indexed:** `/knowledge-base` hub and `/knowledge-base/this-project/**` (transparent architectural blueprint open to crawlers, recruiters, and Team Leads with zero `307` redirects).
- **Protected by Edge JWT:** all other domain study-note categories (e.g., `/knowledge-base/react/**`, `/knowledge-base/backend/**`, `/knowledge-base/others/**`) across all locales (`''`, `/ua`, `/ru`).

With crypto and policy encapsulated, `apps/web/src/proxy.ts` stays minimal and deterministic:

```typescript title="apps/web/src/proxy.ts"
const LOCALE_PREFIX_MATCH_REGEX = /^\/(en|ua|ru)(?=\/|$)/

export async function proxy(request: NextRequest): Promise<NextResponse> {
  const { pathname } = request.nextUrl

  if (isProtectedKnowledgeBasePath(pathname)) {
    const token = request.cookies.get(KB_ACCESS_COOKIE_NAME)?.value
    const isValid = await verifyEdgeJwtHs256(token)

    if (!isValid) {
      const matchedLocale = pathname.match(LOCALE_PREFIX_MATCH_REGEX)?.[1]
      const homePath = matchedLocale && matchedLocale !== routing.defaultLocale ? `/${matchedLocale}` : '/'
      const redirectUrl = new URL(homePath, request.url)
      redirectUrl.searchParams.set('unlock', 'knowledge-base')
      redirectUrl.searchParams.set('redirect', pathname)

      const response = NextResponse.redirect(redirectUrl)
      if (token) {
        response.cookies.delete(KB_ACCESS_COOKIE_NAME)
      }
      return response
    }
  }

  return handleI18nRouting(request)
}

// Explicitly exclude known static asset extensions instead of blanket `.*\..*`
// so future Knowledge Base slugs containing dots (e.g. `next.js-16`) never bypass Edge Auth.
export const config = {
  matcher: [
    '/((?!api|search-index|icon|apple-icon|_next|_vercel|.*opengraph-image.*|.*\\.(?:ico|png|jpg|jpeg|gif|svg|webp|avif|pdf|css|js|mjs|map|woff|woff2|ttf|otf|txt|xml|json|webmanifest)$).*)',
  ],
}
```

> [!IMPORTANT]
> Replacing the naive blanket exclusion `.*\..*` with an **explicit static asset extension allowlist** closes a classic Next.js middleware bypass vector: any Knowledge Base slug containing a dot (such as `next.js-16` or `node.js-streams`) is still routed through `proxy()` and protected by Edge JWT verification.
