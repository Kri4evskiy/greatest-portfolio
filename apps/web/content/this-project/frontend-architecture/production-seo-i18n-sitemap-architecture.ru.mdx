## 1. Трёхуровневая матрица локалей (`Internal Code` vs `URL Prefix` vs `Hreflang / OpenGraph`)

Главная сложность мультиязычного SEO в нашем проекте — то, что код языка внутри системы, публичный префикс в адресной строке браузера и стандартные коды для поисковых роботов Google / мессенджеров (Telegram, LinkedIn, Slack) подчиняются разным спецификациям.

В `apps/web/src/shared/i18n/routing.ts` включён режим `localePrefix: { mode: 'as-needed', prefixes: { uk: '/ua' } }`. Чтобы ни в одной странице не возникало путаницы, модуль `apps/web/src/shared/lib/seo.ts` разделяет эти три представления:

| Язык | Внутренний тип (`SupportedLocale` и суффикс `.mdx`) | Публичный URL-префикс (`as-needed`) | Поисковый стандарт ISO 639-1 (`<html lang>` и `hreflang`) | Стандарт мессенджеров (`og:locale`) |
| :--- | :--- | :--- | :--- | :--- |
| **English (Default)** | `'en'` (`*.en.mdx`) | Без префикса (`/`, `/cv`, `/knowledge-base`) | `en` (+ `x-default`) | `en_US` |
| **Українська** | `'uk'` (`*.uk.mdx`) | `/ua` (`/ua`, `/ua/cv`, `/ua/knowledge-base`) | `uk` | `uk_UA` |
| **Русский** | `'ru'` (`*.ru.mdx`) | `/ru` (`/ru`, `/ru/cv`, `/ru/knowledge-base`) | `ru` | `ru_RU` |

> [!IMPORTANT]
> По спецификации Google Search Central атрибут `hreflang` обязан использовать код языка по стандарту **ISO 639-1** (`uk` для украинского языка, а не код страны `ua`), но сам `href` внутри этого тега должен указывать на реальный публичный маршрут сайта (`https://domain.com/ua/...`). Именно поэтому в `buildLanguageAlternatesMap()` ключ словаря — `uk`, а сгенерированный URL ведёт на префикс `/ua`.

## 2. Единое SEO-ядро и защита от невалидного Origin (`apps/web/src/shared/lib/seo.ts`)

Все SEO-вычисления вынесены в чистые серверные функции без внешних зависимостей:

```typescript title="apps/web/src/shared/lib/seo.ts"
const DEFAULT_SITE_URL = 'http://localhost:3000'

const LOCALE_URL_PREFIX_MAP: Record<SupportedLocale, string> = {
  en: '',
  uk: '/ua',
  ru: '/ru',
}

const OG_LOCALE_MAP: Record<SupportedLocale, string> = {
  en: 'en_US',
  uk: 'uk_UA',
  ru: 'ru_RU',
}

export function resolveSiteUrl(): string {
  const raw = process.env.NEXT_PUBLIC_SITE_URL?.trim()
  if (!raw) return DEFAULT_SITE_URL

  try {
    const parsed = new URL(raw)
    if (parsed.protocol !== 'http:' && parsed.protocol !== 'https:') {
      return DEFAULT_SITE_URL
    }
    return parsed.origin
  } catch {
    return DEFAULT_SITE_URL
  }
}
```

### Почему `resolveSiteUrl()` возвращает `parsed.origin` через `new URL(raw)`?
В `apps/web/src/app/[locale]/layout.tsx` вызывается `metadataBase: new URL(resolveSiteUrl())`. Если в переменной окружения `NEXT_PUBLIC_SITE_URL` на хостинге случайно окажется строка без протокола, с лишним слэшем или путём (например, `example.com/`), прямое создание `new URL()` без `try/catch` уронит сборку `next build`, а некорректный протокол может нарушить целостность `<link rel="canonical">`. Валидация через `parsed.origin` гарантирует чистый `https://domain.com` или безопасный откат на `http://localhost:3000`.

## 3. Как работают `canonical`, `alternates.languages` (`hreflang`) и `openGraph`

Функция `buildPageAlternates(pathname, locale)` вызывается внутри `generateMetadata()` на всех уровнях маршрутизации (`[locale]/layout.tsx`, `[locale]/cv/page.tsx`, `[locale]/knowledge-base/page.tsx` и `[locale]/knowledge-base/[...slug]/page.tsx`):

```typescript title="apps/web/src/shared/lib/seo.ts"
export function buildLanguageAlternatesMap(pathname: string): Record<string, string> {
  return {
    en: buildLocalizedUrl(pathname, 'en'),
    uk: buildLocalizedUrl(pathname, 'uk'),
    ru: buildLocalizedUrl(pathname, 'ru'),
    'x-default': buildLocalizedUrl(pathname, DEFAULT_LOCALE),
  }
}

export function buildPageAlternates(pathname: string, locale: SupportedLocale = DEFAULT_LOCALE) {
  return {
    canonical: buildLocalizedUrl(pathname, locale),
    languages: buildLanguageAlternatesMap(pathname),
  }
}
```

Для страницы `/ru/cv` Next.js 16 автоматически генерирует в `<head>` следующий набор тегов:
1. **`<link rel="canonical" href="https://.../ru/cv" />`** — сообщает поисковику главный адрес текущей локализованной страницы (защита от дублей при наличии query-параметров вроде `?unlock=knowledge-base`).
2. **`<link rel="alternate" hreflang="en" href="https://.../cv" />`** — связывает английскую версию без префикса `/en`.
3. **`<link rel="alternate" hreflang="uk" href="https://.../ua/cv" />`** — связывает украинскую версию по префиксу `/ua`.
4. **`<link rel="alternate" hreflang="ru" href="https://.../ru/cv" />`** — связывает русскую версию.
5. **`<link rel="alternate" hreflang="x-default" href="https://.../cv" />`** — указывает дефолтную (английскую) страницу для пользователей с любыми другими языками браузера.
6. **OpenGraph (`og:title`, `og:description`, `og:url`, `og:locale`, `og:type`)** — формирует локализованную карточку-превью ссылки при отправке в **Telegram, LinkedIn, Slack или Discord** (для статей Базы Знаний дополнительно проставляются `og:type="article"`, `article:published_time` и `article:tag`).

## 4. Статические `robots.ts` и `sitemap.ts` и их взаимодействие с Security / Edge Proxy

Оба файла в `apps/web/src/app/` используют `export const dynamic = 'force-static'`, поэтому они компилируются один раз на этапе `next build` и отдаются как чистая статика:

1. **Прозрачный пропуск через `src/proxy.ts`:**
   В нашем Edge Proxy (`apps/web/src/proxy.ts`) задан фильтр:
   ```typescript
   matcher: ['/((?!api|search-index|_next|_vercel|.*\\..*).*)']
   ```
   Любой URL, содержащий точку (`.*\\..*`), включая `/robots.txt` и `/sitemap.xml`, **обходит Edge-мидлвару напрямую**. Поисковые боты получают XML/TXT мгновенно без запуска Web Crypto JWT и без редиректов локали.
2. **Изоляция служебных эндпоинтов в `robots.ts`:**
   ```typescript title="apps/web/src/app/robots.ts"
   rules: [
     {
       userAgent: '*',
       allow: '/',
       disallow: ['/api/', '/search-index/'],
     },
   ]
   ```
   Мы явно закрываем от поисковых роботов `/api/` (бэкенд-эндпоинты и SSE-поток) и `/search-index/` (сырые JSON-дампы индекса для модалки `Cmd+K`, которые предназначены только для клиентского поиска, а не для выдачи в Google).
3. **Автоматический обход дерева `.mdx` в `sitemap.ts`:**
   Генератор `sitemap.ts` берёт корневые страницы (`/`, `/cv`, `/knowledge-base`), добавляет к ним все статические пути папок и статей через `getAllStaticKnowledgeSlugArrays()` и подтягивает реальную дату публикации `publishedAt` из легковесного кэша фронтматтеров `getAllKnowledgeFrontmatters(DEFAULT_LOCALE)`. Для каждого маршрута создаются 3 записи (`en`, `uk`, `ru`) со встроенной матрицей `alternates.languages`.

## 6. Двухуровневая архитектура границ ошибок и локализованный `404` (`not-found.tsx` + `[...rest]` + `error.tsx`)

В мультиязычном App Router с динамическим корневым сегментом `app/[locale]/*` стандартный корневой `app/not-found.tsx` рендерится **вне** локализованного `LocaleRootLayout` (теряются `WorkfolioHeader`, переключатель темы `Mode × Palette`, поиск `Cmd+K` и активный язык).

Чтобы пользователь при ошибке `404` или сбое рендера оставался внутри привычного интерфейса на выбранном языке, выстроена двухуровневая защита:

1. **Перехват неизвестных маршрутов (`apps/web/src/app/[locale]/[...rest]/page.tsx` ➔ `[locale]/not-found.tsx`):**
   - Любой несуществующий путь внутри локали (например, `/unknown` или `/ru/unknown`) попадает в catch-all сегмент `[...rest]/page.tsx`, который синхронно вызывает `notFound()` из `next/navigation`.
   - Вызов `notFound()` внутри `[locale]` активирует наш локализованный **`apps/web/src/app/[locale]/not-found.tsx`** — чистый **React Server Component (`0 КБ` клиентского JS)** на базе `getTranslations('NotFound')`, который рендерится прямо внутри `<main>` в `LocaleRootLayout`, сохраняя всю навигацию сайта и отдавая корректный HTTP-статус `404` для поисковых роботов.
2. **Два уровня Runtime Error Boundaries (`[locale]/error.tsx` vs `app/global-error.tsx`):**
   - **`apps/web/src/app/[locale]/error.tsx` (`'use client'`):** локализованный предохранитель внутри `LocaleRootLayout` (`useTranslations('ErrorPage')`). Перехватывает 99% ошибок рендера дочерних страниц, сохраняет шапку/футер/тему, логирует исключение в формате Sentry (`Graceful No-Op`, если `NEXT_PUBLIC_SENTRY_DSN` пуст), выводит `error.digest` и даёт кнопку повторной попытки `reset()`.
   - **`apps/web/src/app/global-error.tsx` (`'use client'`):** аварийный корневой предохранитель со своим тегом `<html>` и `<body>` (с автоопределением языка по префиксу `window.location.pathname`), который срабатывает только в том случае, если ошибка произошла в самом корневом `LocaleRootLayout`.
