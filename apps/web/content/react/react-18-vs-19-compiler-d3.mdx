## 1. Эволюция модели рендеринга: от ручного `useMemo` к компилятору

В **React 18** разработчик вынужден вручную оборачивать вычисления в `useMemo`, коллбэки — в `useCallback`, а дочерние компоненты — в `React.memo`. Стоит пропустить одну ссылку на объект или функцию, как изменение локального фильтра вызывает каскадный ререндер всего поддерева (например, сложной таблицы `TanStack Table`).

В **React 19** в сочетании с **Next.js 15 App Router** мы получаем:
- Автоматическое мемоизирование графа зависимостей на этапе компиляции.
- Первоклассную поддержку промисов через хук `use(promise)` внутри границ `<Suspense>`.
- Асинхронные серверные контракты (`await params`, `await searchParams`, `await cookies()`).

## 2. Как мы интегрировали `D3.js` и `Zustand` без лишних ререндеров

Интерактивные SVG-графы на базе `D3.js` часто конфликтуют с виртуальным DOM React, если хранить промежуточные координаты анимации в `useState`. В нашем проекте соблюдаются жесткие правила из `react-next-best-practices`:

```typescript
// Атомарная подписка на Zustand (без деструктуризации всего стора)
const mode = useUIStore((s) => s.reactGraphMode);
const svgRef = useRef<SVGSVGElement | null>(null);
```

1. **Изоляция DOM:** React владеет только корневым `<svg ref={svgRef} />`, а вся математика построения дерева (`d3.tree()`, `d3.linkHorizontal()`) выполняется императивно внутри `useEffect`.
2. **Ленивая загрузка чанков (`next/dynamic`):** Тяжелые модули `D3.js` подгружаются только при открытии статьи Базы Знаний и не попадают в стартовый JS-бандл страницы CV.
