## 1. Детермінований `#hash`-скрол у Next.js App Router

Стандартний роутер Next.js (`<Link href="/#projects">`) пропускає прокрутку, якщо в адресному рядку вже стоїть `#projects`, а користувач прокрутив сторінку вгору колесом миші та клікнув по посиланню повторно.

Щоб навігація по секціях працювала безвідмовно, хук `useSectionNavigation` виконує програмний скрол напряму, коли користувач уже на `/`, і делегує міжсторінковий перехід у `router.push`:

```typescript title="apps/web/src/shared/hooks/use-section-navigation.ts"
const scrollToSection = useCallback(
  (sectionId: WorkfolioSectionId) => {
    if (pathname === '/') {
      const element = document.getElementById(sectionId)
      if (element) {
        element.scrollIntoView({ behavior: 'smooth', block: 'start' })
        window.history.replaceState(null, '', `#${sectionId}`)
        return
      }
    }
    router.push(`/#${sectionId}`)
  },
  [pathname, router],
)
```

У зв’язці з глобальним `scroll-padding-top: 5rem` (та `scroll-mt-20` на секціях) фіксована верхня шапка (`h-14`) ніколи не перекриває заголовок блоку після зупинки плавного скролу.

## 2. `IntersectionObserver` ScrollSpy без Layout Thrashing

Виклик `el.getBoundingClientRect()` на кожен тік прокрутки (навіть усередині `requestAnimationFrame`) змушує браузер регулярно читати геометрію DOM у головному потоці. Тому й головна сторінка CV (`useActiveWorkfolioSection`), і зміст статей Бази Знань (`useActiveHeading`) переведено на браузерний **`IntersectionObserver`**, отримуючи `entry.boundingClientRect.top` асинхронно лише в момент перетину меж.

### Секції головної сторінки та нижній observer для `#roadmap`

`useActiveWorkfolioSection` поєднує основний observer верхньої смуги читання (`rootMargin: '-112px 0px -55% 0px'`, `threshold: 0`) з окремим observer на секції `#roadmap` (`threshold: 0.85`), щоб короткий нижній блок надійно активувався при прокручуванні до кінця сторінки:

```typescript title="apps/web/src/shared/hooks/use-section-navigation.ts"
const sectionObserver = new IntersectionObserver(
  (entries) => {
    for (const entry of entries) {
      const id = entry.target.id as WorkfolioSectionId
      lastTopMap.set(id, entry.boundingClientRect.top)
      if (entry.isIntersecting) {
        visibleSet.add(id)
      } else {
        visibleSet.delete(id)
      }
    }
    resolveActive()
  },
  {
    rootMargin: '-112px 0px -55% 0px',
    threshold: 0,
  },
)

// Гарантує активацію короткої нижньої секції (`roadmap`) при доскролі до кінця сторінки
const roadmapEl = document.getElementById('roadmap')
const bottomObserver = roadmapEl
  ? new IntersectionObserver(
      (entries) => {
        const entry = entries[0]
        if (!entry) return
        isLastSectionFullyVisible = entry.isIntersecting
        resolveActive()
      },
      { threshold: 0.85 },
    )
  : null
```

Якщо в поточний момент жодна секція не перетинає верхню смугу (наприклад, під час читання довгого контенту між межами секцій), `resolveActive()` обирає останню секцію з `lastTopMap`, чия верхня координата пройшла поріг `top <= 160`.

### Зміст статей Бази Знань (`useActiveHeading`)

В `apps/web/src/entities/knowledge-article/ui/article-toc.tsx` компонент `DesktopArticleToc` використовує той самий підхід без layout thrashing, відкалібрований під щільні заголовки статей (`rootMargin: '-88px 0px -65% 0px'`, `threshold: [0, 1]`):

```typescript title="apps/web/src/entities/knowledge-article/ui/article-toc.tsx"
const observer = new IntersectionObserver(
  (entries) => {
    for (const entry of entries) {
      const id = entry.target.id
      lastTopById.set(id, entry.boundingClientRect.top)
      if (entry.isIntersecting) {
        visibleIds.add(id)
      } else {
        visibleIds.delete(id)
      }
    }

    for (const item of items) {
      if (visibleIds.has(item.id)) {
        setActiveId(item.id)
        return
      }
    }

    // Під час читання тексту між двома заголовками утримуємо останній пройдений зверху заголовок
    let current = firstId
    for (const item of items) {
      const top = lastTopById.get(item.id)
      if (top !== undefined && top <= 140) {
        current = item.id
      }
    }
    setActiveId(current)
  },
  {
    rootMargin: '-88px 0px -65% 0px',
    threshold: [0, 1],
  },
)
```

Клік по будь-якому пункту `DesktopArticleToc` чи `MobileArticleToc` викликає `scrollToHeadingId(id)` (`scrollIntoView({ behavior: 'smooth', block: 'start' })` + `window.history.replaceState(null, '', '#' + id)`).

## 3. Ергономіка `PageSectionNavigator` (`< xl` проти `xl+`)

Замість перевантаження верхньої шапки `WorkfolioHeader` списком якірних посилань навігація по секціях винесена в `apps/web/src/widgets/section-nav/page-section-navigator.tsx`:

| Брейкпоінт | Форм-фактор | Інженерна деталь |
| :--- | :--- | :--- |
| **Десктоп (`xl+`)** | Паруюча вертикальна рейка праворуч (`fixed right-4 top-1/2 z-30 -translate-y-1/2 xl:block 2xl:right-6`) | Показує індекси `01`–`05`, активний індикатор (`w-4 bg-primary`), `aria-current="location"`, розкриває підписи по `group-hover/rail` та тримає їх постійно відкритими на надшироких екранах (`min-[1560px]:block`, `min-[1600px]:inline`) |
| **Мобільні та планшети (`< xl`)** | Плаваюча кнопка-пігулка на `@repo/ui` `Popover` у правому нижньому куті (`fixed bottom-4 right-4 z-40 xl:hidden`) | Показує активний індекс і назву; `WorkfolioFooter` задає `pb-20 xl:pb-10`, щоб кнопка в зоні великого пальця не перекривала копірайт і статус SSE |
