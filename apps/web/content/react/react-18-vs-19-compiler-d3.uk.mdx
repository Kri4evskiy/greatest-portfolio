## 1. Еволюція моделі рендерингу: від ручного `useMemo` до компілятора

У **React 18** розробник змушений вручну огортати обчислення в `useMemo`, колбеки — в `useCallback`, а дочірні компоненти — в `React.memo`. Варто пропустити одне посилання на об’єкт або функцію, як зміна локального фільтра викликає каскадний ререндер усього піддерева (наприклад, складної таблиці `TanStack Table`).

У **React 19** у поєднанні з **Next.js 16 App Router** ми отримуємо:
- Автоматичне мемоїзування графа залежностей на етапі компіляції.
- Першокласну підтримку промісів через хук `use(promise)` всередині меж `<Suspense>`.
- Асинхронні серверні контракти (`await params`, `await searchParams`, `await cookies()`).

## 2. Як ми інтегрували `D3.js` та `Zustand` без зайвих ререндерів

Інтерактивні SVG-графи на базі `D3.js` часто конфліктують із віртуальним DOM React, якщо зберігати проміжні координати анімації в `useState`. У нашому проєкті дотримуються суворі правила з `react-next-best-practices`:

```typescript
// Атомарна підписка на Zustand (без деструктуризації всього стору)
const mode = useUIStore((s) => s.reactGraphMode);
const svgRef = useRef<SVGSVGElement | null>(null);
```

1. **Ізоляція DOM:** React володіє лише кореневим `<svg ref={svgRef} />`, а вся математика побудови дерева (`d3.tree()`, `d3.linkHorizontal()`) виконується імперативно всередині `useEffect`.
2. **Ліниве завантаження чанків (`next/dynamic`):** Важкі модулі `D3.js` підвантажуються лише при відкритті статті Бази Знань і не потрапляють у стартовий JS-бандл сторінки CV.
