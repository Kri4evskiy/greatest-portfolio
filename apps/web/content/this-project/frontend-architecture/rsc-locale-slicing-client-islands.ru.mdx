## 1. Серверная нарезка локалей (`Server Locale Slicing`)

В мультиязычных проектах (`EN / UK / RU`) импорт типизированных словарей (опыт работы, кейсы, Tech Radar) внутри `'use client'` компонента заставляет бандлер упаковывать тексты сразу на всех трёх языках в браузерный JS-чанк.

Чтобы клиент получал только одну активную локаль, крупные секции рендерятся как **Server Components**, выбирают нужный язык через `pickLocalized(field, locale)` на сервере и передают готовые строки в точечные клиентские острова:

```tsx title="apps/web/src/entities/workfolio-profile/workfolio-sections.tsx"
export async function WorkfolioExperienceSection({ locale }: { locale: SupportedLocale }) {
  const t = await getTranslations({ locale, namespace: 'Experience' })
  const featuredRoles = COMMERCIAL_EXPERIENCE.filter((role) => role.featured)
  const earlierRoles = COMMERCIAL_EXPERIENCE.filter((role) => !role.featured)

  return (
    <section id="experience" className="scroll-mt-20 space-y-4">
      {/* Основной список рендерится в статический HTML на сервере (0 КБ JS) */}
      {featuredRoles.map((role) => (
        <ExperienceCard key={role.id} item={role} locale={locale} projectsLabel={t('projectsLabel')} />
      ))}

      {/* В клиентский остров передаются только готовые HTML-узлы (ReactNode) */}
      <EarlierRolesDisclosure
        showLabel={t('showEarlierRoles', { count: earlierRoles.length })}
        hideLabel={t('hideEarlierRoles')}
      >
        {earlierRoles.map((role) => (
          <ExperienceCard key={role.id} item={role} locale={locale} projectsLabel={t('projectsLabel')} />
        ))}
      </EarlierRolesDisclosure>
    </section>
  )
}
```

## 2. Клиентские микро-острова и совместимость SSE с мобильным `bfcache`

Каждая интерактивная точка изолирована в собственный легковесный клиентский компонент:

| Микро-остров | Назначение | Передаваемые пропсы |
| :--- | :--- | :--- |
| **`HeroActionRow`** | Программный скролл к `#roadmap` или открытие модалки `Guest Pass` | Только локализованные подписи кнопок |
| **`CaseStudyReadButton`** | Переход к статье кейса или вызов `openAuthModal(targetHref)` | `targetHref`, `readUnlockedLabel`, `readLockedLabel` |
| **`EarlierRolesDisclosure`** | Аккордеон раннего опыта работы | Серверный `children: ReactNode` + текстовые метки |
| **`FooterSseStatus`** | Живой индикатор пульса телеметрии `EventSource` | Строки статусов (`Online`, `Standby`) |

Чтобы открытое соединение `EventSource` в `FooterSseStatus` не блокировало мгновенный возврат по кнопке «Назад» (**Back/Forward Cache — `bfcache`**) в мобильных браузерах, компонент закрывает поток на событии `pagehide` и переподключает его на `pageshow`:

```typescript title="apps/web/src/features/telemetry-stream/footer-sse-status.tsx"
window.addEventListener('pagehide', closeStream)
window.addEventListener('pageshow', (event) => {
  if (event.persisted) connectStream()
})
```

## 3. `React 19 Compiler` и гигиена состояния (`useState` против `Zustand`)

В `apps/web/next.config.ts` включён `reactCompiler` (`babel-plugin-react-compiler` в режиме `compilationMode: 'infer'`), который автоматически мемоизирует вычисления и JSX-узлы на этапе сборки без ручных обёрток `useMemo` и `useCallback`.

Для предсказуемой работы компилятора клиентское состояние разделено по области жизни:
- **Локальный `useState`:** используется внутри интерактивных симуляций `D3.js` (`d3-architecture-flow.tsx`, `d3-react-render-graph.tsx`), чтобы переключение режимов графа не вызывало ререндер соседних компонентов страницы.
- **Глобальный `Zustand` (`use-ui-store.ts`):** хранит только кросс-компонентное состояние UI (модалки `Cmd+K` / `Guest Pass` и раскрытые папки дерева Базы Знаний с SSR-безопасной синхронизацией в `sessionStorage`).

## 4. Enterprise-слой запросов: `apiClient` (`Axios`), `AbortSignal`, `QueryCache` и типизированные роуты

Пока серверный слой Next.js опирается на нативный `fetch`, клиентское взаимодействие с API (`'use client'` + `TanStack Query v5`) построено поверх проверенного **Axios** с жёсткой `Zod`-валидацией и реестрами маршрутов:

1. **Единые реестры `API_ENDPOINTS` и `APP_ROUTES`:**
   - Контракты API описаны в `@repo/shared-schemas` (`API_ENDPOINTS` + шаблонизатор `resolveEndpoint` для параметризованных маршрутов вроде `/api/knowledge/:slug/view`).
   - Маршруты страниц Next.js, хлебные крошки шапки и `Cmd+K` переходы централизованы в `apps/web/src/shared/i18n/app-routes.ts` (`APP_ROUTES`, `resolveHeaderRouteBadge`, `buildKnowledgeBasePath`).
2. **Типизированный Axios `apiClient` (`apps/web/src/shared/lib/api-client.ts`):**
   - Инкапсулирует настроенный инстанс `axios.create({ withCredentials: true, timeout: 10_000 })` (защита цепочки поставок обеспечена через `allowBuilds` в `pnpm-workspace.yaml` и `pnpm-lock.yaml`).
   - Поддерживает `get`, `post`, `put`, `patch`, `delete`, рантайм-валидацию ответов через `Zod`, обработку `204 No Content` и `onUploadProgress`, извлечение `X-Request-Id` в `ApiClientError`, фильтрацию пустых query-параметров (защита от `cursor=null`), нативный `AbortSignal` и интерцепторы Axios.
3. **3-слойные `queries/*.ts` и защита `QueryCache` в `StrictMode`:**
   - Каждый домен разделён на standalone-фетчеры (`fetchSystemCapabilities(signal?)`), фабрики `queryOptions` / `infiniteQueryOptions` (`({ signal }) => ...`) и тонкие хуки `use*`.
   - Глобальный `QueryCache({ onError })` в `QueryProvider` отсекает штатные `AbortError` / `CancelledError` (включая двойной маунт React 19 `StrictMode` в `dev`) и ожидаемые `4xx` ответы RBAC, передавая только реальные сетевые/5xx сбои в `captureClientException` (строго при `NODE_ENV === 'production'`, без утечек dev-ошибок в Sentry).
