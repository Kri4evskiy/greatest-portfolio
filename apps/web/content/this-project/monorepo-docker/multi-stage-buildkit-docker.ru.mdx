## 1. Трёхстадийный конвейер сборки (`pruner -> builder -> runner`)

Чтобы в продакшен-контейнеры не попадали исходники, компиляторы и чужие пакеты монорепозитория, каждый Dockerfile в папке `docker/` строит образ в три шага:

1. **`pruner`:** запускает `turbo prune @repo/<app> --docker`, формируя минимальный подграф (`out/json/`, `out/full/`, `out/pnpm-lock.yaml`) только для целевого сервиса.
2. **`builder`:** активирует `pnpm@12.21.0`, ставит зависимости через `--frozen-lockfile --ignore-scripts` с общим кэшем BuildKit и запускает `pnpm turbo run build --filter=@repo/<app>...`. Бэкенд-образы (`api`, `telemetry-ms`) затем выполняют `pnpm prune --prod --ignore-scripts`; фронтенд-образ (`web`) выставляет `DOCKER_STANDALONE=true`, чтобы Next.js `output: 'standalone'` сам отследил минимальный набор файлов для `server.js` (без шага `pnpm prune`).
3. **`runner`:** копирует только скомпилированные runtime-артефакты и запускает процесс от непривилегированного пользователя (`USER node` для `api`/`telemetry-ms`, `USER nextjs` UID `1001` для `web`).

## 2. `turbo prune` и общий BuildKit Cache Mount

При сборке нескольких микросервисов из одного монорепозитория `out/json/` стабилизирует Docker-слой зависимостей, а монтирование `/root/.local/share/pnpm/store` через BuildKit `type=cache,id=pnpm` позволяет скачать общие пакеты один раз и переиспользовать их во всех образах:

```dockerfile title="docker/api.Dockerfile"
FROM node:22-alpine AS pruner
RUN apk add --no-cache libc6-compat openssl
ENV DO_NOT_TRACK=1
ENV TURBO_TELEMETRY_DISABLED=1
RUN npm install -g turbo@^2
WORKDIR /app
COPY . .
RUN turbo prune @repo/api --docker

FROM node:22-alpine AS builder
RUN apk add --no-cache libc6-compat openssl
ENV DO_NOT_TRACK=1
ENV TURBO_TELEMETRY_DISABLED=1
RUN corepack enable && corepack prepare pnpm@12.21.0 --activate && pnpm --version
WORKDIR /app

COPY --from=pruner /app/out/json/ .
COPY --from=pruner /app/out/pnpm-lock.yaml ./pnpm-lock.yaml
RUN --mount=type=cache,id=pnpm,target=/root/.local/share/pnpm/store \
    pnpm install --frozen-lockfile --ignore-scripts
```

## 3. Две стратегии оптимизации: `pnpm prune` (Backend) и `output: 'standalone'` (Web)

### Бэкенд (`api` и `telemetry-ms`): `pnpm prune --prod` и Rust-free Prisma 7

В `docker/api.Dockerfile` (и аналогично без `openssl` в `docker/telemetry-ms.Dockerfile`) команда `pnpm turbo run build --filter=@repo/api...` генерирует ESM-клиент Prisma 7 (`prisma-client`) в `apps/api/src/generated/prisma/` и компилирует его через `tsc` в `apps/api/dist/generated/prisma/`. Поскольку Prisma 7 заменила нативный Rust-движок в `.prisma/client` на Wasm-компилятор запросов внутри production-пакета `@prisma/client` (в паре с `@prisma/adapter-pg` и `pg`), очистка `pnpm prune --prod --ignore-scripts` выполняется без `/tmp`-костылей, а стадии `runner` больше не нужен `openssl`:

```dockerfile title="docker/api.Dockerfile"
RUN --mount=type=cache,id=pnpm,target=/root/.local/share/pnpm/store \
    pnpm turbo run build --filter=@repo/api... && \
    pnpm prune --prod --ignore-scripts

# Stage 3: Production non-root runner
FROM node:22-alpine AS runner
WORKDIR /app
ENV NODE_ENV=production
ENV PORT=4000
```

### Фронтенд (`web`): `turbo prune @repo/web --docker` + Next.js `output: 'standalone'`

В `docker/web.Dockerfile` команда `pnpm prune` **не вызывается**. Вместо этого `builder` задаёт `ENV DOCKER_STANDALONE=true` и `ENV API_INTERNAL_URL=http://api:4000` для `pnpm turbo run build --filter=@repo/web...`. Next.js собирает автономный `.next/standalone`, а стадия `runner` забирает только standalone-сервер, статические чанки, `public/` и `apps/web/content/` (для чтения MDX в рантайме):

```dockerfile title="docker/web.Dockerfile"
COPY --from=pruner /app/out/full/ .
COPY tsconfig.base.json ./tsconfig.base.json
ENV DOCKER_STANDALONE=true
ENV API_INTERNAL_URL=http://api:4000
RUN pnpm turbo run build --filter=@repo/web...

# Stage 3: Production non-root runner
FROM node:22-alpine AS runner
...
COPY --from=builder --chown=nextjs:nodejs /app/apps/web/.next/standalone ./
COPY --from=builder --chown=nextjs:nodejs /app/apps/web/.next/static ./apps/web/.next/static
COPY --from=builder --chown=nextjs:nodejs /app/apps/web/public ./apps/web/public
COPY --from=builder --chown=nextjs:nodejs /app/apps/web/content ./apps/web/content

USER nextjs
EXPOSE 3000
CMD ["node", "apps/web/server.js"]
```

| Контейнер | Базовый образ | Способ оптимизации | Экспонируемый порт | Пользователь рантайма |
| :--- | :---: | :--- | :---: | :---: |
| `workfolio-telemetry-ms` | `node:22-alpine` | `turbo prune` + `pnpm prune --prod --ignore-scripts` | `4001` (только внутренняя сеть) | `node` (не-root) |
| `workfolio-api` | `node:22-alpine` | `turbo prune` + `pnpm prune --prod --ignore-scripts` | `4000` | `node` (не-root) |

> Так как продакшен-образ `api` не содержит `Prisma CLI`, миграции схемы БД (`prisma migrate deploy`) выполняются отдельным шагом в CI/CD перед переключением трафика.

## 4. `docker-compose.yml` (Zero-Friction Demo) vs `docker-compose.prod.yml` (Hardened Production)

Оркестрация разделена на два файла, чтобы тимлид или СТО мог поднять весь стек одной командой `docker compose up --build -d` без ручного `.env`, а боевой деплой на VPS оставался жёстко защищённым на уровне ядра контейнеров и секретов:

| Параметр | `docker-compose.yml` (Local Reviewer Demo) | `docker-compose.prod.yml` (Hardened Production) |
| :--- | :--- | :--- |
| **Команда запуска** | `docker compose up --build -d` | `docker compose -f docker-compose.prod.yml --env-file .env.prod up --build -d` |
| **`WORKFOLIO_DEMO_MODE`** | `${WORKFOLIO_DEMO_MODE:-true}` на **обоих сервисах `api` и `web`** (общий fallback на `DEFAULT_DEV_JWT_SECRET` + предупреждение) | Не задан (`"false"` — жёсткий fail-fast в `loadAppConfig`) |
| **Публикация портов хоста** | Только loopback + переопределяемые порты: `127.0.0.1:${POSTGRES_HOST_PORT:-5432}:5432`, `127.0.0.1:${API_HOST_PORT:-4000}:4000`, `127.0.0.1:${WEB_HOST_PORT:-3000}:3000` | `postgres` и `telemetry-ms` **не опубликованы** (только `backend-network`); `api` (`127.0.0.1:4000:4000`) и `web` (`127.0.0.1:3000:3000`) строго на loopback за reverse proxy |
| **Проверка секретов и origin** | `${JWT_SECRET:-}` (авто-резолв через `resolveJwtSecret()` без `.env`) | Обязательная интерполяция `${POSTGRES_PASSWORD:?}`, `${JWT_SECRET:?}` (на `api` и `web`), `${ADMIN_SECRET_PASSCODE:?}`, `${WEB_ORIGIN:?}`, `${NEXT_PUBLIC_SITE_URL:?}` |
| **Доверие reverse proxy** | Прямой localhost (`TRUST_PROXY_HOPS` не задан) | `TRUST_PROXY_HOPS: ${TRUST_PROXY_HOPS:-1}` на `api` для корректного IP клиента в rate limiter за Nginx/Caddy/ALB |
| **Флаг `Secure` у `kb_access_token`** | `false` (`isProduction && !isDemoMode` — работает по `http://localhost:3000`) | `true` (строго поверх HTTPS / TLS) |

### Матрица hardening и healthcheck в `docker-compose.prod.yml`

Каждый продакшен-контейнер работает с ограничениями ядра Linux и явными проверками готовности (`depends_on` ждёт `condition: service_healthy` по цепочке `postgres -> api`, `telemetry-ms -> api`, `api -> web`):

```yaml title="docker-compose.prod.yml (фрагмент)"
  web:
    restart: always
    read_only: true
    tmpfs:
      - /tmp
      - /app/apps/web/.next/cache
    security_opt:
      - no-new-privileges:true
    cap_drop:
      - ALL
    pids_limit: 256
    healthcheck:
      test: ["CMD", "node", "-e", "fetch('http://127.0.0.1:3000/robots.txt').then((r)=>process.exit(r.ok?0:1)).catch(()=>process.exit(1))"]
```

| Сервис | Директивы hardening ядра | Read-Only ФС + `tmpfs` | Healthcheck-проба |
| :--- | :--- | :--- | :--- |
| **`postgres`** | `no-new-privileges:true`, `pids_limit: 256` | Данные в volume `postgres_prod_data` | `pg_isready -U ${POSTGRES_USER:-postgres} -d ${POSTGRES_DB:-workfolio_db}` |
| **`telemetry-ms`** | `no-new-privileges:true`, `cap_drop: [ALL]`, `pids_limit: 256` | `read_only: true`, `tmpfs: [/tmp]` | Node `node:net` TCP-подключение к `127.0.0.1:4001` |
| **`api`** | `no-new-privileges:true`, `cap_drop: [ALL]`, `pids_limit: 256` | `read_only: true`, `tmpfs: [/tmp]` | `wget -qO- http://127.0.0.1:4000/api/health \|\| exit 1` |
| **`web`** | `no-new-privileges:true`, `cap_drop: [ALL]`, `pids_limit: 256` | `read_only: true`, `tmpfs: [/tmp, /app/apps/web/.next/cache]` | Node `fetch('http://127.0.0.1:3000/robots.txt')` |
