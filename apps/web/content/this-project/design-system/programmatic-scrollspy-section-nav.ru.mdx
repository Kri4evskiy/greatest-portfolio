## 1. Детерминированный `#hash`-скролл в Next.js App Router

Стандартный роутер Next.js (`<Link href="/#projects">`) пропускает прокрутку, если в адресной строке уже стоит `#projects`, а пользователь прокрутил страницу вверх колесом мыши и кликнул по ссылке повторно.

Чтобы навигация по секциям работала безотказно, хук `useSectionNavigation` выполняет программный скролл напрямую, когда пользователь уже на `/`, и делегирует межстраничный переход в `router.push`:

```typescript title="apps/web/src/shared/hooks/use-section-navigation.ts"
const scrollToSection = useCallback(
  (sectionId: WorkfolioSectionId) => {
    if (pathname === '/') {
      const element = document.getElementById(sectionId)
      if (element) {
        element.scrollIntoView({ behavior: 'smooth', block: 'start' })
        window.history.replaceState(null, '', `#${sectionId}`)
        return
      }
    }
    router.push(`/#${sectionId}`)
  },
  [pathname, router],
)
```

В связке с глобальным `scroll-padding-top: 5rem` (и `scroll-mt-20` на секциях) фиксированная верхняя шапка (`h-14`) никогда не перекрывает заголовок блока после остановки плавного скролла.

## 2. `IntersectionObserver` ScrollSpy без Layout Thrashing

Вызов `el.getBoundingClientRect()` на каждый тик прокрутки (даже внутри `requestAnimationFrame`) вынуждает браузер регулярно читать геометрию DOM в основном потоке. Поэтому и главная страница CV (`useActiveWorkfolioSection`), и оглавление статей Базы Знаний (`useActiveHeading`) переведены на браузерный **`IntersectionObserver`**, получая `entry.boundingClientRect.top` асинхронно только в момент пересечения границ.

### Секции главной страницы и нижний observer для `#roadmap`

`useActiveWorkfolioSection` комбинирует основной observer верхней полосы чтения (`rootMargin: '-112px 0px -55% 0px'`, `threshold: 0`) с отдельным observer на секции `#roadmap` (`threshold: 0.85`), чтобы короткий нижний блок надёжно активировался при прокрутке до конца страницы:

```typescript title="apps/web/src/shared/hooks/use-section-navigation.ts"
const sectionObserver = new IntersectionObserver(
  (entries) => {
    for (const entry of entries) {
      const id = entry.target.id as WorkfolioSectionId
      lastTopMap.set(id, entry.boundingClientRect.top)
      if (entry.isIntersecting) {
        visibleSet.add(id)
      } else {
        visibleSet.delete(id)
      }
    }
    resolveActive()
  },
  {
    rootMargin: '-112px 0px -55% 0px',
    threshold: 0,
  },
)

// Гарантирует активацию короткой нижней секции (`roadmap`) при доскролле до конца страницы
const roadmapEl = document.getElementById('roadmap')
const bottomObserver = roadmapEl
  ? new IntersectionObserver(
      (entries) => {
        const entry = entries[0]
        if (!entry) return
        isLastSectionFullyVisible = entry.isIntersecting
        resolveActive()
      },
      { threshold: 0.85 },
    )
  : null
```

Если в текущий момент ни одна секция не пересекает верхнюю полосу (например, при чтении длинного контента между границами секций), `resolveActive()` выбирает последнюю секцию из `lastTopMap`, чья верхняя координата прошла порог `top <= 160`.

### Оглавление статей Базы Знаний (`useActiveHeading`)

В `apps/web/src/entities/knowledge-article/ui/article-toc.tsx` компонент `DesktopArticleToc` использует тот же подход без layout thrashing, откалиброванный под плотные заголовки статей (`rootMargin: '-88px 0px -65% 0px'`, `threshold: [0, 1]`):

```typescript title="apps/web/src/entities/knowledge-article/ui/article-toc.tsx"
const observer = new IntersectionObserver(
  (entries) => {
    for (const entry of entries) {
      const id = entry.target.id
      lastTopById.set(id, entry.boundingClientRect.top)
      if (entry.isIntersecting) {
        visibleIds.add(id)
      } else {
        visibleIds.delete(id)
      }
    }

    for (const item of items) {
      if (visibleIds.has(item.id)) {
        setActiveId(item.id)
        return
      }
    }

    // При чтении текста между двумя заголовками удерживаем последний пройденный сверху заголовок
    let current = firstId
    for (const item of items) {
      const top = lastTopById.get(item.id)
      if (top !== undefined && top <= 140) {
        current = item.id
      }
    }
    setActiveId(current)
  },
  {
    rootMargin: '-88px 0px -65% 0px',
    threshold: [0, 1],
  },
)
```

Клик по любому пункту `DesktopArticleToc` или `MobileArticleToc` вызывает `scrollToHeadingId(id)` (`scrollIntoView({ behavior: 'smooth', block: 'start' })` + `window.history.replaceState(null, '', '#' + id)`).

## 3. Эргономика `PageSectionNavigator` (`< xl` против `xl+`)

Вместо перегрузки верхней шапки `WorkfolioHeader` списком якорных ссылок навигация по секциям вынесена в `apps/web/src/widgets/section-nav/page-section-navigator.tsx`:

| Брейкпоинт | Форм-фактор | Инженерная деталь |
| :--- | :--- | :--- |
| **Десктоп (`xl+`)** | Парящий вертикальный рельс справа (`fixed right-4 top-1/2 z-30 -translate-y-1/2 xl:block 2xl:right-6`) | Показывает индексы `01`–`05`, активный индикатор (`w-4 bg-primary`), `aria-current="location"`, раскрывает подписи по `group-hover/rail` и держит их постоянно открытыми на сверхшироких экранах (`min-[1560px]:block`, `min-[1600px]:inline`) |
| **Мобильные и планшеты (`< xl`)** | Плавающая кнопка-таблетка на `@repo/ui` `Popover` в правом нижнем углу (`fixed bottom-4 right-4 z-40 xl:hidden`) | Показывает активный индекс и название; `WorkfolioFooter` задаёт `pb-20 xl:pb-10`, чтобы кнопка в зоне большого пальца не перекрывала копирайт и статус SSE |
