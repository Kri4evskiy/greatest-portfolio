## 1. Two-Dimensional Semantic Token Matrix (`Light/Dark` × `Palette`)

Instead of coupling components to raw Tailwind palette classes (`slate-*`, `emerald-*`, `amber-*`), the entire color system is defined as semantic HSL CSS variables (supporting alpha modifiers such as `hsl(var(--primary) / 0.15)`):

- **Surface Hierarchy:** `--background`, `--surface-subtle`, `--surface-elevated`, `--card`, `--popover`.
- **Semantic Statuses:** `--success`, `--warning`, `--info`, `--destructive` (paired with `*-foreground`).
- **Visualization & Code:** `--chart-1..4` for SVG/D3 diagrams and `--code-bg`, `--code-header`, `--code-border` for code blocks.

```css title="packages/ui/src/styles/globals.css"
:root {
  --background: 40 33% 98%;
  --surface-subtle: 38 26% 95%;
  --surface-elevated: 0 0% 100%;
  --primary: 24 9.8% 10%;
  --success: 152 69% 31%;
  --warning: 38 92% 42%;
  --info: 217 91% 52%;
}

:root.dark,
.dark {
  --background: 24 10% 8%;
  --surface-subtle: 24 9% 11%;
  --surface-elevated: 24 9% 14%;
  --primary: 36 25% 94%;
  --success: 152 60% 52%;
}

:root[data-palette="graphite"] {
  --background: 220 20% 98%;
  --surface-subtle: 220 16% 95%;
  --info: 221 83% 53%;
}
```

> [!TIP]
> Separating `.dark` from `data-palette` makes adding a new theme or `multi-tenant / white-label` brand a pure ~20-variable CSS override with zero changes to React components.

## 2. Dependency Inversion via `Tailwind Preset`

To keep `@repo/ui` self-contained and agnostic of `apps/web`, the UI package exports its own `tailwind.config.ts` as a **Tailwind Preset**:

```typescript title="apps/web/tailwind.config.ts"
import uiPreset from '@repo/ui/tailwind.config'
import type { Config } from 'tailwindcss'

const config: Config = {
  presets: [uiPreset],
  content: [
    './src/**/*.{ts,tsx,mdx}',
    '../../packages/ui/src/**/*.{ts,tsx}',
  ],
}

export default config
```

This architecture provides three advantages:
1. A single source of truth mapping CSS variables to utility classes (`bg-surface-subtle`, `text-warning`, `border-code-border`) across both `apps/web` and `Storybook 10`.
2. Zero upward `../../apps/*` imports inside the shared design system package.
3. Instant onboarding for any new frontend app in the monorepo via `presets: [uiPreset]`.

## 3. Responsive Data Views (`< md` Cards vs `>= md` Tables)

For information-dense components, rather than squeezing wide tables onto `360px` screens, the UI switches representation patterns by breakpoint:

| Component | Smartphones (`< md`) | Tablets & Desktop (`>= md`) |
| :--- | :--- | :--- |
| **`TechRadarTable`** | Stacked card list (`md:hidden`) with direct `ADR` action buttons | Full 6-column `TanStack Table` (`hidden md:block`) with sorting and filtering |
| **`D3.js` / `SVG` Graphs** | Horizontal scroll container `overflow-x-auto` with `min-w-[540px]` | Full-width interactive vector simulation |
| **`Storybook 10` (`@repo/ui`)** | Viewport presets for `360px` and `768px` contrast verification | Live toolbar switcher for `Warm Paper / Dark / Graphite / Sepia` |
