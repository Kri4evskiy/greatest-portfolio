## 1. Двумерная матрица семантических токенов (`Light/Dark` × `Palette`)

Вместо привязки компонентов к конкретным палитрам Tailwind (`slate-*`, `emerald-*`, `amber-*`) вся цветовая система вынесена в семантические CSS-переменные в формате `H S% L%` (совместимом как с нативным `color-mix()` для модификаторов прозрачности в Tailwind v4, так и с SVG-атрибутами `hsl(var(--chart-1))`):

- **Иерархия поверхностей:** `--background`, `--surface-subtle`, `--surface-elevated`, `--card`, `--popover`.
- **Семантические статусы:** `--success`, `--warning`, `--info`, `--destructive` (с парными `*-foreground`).
- **Визуализация и код:** `--chart-1..4` для SVG/D3-диаграмм и `--code-bg`, `--code-header`, `--code-border` для блоков кода.

```css title="packages/ui/src/styles/theme.css"
@custom-variant dark (&:where(.dark, .dark *));

:root {
  --background: 40 20% 99%;
  --surface-subtle: 40 16% 96.5%;
  --surface-elevated: 0 0% 100%;
  --primary: 24 10% 12%;
  --success: 158 64% 32%;
  --warning: 32 92% 38%;
  --info: 214 84% 44%;
}

:root.dark,
.dark {
  --background: 24 10% 8%;
  --surface-subtle: 24 9% 10%;
  --surface-elevated: 24 9% 13%;
  --primary: 40 15% 95%;
  --success: 156 68% 54%;
}

@theme inline {
  --color-background: hsl(var(--background));
  --color-surface-subtle: hsl(var(--surface-subtle));
  --color-primary: hsl(var(--primary));
  --color-success: hsl(var(--success));
  --radius-sm: calc(var(--radius) - 4px);
  --radius-md: calc(var(--radius) - 2px);
  --radius-lg: var(--radius);
}
```

> [!TIP]
> Разделение осей `.dark` и `data-palette` в связке с `@theme inline` позволяет подключить любую новую тему или брендинг клиента (`multi-tenant / white-label`) переопределением ~20 переменных в CSS без единой правки в React-компонентах.

## 2. CSS-first инверсия зависимостей (`@repo/ui/theme.css` + `@source`)

Чтобы пакет `@repo/ui` оставался полностью независимым и не знал о файловой структуре `apps/web`, он экспортирует чистый слой токенов и базовых стилей `@repo/ui/theme.css` (без `@import "tailwindcss";`), а витрина Storybook в `packages/ui/src/styles/globals.css` собирается нативным плагином `@tailwindcss/vite`.

В `apps/web` подключается `@tailwindcss/postcss`, а входной CSS-файл явно указывает границы сканирования `@source`:

```css title="apps/web/src/app/globals.css"
@import "tailwindcss";
@import "@repo/ui/theme.css";

@source "../";
@source "../../content";
@source "../../../../packages/ui/src";
```

Оба пакета (`apps/web/package.json` и `packages/ui/package.json`) фиксируют современные таргеты `"browserslist": ["Chrome >= 111", "Edge >= 111", "Firefox >= 128", "Safari >= 16.4"]`, запрещая `Lightning CSS` и `Next.js SWC` генерировать лишние полифилы под `@property` и `color-mix()`.

Такая схема даёт три архитектурных преимущества:
1. Единый CSS-first источник маппинга переменных в классы Tailwind (`bg-surface-subtle`, `text-warning`, `border-code-border`) как для `apps/web`, так и для изолированного `Storybook 10`.
2. Отсутствие обратных путей `../../apps/*` внутри пакета дизайн-системы.
3. Возможность подключить второй фронтенд-сервис к той же дизайн-системе двумя строками: `@import "@repo/ui/theme.css";` и `@source`.

## 3. Адаптивные представления плотных данных (`< md` против `>= md`)

В компонентах с высокой плотностью информации вместо горизонтального сжимания таблиц на узких экранах (`360px`) применяется смена паттерна отображения:

| Компонент | Смартфоны (`< md`) | Планшеты и десктоп (`>= md`) |
| :--- | :--- | :--- |
| **`TechRadarTable`** | Стек карток (`md:hidden`) с быстрым переходом к `ADR` | 6-колоночная таблица `TanStack Table` (`hidden md:block`) с сортировкой и фильтрами |
| **`D3.js` / `SVG` графы** | Горизонтальный скролл-контейнер `overflow-x-auto` с `min-w-[540px]` | Полная интерактивная векторная сцена на всю ширину колонки |
| **`Storybook 10` (`@repo/ui`)** | Проверка контраста и переносов во вьюпортах `360px` и `768px` | Интерактивное переключение тем `Warm Paper / Dark / Graphite / Sepia` в тулбаре |
