## 1. `reactCompiler` & Bundle Optimization in `apps/web/next.config.ts`

In Next.js 16, `reactCompiler` accepts a typed `ReactCompilerOptions` object alongside package-level barrel tree-shaking:

```typescript title="apps/web/next.config.ts"
const nextConfig: NextConfig = {
  ...(process.env.DOCKER_STANDALONE === 'true' ? { output: 'standalone' } : {}),
  ...(process.env.NEXT_DIST_DIR ? { distDir: process.env.NEXT_DIST_DIR } : {}),
  poweredByHeader: false,
  reactStrictMode: true,
  reactCompiler: {
    compilationMode: 'infer',
    panicThreshold: 'none',
  },
  transpilePackages: ['@repo/ui', '@repo/shared-schemas'],
  experimental: {
    optimizePackageImports: ['lucide-react', 'd3', '@repo/ui', '@repo/shared-schemas'],
  },
}
```

### Why These Options Were Chosen

| Option | Value | Engineering Rationale |
| :--- | :---: | :--- |
| **`compilationMode`** | `'infer'` | Next.js runs its own Rust/SWC heuristics before invoking `babel-plugin-react-compiler`, compiling only files that define PascalCase JSX components or `use*` hooks and skipping pure server/utility modules (`mdx-ast-parser.ts`, `edge-jwt.ts`) |
| **`panicThreshold`** | `'none'` | Guarantees resilient CI/CD builds: if the compiler encounters a third-party hook with interior mutability, it safely skips optimizing that function instead of failing `next build` |
| **`optimizePackageImports`** | `['lucide-react', 'd3', '@repo/ui', '@repo/shared-schemas']` | Rewrites barrel imports into direct submodule paths at build time so client chunks pull only the icons, D3 primitives, UI components, and schemas actually referenced |

## 2. Built-in `knownIncompatible` Registry & `React Hook Form`

Inside `babel-plugin-react-compiler` (`DefaultModuleTypeProvider`), the compiler maintains a registry of third-party APIs that rely on interior mutability:

1. **`react-hook-form` (`useForm().watch`)**: because `watch()` mutates internal subscriptions without changing its function identity, the compiler flags it as `knownIncompatible`. In `apps/web/src/features/auth/guest-pass-modal.tsx`, we subscribe via **`useWatch({ control, name: 'visitorType' })`**, keeping `GuestPassModal` 100% compatible with automatic memoization.
2. **`@tanstack/react-table` v9 (`useTable`)**: returns a single stable table reference backed by TanStack Store atoms. Calling `table.getRowModel()` directly inside a React Compiler-memoized component can stale-cache rendered rows unless isolated behind `'use no memo'`.

## 3. Extracted `'use no memo'` Table Boundaries (TanStack Table v9)

### A. `TechRadarTable` + Extracted `table/` Submodules
`TechRadarTable` (`apps/web/src/entities/engineering-roadmap/tech-radar-table.tsx`) renders search, category filters, mobile cards (`< md`), the desktop table (`>= md`), and the ADR inspector `Dialog`. To keep the parent component fully compiled and tree-shake unused table features, the TanStack Table v9 layer is split into two focused files under `apps/web/src/entities/engineering-roadmap/table/`:

- **`table/tech-radar-columns.tsx`** — pure `createTechRadarColumns({ labels, onInspectAdr })` factory returning typed `TechRadarColumnDef[]`.
- **`table/tech-radar-data-table.tsx`** — static `tableFeatures({ rowSortingFeature, sortedRowModel: createSortedRowModel(), sortFns })` plus a thin `'use no memo'` wrapper calling `useTable` and `<table.FlexRender />`:

```tsx title="apps/web/src/entities/engineering-roadmap/table/tech-radar-data-table.tsx"
export const techRadarTableFeatures = tableFeatures({
  rowSortingFeature,
  sortedRowModel: createSortedRowModel(),
  sortFns: {
    alphanumeric: sortFn_alphanumeric,
    basic: sortFn_basic,
  },
})

export function DesktopTechRadarDataTable({ data, columns, emptyResultLabel }: DesktopTechRadarDataTableProps) {
  'use no memo'

  const table = useTable({
    features: techRadarTableFeatures,
    data,
    columns,
    initialState: {
      sorting: [{ id: 'adrNumber', desc: false }],
    },
  })

  return (
    <div className="hidden overflow-x-auto rounded-lg border border-border bg-card shadow-xs md:block">
      {/* Renders headers & cells via <table.FlexRender header={header} /> and <table.FlexRender cell={cell} /> */}
    </div>
  )
}
```

In the parent `TechRadarTable`, `filteredData` and `columns` (built via `createTechRadarColumns`) are wrapped in `useMemo` alongside `useCallback` for `handleInspectAdr` so that props crossing the `'use no memo'` boundary into `DesktopTechRadarDataTable` retain stable object identities when unrelated state (such as opening the ADR `Dialog`) updates. Meanwhile, filters, mobile cards, `activeDialogItem`, and the `Dialog` JSX stay auto-memoized by React Compiler.

### B. Reusable `ObservabilityDataTable` with Scoped `metaHelper`
For `/system-status` telemetry and leaderboard views, `apps/web/src/features/telemetry-stream/ui/table/observability-data-table.tsx` provides a generic `'use no memo'` TanStack Table v9 shell that registers **zero** client-side sorting/filtering/pagination bundles (all pagination & sorting is server-driven) and scopes per-column styling metadata directly to the table via v9's `metaHelper<ObservabilityColumnMeta>()` (no global declaration merging needed):

```tsx title="apps/web/src/features/telemetry-stream/ui/table/observability-data-table.tsx"
export interface ObservabilityColumnMeta {
  headerClassName?: string
  cellClassName?: string

export const observabilityTableFeatures = tableFeatures({
  columnMeta: metaHelper<ObservabilityColumnMeta>(),

  const table = useTable({

    data,
    columns,

  })

}
```

## 4. React Compiler-Safe Zustand Architecture (`use-ui-store.ts`)

Helper utilities like `createSelectors` (which attach dynamic `.use.field()` getters onto a store object) obscure hook calls from React Compiler's static analysis and can cause unnecessary bailouts or over-subscriptions.

Instead, `apps/web/src/shared/store/use-ui-store.ts` follows a strict atomic-hook architecture:
- **Private Base Store:** `useUIStoreBase` is never exported directly, making accidental whole-store subscriptions (`const state = useUIStore()`) impossible at compile time.
- **Separated `UIState` & `UIActions`:** every mutator lives inside a single referentially stable `actions` object returned by `useUIActions()`.
- **Explicit Atomic Hooks:** each reactive slice exposes a dedicated `use*` hook (`useIsGuestPassModalOpen`, `useTechRadarCategoryFilter`, `useTechRadarSearch`, `useSelectedAdrItem`, `useExpandedKbFolders`, `usePalette`, `useHasHydratedPalette`), plus a minimal imperative `uiStore` (`getState` / `subscribe`) for non-React bridges and tests:

```typescript title="apps/web/src/shared/store/use-ui-store.ts"
export const useUIActions = () => useUIStoreBase((s) => s.actions)
export const useIsGuestPassModalOpen = () => useUIStoreBase((s) => s.isGuestPassModalOpen)
export const useSelectedAdrItem = () => useUIStoreBase((s) => s.selectedAdrItem)
export const useTechRadarCategoryFilter = () => useUIStoreBase((s) => s.techRadarCategoryFilter)
export const useTechRadarSearch = () => useUIStoreBase((s) => s.techRadarSearch)
```
