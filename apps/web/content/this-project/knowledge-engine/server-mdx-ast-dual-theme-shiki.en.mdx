## 1. `/[locale]/knowledge-base/[...slug]` Catch-All Routing

Articles are organized on disk as `apps/web/content/<topic>/<subtopic>/<slug>.<locale>.mdx`. To support arbitrary hierarchy depth without duplicating route files, a single catch-all route `app/[locale]/knowledge-base/[...slug]/page.tsx` resolves both folders and leaf notes:

| `slug` Depth | Example URL | Rendered View in `page.tsx` |
| :--- | :--- | :--- |
| **1 segment (`[topic]`)** | `/en/knowledge-base/this-project` | **Topic Hub:** `TopicSubtopicTabs`, subfolder cards, and full section article list |
| **2 segments (`[topic, subtopic]`)** | `/en/knowledge-base/this-project/knowledge-engine` | **Subtopic Hub:** active subtopic tab and filtered article cards for that folder |
| **3 segments (`[...path, article]`)** | `/en/knowledge-base/this-project/knowledge-engine/server-mdx-ast-dual-theme-shiki` | **Article Page:** `TL;DR` summary, `MdxArticleRenderer`, sticky `TOC`, and `Prev / Next` links |

At build time, `generateStaticParams()` computes the Cartesian product of `SUPPORTED_LOCALES` (`en`, `uk`, `ru`) and `getAllStaticKnowledgeSlugArrays()`, statically generating every folder hub and article page:

```typescript title="apps/web/src/app/[locale]/knowledge-base/[...slug]/page.tsx"
export function generateStaticParams() {
  const slugArrays = getAllStaticKnowledgeSlugArrays()
  return SUPPORTED_LOCALES.flatMap((locale) =>
    slugArrays.map((slug) => ({
      locale,
      slug,
    })),
  )
}
```

When rendering a request, `page.tsx` resolves `getArticleByPathSegments` (which parses HAST on-demand only for the requested article) or falls back to `getFolderByPathSegments` against the lightweight `getKnowledgeTree(locale)` frontmatter tree, while locale-aware links use `Link` from `@/shared/i18n/navigation`.

## 2. Zero-Eval HAST Pipeline (`remark-directive` ➔ `remark-rehype` ➔ `toJsxRuntime`)

All `.mdx` parsing executes strictly on the server inside `apps/web/src/entities/knowledge-content/lib/mdx-ast-parser.ts` and `mdx-fs-loader.ts`:

1. **`parseFrontmatterOnly` (`gray-matter`)** extracts typed YAML frontmatter (`title`, `sidebarLabel`, `summary`, `category`, `format`, `tags`, `readingTime`, `order`, `tldr`) with cross-request `mtimeMs` caching so sidebar trees and hub pages never parse Markdown bodies.
2. **`unified().use(remarkParse).use(remarkGfm).use(remarkDirective)`** constructs an `mdast` syntax tree, decorates `h2–h4` headings, GitHub-style callouts, and code blocks, and converts both `<Widget />` tags and `::sandbox{name="..."}` / `:::sandbox{name="..."}` directives into typed `div[data-mdx-widget]` nodes while stripping arbitrary raw HTML (Zero-Eval CSP).
3. **`unified().use(remarkRehype)`** converts `mdast` into a standard `HastRoot` tree, which is rendered directly to React Server Component elements via `toJsxRuntime` from `hast-util-to-jsx-runtime`:

```typescript title="apps/web/src/entities/knowledge-content/lib/mdx-ast-parser.ts"
const markdownParser = unified().use(remarkParse).use(remarkGfm).use(remarkDirective)
const mdastToHastProcessor = unified().use(remarkRehype)

export function parseRawMdx(
  raw: string,
  fallbackCategory: KnowledgeCategory,
  leafSlug: string,
  relativeSubSegments: readonly string[],
  locale: SupportedLocale,
  isFallback: boolean,
): MdxArticleDocument {
  const { frontmatter, content } = parseFrontmatterOnly(
    raw,
    fallbackCategory,
    leafSlug,
    relativeSubSegments,
    locale,
    isFallback,
  )

  const mdastRoot = markdownParser.parse(content) as MdastRoot
  const toc: ArticleTocEntry[] = []
  const codeBlocks: MdxCodeBlockMeta[] = []
  const usedHeadingIds = new Map<string, number>()

  transformMdastChildren(mdastRoot.children, usedHeadingIds, toc, codeBlocks, false)
  const hast = mdastToHastProcessor.runSync(mdastRoot) as HastRoot

  return { ...frontmatter, toc, hast, codeBlocks }
}
```

Because transformation operates over standard `mdast` ➔ `HAST` trees, the engine natively supports:
- Nested code blocks and task lists inside GitHub-style `> [!TIP]`, `> [!IMPORTANT]`, and `> [!WARNING]` callouts.
- Arbitrarily nested inline formatting (`**bold text with `inline code` inside links**`) and Markdown figures `![Caption](/path.webp)`.
- Declarative interactive client islands (`::sandbox{name="NestAiMcpDiagram" defaultMode="ai"}` or `<ReactRenderGraphD3 />`) mapped via `MDX_WIDGET_REGISTRY` in `apps/web/src/features/kb-sandboxes/ui/mdx-client-widgets.tsx`.

## 3. Dual-Theme `Shiki v4` Syntax Highlighting (`0 KB` Client JS)

The Server Component `MdxArticleRenderer` (`apps/web/src/entities/knowledge-article/ui/mdx-article-renderer.tsx`) highlights all `codeBlocks` in parallel via `Promise.all` and `highlightCodeServer` (`apps/web/src/entities/knowledge-content/lib/shiki-highlighter.ts`) before running `toJsxRuntime(hast, { Fragment, jsx, jsxs, components })`:

```typescript title="apps/web/src/entities/knowledge-content/lib/shiki-highlighter.ts"
const html = await highlighter.codeToHtml(trimmed, {
  lang: safeLang,
  themes: {
    light: 'github-light-default',
    dark: 'github-dark-default',
  },
  defaultColor: false,
})
```

Setting `defaultColor: false` instructs `Shiki` to output `--shiki-light` and `--shiki-dark` CSS variables on each token `<span>`. Theme switching happens purely via CSS cascade in `globals.css` with zero DOM re-rendering and `0 KB` of browser JavaScript:

```css title="packages/ui/src/styles/globals.css"
.shiki span {
  color: var(--shiki-light);
}

.dark .shiki span {
  color: var(--shiki-dark);
}
```
