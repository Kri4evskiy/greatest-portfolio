## 1. Трёхстадийный конвейер сборки (`pruner -> builder -> runner`)

Чтобы в продакшен-контейнеры не попадали исходники, компиляторы и чужие пакеты монорепозитория, каждый Dockerfile в папке `docker/` строит образ в три шага:

1. **`pruner`:** запускает `turbo prune @repo/<app> --docker`, формируя минимальный подграф (`out/json/`, `out/full/`, `out/pnpm-lock.yaml`) только для целевого сервиса.
2. **`builder`:** активирует `pnpm@12.21.0`, ставит зависимости через `--frozen-lockfile --ignore-scripts` с общим кэшем BuildKit, запускает `pnpm turbo run build --filter=@repo/<app>...` и очищает `devDependencies`.
3. **`runner`:** копирует только скомпилированные артефакты (`dist/` или `.next/standalone`) и запускает процесс от непривилегированного пользователя (`USER node` / `USER nextjs`).

## 2. `turbo prune` и общий BuildKit Cache Mount

При сборке нескольких микросервисов из одного монорепозитория `out/json/` стабилизирует Docker-слой зависимостей, а монтирование `/root/.local/share/pnpm/store` через BuildKit `type=cache,id=pnpm` позволяет скачать общие пакеты один раз и переиспользовать их во всех образах:

```dockerfile title="docker/api.Dockerfile"
FROM node:22-alpine AS pruner
RUN apk add --no-cache libc6-compat openssl
ENV DO_NOT_TRACK=1
ENV TURBO_TELEMETRY_DISABLED=1
RUN npm install -g turbo@^2
WORKDIR /app
COPY . .
RUN turbo prune @repo/api --docker

FROM node:22-alpine AS builder
RUN apk add --no-cache libc6-compat openssl
ENV DO_NOT_TRACK=1
ENV TURBO_TELEMETRY_DISABLED=1
RUN corepack enable && corepack prepare pnpm@12.21.0 --activate && pnpm --version
WORKDIR /app

COPY --from=pruner /app/out/json/ .
COPY --from=pruner /app/out/pnpm-lock.yaml ./pnpm-lock.yaml
RUN --mount=type=cache,id=pnpm,target=/root/.local/share/pnpm/store \
    pnpm install --frozen-lockfile --ignore-scripts
```

## 3. Очистка `devDependencies` и Rust-free Prisma 7

В стадии `builder` команда `pnpm turbo run build --filter=@repo/api...` генерирует ESM-клиент Prisma 7 (`prisma-client`) в `apps/api/src/generated/prisma/` и компилирует его через `tsc` прямо в `apps/api/dist/generated/prisma/`. Поскольку Prisma 7 заменила нативный Rust-движок в `.prisma/client` на Wasm-компилятор запросов внутри production-пакета `@prisma/client` (в паре с `@prisma/adapter-pg` и `pg`), очистка `pnpm prune --prod --ignore-scripts` выполняется без временного буфера `/tmp`, а стадии `runner` больше не нужен `openssl`:

```dockerfile title="docker/api.Dockerfile"
RUN --mount=type=cache,id=pnpm,target=/root/.local/share/pnpm/store \
    pnpm turbo run build --filter=@repo/api... && \
    pnpm prune --prod --ignore-scripts

# Stage 3: Production non-root runner
FROM node:22-alpine AS runner
WORKDIR /app
ENV NODE_ENV=production
ENV PORT=4000
```

### Характеристики финальных продакшен-образов

| Контейнер | Базовый образ | Экспонируемый порт | Пользователь рантайма |
| :--- | :---: | :---: | :---: |
| `workfolio-telemetry-ms` | `node:22-alpine` | `4001` (только внутренняя сеть) | `node` (не-root) |
| `workfolio-api` | `node:22-alpine` | `4000` | `node` (не-root) |
| `workfolio-web` (`standalone`) | `node:22-alpine` | `3000` | `nextjs` (`UID 1001`) |

> [!TIP]
> Так как продакшен-образ `api` не содержит `Prisma CLI`, миграции схемы БД (`prisma migrate deploy`) выполняются отдельным шагом в CI/CD перед переключением трафика.

## 4. Разделение `docker-compose.yml` (Zero-Friction Reviewer Demo) и `docker-compose.prod.yml` (Strict Production)

Чтобы тимлид или СТО мог развернуть весь стек одной командой `docker compose up --build` без ручного создания `.env`, но боевой деплой на VPS оставался строго защищённым от дефолтных секретов, оркестрация разделена на два файла:

| Параметр | `docker-compose.yml` (Local Reviewer Demo) | `docker-compose.prod.yml` (Strict Production) |
| :--- | :--- | :--- |
| **Команда запуска** | `docker compose up --build -d` | `docker compose -f docker-compose.prod.yml --env-file .env.prod up --build -d` |
| **`WORKFOLIO_DEMO_MODE`** | `"true"` (разрешает fallback на единый `DEFAULT_DEV_JWT_SECRET` из `@repo/shared-schemas` и выводит `console.warn`) | Не задан (`"false"` — жёсткий fail-fast в `loadAppConfig` при пустых или дефолтных секретах) |
| **Проверка секретов на уровне Compose** | `${JWT_SECRET:-}` (авто-резолв через `resolveJwtSecret()` без `.env`) | Обязательная интерполяция `${JWT_SECRET:?}`, `${ADMIN_SECRET_PASSCODE:?}`, `${POSTGRES_PASSWORD:?}` |
| **Флаг `Secure` у `HttpOnly` куки `kb_access_token`** | `false` (`appConfig.isProduction && !appConfig.isDemoMode` — работает по `http://localhost:3000`) | `true` (работает строго поверх HTTPS / TLS) |
| **Порт `postgres` (`5432`)** | `127.0.0.1:5432:5432` (доступен только с localhost для DBeaver / DataGrip) | **Не опубликован на хост** (100% изолирован внутри приватной сети `backend-network`) |
