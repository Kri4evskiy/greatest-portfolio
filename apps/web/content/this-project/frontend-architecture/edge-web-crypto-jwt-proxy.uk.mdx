## 1. Єдині 1-денні контракти та Fail-Closed резолвінг секрету в продакшені

Щоб фронтенд (`apps/web`) та бекенд (`apps/api`) ніколи не розсинхронізувалися в назві `HttpOnly`-куки, часі її життя або базових правилах секрету, спільні auth-примітиви винесені в `@repo/shared-schemas`:

```typescript title="packages/shared-schemas/src/auth.schema.ts"
export const KB_ACCESS_COOKIE_NAME = 'kb_access_token'
export const KB_COOKIE_MAX_AGE_MS = 1000 * 60 * 60 * 24 // 1 day
export const DEFAULT_DEV_JWT_SECRET = 'workfolio-super-secret-jwt-key-2026'

export function resolveJwtSecret(envSecret?: string): string {
  const trimmed = envSecret?.trim()
  return trimmed && trimmed.length > 0 ? trimmed : DEFAULT_DEV_JWT_SECRET
}
```

Однак на Edge-периметрі автоматичний відкат на публічний dev-секрет у продакшені став би критичною вразливістю. Тому в `apps/web/src/shared/config/env.ts` поверх базового контракту працює суворий `resolveEdgeJwtSecretStrict()`:

```typescript title="apps/web/src/shared/config/env.ts"
const MIN_PROD_JWT_SECRET_LENGTH = 32

export function resolveEdgeJwtSecretStrict(env: NodeJS.ProcessEnv = process.env): string | null {
  const parsed = WebEnvSchema.safeParse(env)
  const nodeEnv = parsed.success ? parsed.data.NODE_ENV : process.env.NODE_ENV
  const isProduction = nodeEnv === 'production'
  const isDemoMode = (parsed.success ? parsed.data.WORKFOLIO_DEMO_MODE : env.WORKFOLIO_DEMO_MODE) === 'true'
  const rawSecret = (parsed.success ? parsed.data.JWT_SECRET : env.JWT_SECRET)?.trim() ?? ''

  if (isProduction && !isDemoMode) {
    if (rawSecret.length < MIN_PROD_JWT_SECRET_LENGTH || rawSecret === DEFAULT_DEV_JWT_SECRET) {
      return null
    }
    return rawSecret
  }

  return resolveJwtSecret(rawSecret || undefined)
}
```

- **Продакшен (`NODE_ENV=production` без `WORKFOLIO_DEMO_MODE=true`):** сувора **fail-closed** політика — якщо `JWT_SECRET` не заданий, коротший за `32` символи або збігається з `DEFAULT_DEV_JWT_SECRET`, функція повертає `null`, і Edge Proxy гарантовано відхиляє будь-який токен (`false`).
- **Локальна розробка / тести / Docker-демо (`WORKFOLIO_DEMO_MODE=true`):** зберігається безшовний старт без ручного налаштування `.env` через делегування в `resolveJwtSecret()`.

## 2. Верифікація `HS256` через нативний Web Crypto API (`crypto.subtle`)

Оскільки сторінки Бази Знань передгенеруються в статику (`SSG`), перевірка доступу виконується просто на межі мережі в Edge Runtime до віддачі HTML. Замість сторонніх JWT-бібліотек `apps/web/src/shared/lib/edge-jwt.ts` використовує вбудований **Web Crypto API** із кешуванням `CryptoKey` на рівні ізоляту та скиданням відхиленого промісу:

```typescript title="apps/web/src/shared/lib/edge-jwt.ts"
let cachedSecretValue: string | null = null
let cachedHmacKeyPromise: Promise<CryptoKey> | null = null

const ALLOWED_JWT_ROLES = new Set(['USER', 'ADMIN'])

function getHmacKey(secret: string): Promise<CryptoKey> {
  if (cachedSecretValue === secret && cachedHmacKeyPromise) {
    return cachedHmacKeyPromise
  }

  cachedSecretValue = secret
  cachedHmacKeyPromise = crypto.subtle
    .importKey('raw', new TextEncoder().encode(secret), { name: 'HMAC', hash: 'SHA-256' }, false, ['verify'])
    .catch((error: unknown) => {
      // Скидаємо відхилений проміс, щоб тимчасовий збій Web Crypto не отруїв ізолят назавжди
      cachedSecretValue = null
      cachedHmacKeyPromise = null
      throw error
    })
  return cachedHmacKeyPromise
}
```

### Точний порядок перевірок у `verifyEdgeJwtHs256(token)`

Функція `verifyEdgeJwtHs256(token: string | undefined): Promise<boolean>` за `< 0.2 мс` виконує багатоступеневу валідацію, відсікаючи невалідні токени ще до криптографічних обчислень:

1. **Структура та суворий Base64URL:** розбиває токен рівно на 3 непорожні сегменти (`header.payload.signature`) і декодує їх через `decodeBase64UrlToBytes()` (відкидаючи сторонні символи та некоректну довжину `length % 4 === 1`) у `Uint8Array<ArrayBuffer>`.
2. **Фіксація алгоритму в заголовку:** парсить JSON заголовка й корисного навантаження як plain-об'єкти (`isPlainObject`) та вимагає строго `headerJson.alg === 'HS256'` (захист від `alg: "none"` і підміни алгоритму).
3. **Валідація часових і рольових claims:**
   - Перевіряє `typeof payloadJson.exp === 'number'` та `payloadJson.exp * 1000 > nowMs` (відповідно до `1d` JWT TTL).
   - Якщо вказаний `payloadJson.nbf`, вимагає `typeof payloadJson.nbf === 'number'` та `payloadJson.nbf * 1000 <= nowMs`.
   - Перевіряє наявність непорожнього рядка `payloadJson.sub` (`sub.trim().length > 0`).
   - Перевіряє, що `payloadJson.role` входить до білого списку `ALLOWED_JWT_ROLES` (`'USER' | 'ADMIN'`).
4. **Fail-Closed секрет і константна перевірка підпису:** викликає `resolveEdgeJwtSecretStrict()` (у продакшені при `null` логує помилку й повертає `false`), отримує кешований ключ через `getHmacKey(secret)` та виконує `crypto.subtle.verify('HMAC', hmacKey, signatureBytes, signingInput)`.

## 3. Гібридна межа Бази Знань і явний matcher статики в `apps/web/src/proxy.ts`

Політика доступу централізована в `apps/web/src/shared/i18n/app-routes.ts`, тому Edge Proxy, генератор `sitemap.xml`, `robots.ts` і клієнтські кнопки спираються на єдину логіку:

```typescript title="apps/web/src/shared/i18n/app-routes.ts"
export const PUBLIC_KB_ROOT_SEGMENTS = ['this-project'] as const

export function isPublicKnowledgeBasePath(pathname: string): boolean {
  const normalized = stripLocalePrefix(pathname).replace(/\/+$/, '') || '/'
  if (normalized === APP_ROUTES.knowledgeBase) {
    return true
  }
  return PUBLIC_KB_ROOT_SEGMENTS.some(
    (segment) =>
      normalized === `${APP_ROUTES.knowledgeBase}/${segment}` ||
      normalized.startsWith(`${APP_ROUTES.knowledgeBase}/${segment}/`),
  )
}

export function isProtectedKnowledgeBasePath(pathname: string): boolean {
  const normalized = stripLocalePrefix(pathname).replace(/\/+$/, '') || '/'
  if (!isRouteActive(normalized, APP_ROUTES.knowledgeBase, true)) {
    return false
  }
  return !isPublicKnowledgeBasePath(normalized)
}
```

- **Публічні й індексовані SEO-маршрути:** хаб `/knowledge-base` і гілка `/knowledge-base/this-project/**` (прозора архітектурна специфікація, відкрита для краулерів, рекрутерів і тімлідів без `307`-редиректів).
- **Захищені Edge JWT маршрути:** усі інші доменні конспекти (наприклад, `/knowledge-base/react/**`, `/knowledge-base/backend/**`, `/knowledge-base/others/**`) у всіх локалях (`''`, `/ua`, `/ru`).

Завдяки інкапсуляції криптографії й правил доступу `apps/web/src/proxy.ts` залишається компактним і прозорим:

```typescript title="apps/web/src/proxy.ts"
const LOCALE_PREFIX_MATCH_REGEX = /^\/(en|ua|ru)(?=\/|$)/

export async function proxy(request: NextRequest): Promise<NextResponse> {
  const { pathname } = request.nextUrl

  if (isProtectedKnowledgeBasePath(pathname)) {
    const token = request.cookies.get(KB_ACCESS_COOKIE_NAME)?.value
    const isValid = await verifyEdgeJwtHs256(token)

    if (!isValid) {
      const matchedLocale = pathname.match(LOCALE_PREFIX_MATCH_REGEX)?.[1]
      const homePath = matchedLocale && matchedLocale !== routing.defaultLocale ? `/${matchedLocale}` : '/'
      const redirectUrl = new URL(homePath, request.url)
      redirectUrl.searchParams.set('unlock', 'knowledge-base')
      redirectUrl.searchParams.set('redirect', pathname)

      const response = NextResponse.redirect(redirectUrl)
      if (token) {
        response.cookies.delete(KB_ACCESS_COOKIE_NAME)
      }
      return response
    }
  }

  return handleI18nRouting(request)
}

// Явно виключаємо відомі розширення статики замість широкого `.*\..*`,
// щоб слаги Бази Знань із крапкою (наприклад, `next.js-16`) ніколи не оминали Edge Auth.
export const config = {
  matcher: [
    '/((?!api|search-index|icon|apple-icon|_next|_vercel|.*opengraph-image.*|.*\\.(?:ico|png|jpg|jpeg|gif|svg|webp|avif|pdf|css|js|mjs|map|woff|woff2|ttf|otf|txt|xml|json|webmanifest)$).*)',
  ],
}
```

> [!IMPORTANT]
> Заміна шаблонного виключення `.*\..*` на **явний перелік розширень статичних файлів** закриває класичний вектор обходу Next.js middleware: будь-які майбутні слаги Бази Знань із крапками (наприклад, `next.js-16` або `node.js-streams`) гарантовано проходять через `proxy()` та Edge JWT-валідацію.
