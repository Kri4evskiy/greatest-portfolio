## 1. Offline-First Caching in Browser `IndexedDB`

To make repeat navigation across articles and the technology matrix happen in **0ms** (even in `Offline` airplane mode), we wired `PersistQueryClientProvider` from `@tanstack/react-query-persist-client` with an asynchronous `idb-keyval` storage adapter.

Unlike synchronous `LocalStorage` (which blocks the main thread during JSON serialization and is capped at 5 MB), `IndexedDB` operates asynchronously and persists the `TanStack Query v5` cache with a `gcTime: 24h` policy.

## 2. Production Bundle Diet: `React 19 Compiler` + RSC Islands

In `apps/web/next.config.ts`, we enabled the official `babel-plugin-react-compiler` (`reactCompiler: true`) alongside `@next/bundle-analyzer`, `optimizePackageImports` (`lucide-react`, `d3`, `@repo/ui`), `next/dynamic` for heavy visualizations, and strict server-side locale slicing so inactive translations never cross into client bundles.

| RSC Diet + On-Demand `Cmd+K` Index + `reactCompiler` | **84.2 kB (-41%)** | **101.5 kB (-49%)** |

## 3. Three-Stage Containerization (`Docker` + `turbo prune`)

All three services (`web`, `api`, `telemetry-ms`) are packaged into multi-stage `Dockerfile` definitions inside `docker/`:
1. **Stage 1 (`pruner`):** Executes `turbo prune @repo/<app> --docker`, isolating only the required monorepo packages.
2. **Stage 2 (`builder`):** Caches `pnpm install --frozen-lockfile` layers and builds the target via `turbo build`.
3. **Stage 3 (`runner`):** Clean `node:22-alpine` image running as a non-root user, launched with a single `docker compose up --build` command.
