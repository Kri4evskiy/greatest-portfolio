## 1. Why Modern Full-Stack Applications Need Defense-in-Depth

In a monorepo combining a public Next.js frontend, a NestJS API, an internal TCP microservice, and PostgreSQL, compromising a single layer can cascade across the stack. Our architecture enforces **Defense-in-Depth** across five autonomous boundaries:

```text
[ Browser ]
    │
    ├── (1) HTTP Security Headers (Next.js): Narrowed CSP, HSTS, COOP, CORP: same-origin, X-Frame-Options
    │
    ├── (2) Edge Auth Barrier (proxy.ts + edge-jwt.ts): Hybrid KB policy + Fail-Closed HS256 Web Crypto JWT
    │
    ├── (3) API Gateway Hardening (NestJS): JSON-only 100kb parser + Strict Helmet CSP + CsrfOriginMiddleware
    │
    ├── (4) Rate Limiting & RBAC: Shared Throttler (60/min global, 5/min auth & SSE) + HS256 1d JWT + Roles
    │
    └── (5) Container & Network Isolation (docker-compose.prod.yml): read_only, cap_drop ALL, loopback 127.0.0.1, private TCP :4001
```

Each tier operates independently: if an attacker bypasses client validation, `CsrfOriginMiddleware`, `ZodValidationPipe`, and `ThrottlerGuard` halt the request on the API; if they attempt to frame the app, `frame-ancestors 'none'` blocks rendering.

## 2. HTTP Security Headers in Next.js 16 (`apps/web/config/security-headers.config.ts`)

To keep `apps/web/next.config.ts` concise and respect FSD boundaries, all security headers live in `apps/web/config/security-headers.config.ts`. Production `connect-src` intentionally omits blanket `https:` exfiltration—only `'self'` plus explicitly validated origins (`NEXT_PUBLIC_API_URL`, `NEXT_PUBLIC_POSTHOG_HOST`, `NEXT_PUBLIC_SENTRY_DSN` via `parseSafeHttpOrigin`) are allowed:

```typescript title="apps/web/config/security-headers.config.ts"
export function buildContentSecurityPolicy(
  isProduction: boolean,
  publicApiUrl = '',
  options: ContentSecurityPolicyOptions = {},
): string {
  const { allowSameOriginFraming = false } = options
  const allowedConnectOrigins = new Set<string>()
  const safeApiOrigin = parseSafeHttpOrigin(publicApiUrl)
  if (safeApiOrigin) allowedConnectOrigins.add(safeApiOrigin)

  const posthogOrigin = parseSafeHttpOrigin(process.env.NEXT_PUBLIC_POSTHOG_HOST)
  if (posthogOrigin) allowedConnectOrigins.add(posthogOrigin)
  const sentryOrigin = parseSafeHttpOrigin(process.env.NEXT_PUBLIC_SENTRY_DSN)
  if (sentryOrigin) allowedConnectOrigins.add(sentryOrigin)

  const extraConnectSrc = allowedConnectOrigins.size > 0 ? ` ${Array.from(allowedConnectOrigins).join(' ')}` : ''

  // In production, internal ports and blanket `https:` are NEVER allowed in connect-src.
  const connectSrc = isProduction
    ? `'self'${extraConnectSrc}`
    : `'self' http://localhost:4000 http://localhost:4001 http://127.0.0.1:4000 http://127.0.0.1:4001 ws: wss:${extraConnectSrc}`

  // In production, 'unsafe-eval' is strictly disabled (MDX compiles to HAST without eval).
  const scriptSrc = isProduction ? "'self' 'unsafe-inline'" : "'self' 'unsafe-inline' 'unsafe-eval'"
  const frameAncestors = allowSameOriginFraming ? "'self'" : "'none'"

  const directives: string[] = [
    "default-src 'self'",
    `script-src ${scriptSrc}`,
    "style-src 'self' 'unsafe-inline'",
    "img-src 'self' blob: data: https:",
    "font-src 'self' data:",
    `connect-src ${connectSrc}`,
    "frame-src 'self'",
    `frame-ancestors ${frameAncestors}`,
    "form-action 'self'",
    "base-uri 'self'",
    "object-src 'self'",
    ...(isProduction ? ['upgrade-insecure-requests'] : []),
  ]

  return directives.join('; ').trim()
}
```

### Key Hardening Directives in `getSecurityHeaders()`
- **Narrowed Prod `connect-src` & Zero Eval:** Strips localhost ports (`:4000`, `:4001`), removes blanket `https:`, and disables `'unsafe-eval'` in production.
- **`Cross-Origin-Opener-Policy: same-origin` & `Cross-Origin-Resource-Policy: same-origin`:** Isolates the top-level browsing context and blocks cross-origin reads of frontend assets (XS-Leaks / Spectre defense).
- **Clickjacking & Scoped `/cv/:path+` PDFs:** `next.config.ts` sets `poweredByHeader: false`, applies `frame-ancestors 'none'` + `X-Frame-Options: DENY` globally on `/(.*)`, and relaxes framing to `'self'` / `SAMEORIGIN` **exclusively** on `/cv/:path+` so SPA `<Link href="/cv">` navigation renders `<object type="application/pdf">` without loosening any other route.
- **`Strict-Transport-Security` (Prod only), `nosniff`, `Referrer-Policy`, `Permissions-Policy`:** `max-age=63072000; includeSubDomains; preload`, `X-Content-Type-Options: nosniff`, `strict-origin-when-cross-origin`, and `camera=(), microphone=(), geolocation=(), browsing-topics=()`.

## 3. Hybrid KB Access, Explicit Asset Matcher & Fail-Closed Edge JWT (`proxy.ts` & `edge-jwt.ts`)

In Next.js 16, `apps/web/src/proxy.ts` enforces a **Hybrid Knowledge Base** boundary using `isProtectedKnowledgeBasePath()`:
- **Public & SEO-indexed:** `/knowledge-base` hub and `/knowledge-base/this-project/**` load directly with zero redirects for crawlers, recruiters, and Team Leads.
- **Protected by Edge Web Crypto JWT:** all other domain study-note trees (`/knowledge-base/react/**`, etc.) require a valid `kb_access_token` cookie verified via `verifyEdgeJwtHs256()`.

```typescript title="apps/web/src/proxy.ts"
// Explicitly exclude known static asset extensions instead of blanket `.*\..*`
// so future Knowledge Base slugs containing dots (e.g. `next.js-16`) never bypass Edge Auth.
export const config = {
  matcher: [
    '/((?!api|search-index|icon|apple-icon|_next|_vercel|.*opengraph-image.*|.*\\.(?:ico|png|jpg|jpeg|gif|svg|webp|avif|pdf|css|js|mjs|map|woff|woff2|ttf|otf|txt|xml|json|webmanifest)$).*)',
  ],
}
```

Inside `apps/web/src/shared/lib/edge-jwt.ts`, `verifyEdgeJwtHs256()` is strictly **fail-closed**:
1. Enforces `header.alg === 'HS256'`, valid `exp` and optional `nbf`, non-empty `sub`, and `role` in `{'USER', 'ADMIN'}`.
2. Calls `resolveEdgeJwtSecretStrict()`, which returns `null` in production (outside explicit `WORKFOLIO_DEMO_MODE=true`) if `JWT_SECRET` is missing, shorter than 32 chars, or equals `DEFAULT_DEV_JWT_SECRET` — guaranteeing Edge Auth never falls back to a public dev key.
3. Caches the imported Web Crypto `CryptoKey` per secret and evicts rejected promises on error so transient isolate failures never poison verification.

## 4. API Gateway Hardening (`main.ts`), `1d` HS256 JWTs & Safe Error Handling

In `apps/api/src/main.ts`, Express runs with `bodyParser: false` and registers **only** a `100kb` JSON parser (removing `urlencoded` completely), configures `trust proxy` from validated `appConfig.trustProxyHops` (`0..5`, default `1`), and applies a **strict Helmet JSON CSP** alongside cross-origin CORP for authorized cross-domain Vercel ➔ Render API fetches:

```typescript title="apps/api/src/main.ts"
async function bootstrap(): Promise<void> {
  const app = await NestFactory.create<NestExpressApplication>(AppModule, {
    bodyParser: false,
  })
  app.useBodyParser('json', { limit: '100kb' })

  if (appConfig.isProduction && appConfig.trustProxyHops > 0) {
    app.set('trust proxy', appConfig.trustProxyHops)
  }

  app.setGlobalPrefix('api')
  app.use(
    helmet({
      crossOriginResourcePolicy: { policy: 'cross-origin' },
      contentSecurityPolicy: {
        directives: {
          defaultSrc: ["'none'"],
          frameAncestors: ["'none'"],
        },
      },
    }),
  )
  app.use(cookieParser())
  app.useGlobalFilters(new SentryExceptionFilter())
  app.useGlobalInterceptors(new LoggingInterceptor())

  app.enableCors({
    origin: appConfig.allowedOrigins,
    credentials: true,
    methods: ['GET', 'POST', 'PUT', 'PATCH', 'DELETE', 'OPTIONS'],
    exposedHeaders: ['X-Request-Id'],
  })
  app.enableShutdownHooks()
}
```

### Auth Hardening & Safe Error Serialization
- **`1d` TTL, `HS256` Pinning & Fail-Closed Admin Escalation (`AuthService`):**
  `KB_COOKIE_MAX_AGE_MS` is pinned to **1 day** (`expiresIn: '1d'`), `jwtService.signAsync` pins `algorithm: 'HS256'`, and `jwtService.verifyAsync` pins `algorithms: ['HS256']` (preventing algorithm-confusion attacks). If a non-empty `adminPasscode` is supplied, `isPasscodeMatch()` compares SHA-256 digests with `crypto.timingSafeEqual()` and throws **`403 ForbiddenException`** on mismatch — never silently downgrading to `USER`.
- **`headersSent` Guard & Log Sanitization (`SentryExceptionFilter`):**
  If a client disconnects mid-stream during an active SSE response, HTTP headers are already flushed; `if (response.headersSent) return` prevents uncaught `ERR_HTTP_HEADERS_SENT` worker crashes. All user-controlled URLs and headers pass through `sanitizeLogValue()` (stripping ANSI escape codes, `\r\n`, and control characters) to prevent Log Forging.
- **Zero-Eval MDX Sanitization (`apps/web/src/entities/knowledge-content/lib/`):**
  `mdx-ast-parser.ts` disables `gray-matter`'s legacy `js`/`javascript` eval engines, strips arbitrary raw HTML blocks that are not registered widgets, and `link-sanitizer.ts` (`classifySafeMarkdownLink` / `isSafeMarkdownImageSrc`) blocks `javascript:`, `data:`, and protocol-relative `//` / `/\` links.

## 5. `CsrfOriginMiddleware` & Secure Extension Patterns for Future Media Uploads

Because `SameSite=Lax` cookies alone do not protect every cross-site state-changing vector (e.g., same-site subdomain attacks or simple HTML `<form>` submissions), `AppModule` applies `CsrfOriginMiddleware` across `'{*path}'` for all mutating HTTP methods (`POST`, `PUT`, `PATCH`, `DELETE`):

1. **JSON-Only Content-Type Gate (`415 Unsupported Media Type`):** Rejects any mutating request carrying a body whose `Content-Type` is not `application/json` — blocking all three CORS "simple request" types (`application/x-www-form-urlencoded`, `text/plain`, `multipart/form-data`) that cross-site HTML `<form>` tags can submit without a CORS preflight.
2. **Strict `Origin` Allowlist (`403 Forbidden`):** Whenever browsers attach an `Origin` header, it must match `appConfig.allowedOrigins`.
3. **`Sec-Fetch-Site` Guard (`403 Forbidden`):** Rejects `Sec-Fetch-Site` values other than `same-origin` or `none` unless `Origin` is explicitly allowlisted (preserving legitimate cross-domain Vercel ➔ Render requests when `WEB_ORIGIN` is configured).

### Architectural Extension Patterns for Future Media / File Uploads
If the platform later adds user avatars, diagram attachments, or media uploads, `CsrfOriginMiddleware` documents two secure extension paths:
- **Pattern A (Recommended — S3/R2 Presigned URLs):** The browser sends a standard JSON request (`POST /api/storage/presign`) that passes `CsrfOriginMiddleware` unchanged, receives a short-lived signed upload URL, and uploads binary media directly to Cloudflare R2 / MinIO — keeping the NestJS API 100% JSON-only with zero Node.js RAM pressure.
- **Pattern B (Scoped Multipart Proxy):** If a NestJS route genuinely requires `multipart/form-data`, exempt **only** that explicit path via a narrow allowlist while still enforcing `Origin`, `Sec-Fetch-Site`, and a preflight-triggering custom header (e.g. `X-Requested-With`).
- **Mandatory Upload XSS Rule:** Never accept or serve inline user-uploaded `.svg` files from the application origin (Stored XSS vector); allow only raster formats (`PNG`, `WebP`, `AVIF`, `JPEG`) verified by magic bytes and served from an isolated CDN/R2 domain or sandboxed CSP.

## 6. Brute-Force & DoS Defense: `@nestjs/throttler` Shared Buckets & Bounded SSE

`AppModule` configures a global limit of **`60 req/min`** and a custom `generateKey` function so `/api/auth/guest-pass` (`issueGuestPass`) and its `/api/auth/login` (`login`) alias share a **single `5 req/min` bucket** — preventing attackers from doubling brute-force attempts across both endpoints:

```typescript title="apps/api/src/app.module.ts"
const SHARED_AUTH_THROTTLE_HANDLERS = new Set(['issueGuestPass', 'login'])

ThrottlerModule.forRoot({
  throttlers: [{ ttl: 60000, limit: 60 }],
  generateKey: (context, trackerString, throttlerName) => {
    const className = context.getClass().name
    const handlerName = context.getHandler().name
    if (className === 'AuthController' && SHARED_AUTH_THROTTLE_HANDLERS.has(handlerName)) {
      return `AuthController:issuePass:${trackerString}:${throttlerName}`
    }
    return `${className}:${handlerName}:${trackerString}:${throttlerName}`
  },
})
```

### Bounded SSE Instead of `@SkipThrottle()`
Rather than exempting SSE from rate limiting completely, `TelemetryController.streamEvents()` applies **`@Throttle({ default: { limit: 5, ttl: 60000 } })`** to cap reconnect handshakes at `5/min/IP` while keeping **`@SkipTimeout()`** so `TimeoutInterceptor` never terminates healthy streams. Concurrently, `TelemetryService` caps active connections at **`2/IP`**, **`50` global**, and **`15 minutes` max stream TTL** (`finalize()` releases slots on disconnect).

### Evolution Path: In-Memory ➔ Distributed Redis Throttler
Single-instance deployments use zero-cost In-Memory counters. When scaling `apps/api` horizontally across replicas, plugging `ThrottlerStorageRedisService` over `REDIS_URL` synchronizes sliding-window counters atomically with graceful fallback to local memory when `REDIS_URL` is absent.

## 7. Security Checklist, Container Hardening & Conscious Trade-offs

In `docker-compose.prod.yml`, every application container (`web`, `api`, `telemetry-ms`) runs with `read_only: true`, `cap_drop: [ALL]`, `no-new-privileges:true`, `pids_limit: 256`, host bindings restricted to `127.0.0.1`, mandatory non-default secret checks (`${JWT_SECRET:?...}`), and PostgreSQL + TCP `:4001` isolated inside `backend-network`.

| Threat Vector | Monorepo Defense Implementation | Status |
| :--- | :--- | :--- |
| **XSS Token Exfiltration** | `HttpOnly` cookies + Zero-Eval HAST (`gray-matter` JS engines disabled) + `classifySafeMarkdownLink` | 🛡️ Shielded |
| **CSRF (Login/Logout/Mutations)** | `SameSite=Lax` + `CsrfOriginMiddleware` (JSON-only `415`, `Origin` + `Sec-Fetch-Site` `403`) + no `urlencoded` parser | 🛡️ Shielded |
| **Clickjacking & XS-Leaks** | `X-Frame-Options: DENY`, CSP `frame-ancestors 'none'` (scoped `/cv/:path+`), `COOP: same-origin`, `CORP: same-origin` | 🛡️ Shielded |
| **Brute-Force & SSE Floods** | Global `60/min`, shared `5/min` auth bucket, `403` on bad `adminPasscode`, SSE `5/min` + `2/IP` / `50` global / `15m` TTL | 🛡️ Shielded |
| **Log Forging & Stream Crashes** | `resolveCorrelationRequestId` + `sanitizeLogValue` + `SentryExceptionFilter` `response.headersSent` guard | 🛡️ Shielded |
| **Cross-Service & Container Escape** | Loopback `127.0.0.1:4001` default + `docker-compose.prod.yml` (`read_only`, `cap_drop: ALL`, private `backend-network`) | 🛡️ Shielded |

### Conscious Architectural Trade-offs
1. **Static `SSG` (`'unsafe-inline'`) vs. Per-Request `CSP Nonce`:**
   - *Trade-off:* Removing `'unsafe-inline'` from `script-src` requires generating a per-request cryptographic `nonce`, forcing all **199** statically generated routes out of **SSG** into dynamic per-request `SSR` and sacrificing edge CDN caching.
   - *Mitigation:* No untrusted user HTML is rendered (`.mdx` files are repository-controlled, compiled via Zero-Eval HAST with raw HTML stripped and URLs sanitized), and session JWTs live exclusively in `HttpOnly` cookies.
2. **Hybrid Public Discovery (`/search-index/[locale]` & `/knowledge-base/this-project/**`) vs. Protected Study Notes:**
   - *Trade-off:* `proxy.ts` intentionally leaves `/search-index/[locale]`, `/knowledge-base`, and `/knowledge-base/this-project/**` public for SEO and instant recruiter evaluation while keeping all other KB categories gated behind fail-closed Edge `HS256` JWT verification.
3. **Stateless `1d` Edge Verification vs. Instant Token Revocation (Pre-Redis):**
   - *Trade-off:* `verifyEdgeJwtHs256` verifies signatures and `exp` in `< 0.2 ms` with zero DB round-trips, so an issued **`1d`** token cannot be individually revoked at the Edge without rotating `JWT_SECRET`.
   - *Mitigation:* Shortening the cookie/JWT TTL from 7 days to **`1d`** shrinks the exposure window, while the Post-MVP roadmap pairs **Redis** with short-lived `Access` (`15m`) + rotating `HttpOnly Refresh` tokens backed by `VisitorSession`.
