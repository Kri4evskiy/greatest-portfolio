## 1. Server Locale Slicing & `pickIntlMessages()` Namespace Splitting

In multilingual applications (`EN / UK / RU`), two silent payload leaks often bloat initial page loads:
1. Importing trilingual TypeScript data modules (`author-profile.ts`, `tech-radar`, `engineering-roadmap`) into `'use client'` files bundles all 3 languages into browser JS chunks.
2. Passing the entire `getMessages()` object to a single root `<NextIntlClientProvider>` serializes every page's translation keys into the SSR HTML stream of every route.

We eliminate both leaks on the server:
- **Typed Data Slicing:** primary home sections (`WorkfolioHeroSection`, `WorkfolioProjectsSection`, `WorkfolioExperienceSection`, `WorkfolioFooter`) and `CvDocumentShowcase` run as **Server Components**, project only the active locale via `pickLocalized(field, locale)`, and pass plain strings or pre-rendered `ReactNode` slots to thin client islands.
- **Namespace Slicing via `pickIntlMessages()` (`apps/web/src/shared/i18n/pick-messages.ts`):**
  - Root `apps/web/src/app/[locale]/layout.tsx` slices **only** `['Header', 'GuestPassModal', 'KnowledgeBase', 'ErrorPage']`.
  - Individual route pages wrap only their client subtrees with scoped `<NextIntlClientProvider>` instances: Home (`['TechRadar', 'Roadmap']`), `/cv` (`['CvPage']`), and `/system-status` (`['SystemStatusPage']`).

### `CvDocumentShowcase` Server Island + `CvViewTabs` (`forceMount`)
On `/[locale]/cv`, `CvDocumentShowcase` (`apps/web/src/entities/workfolio-profile/cv-document-showcase.tsx`) renders the complete structured ATS resume on the server and injects it via `structuredSlot={structuredResumeNode}` into the thin Client Island `CvViewTabs` (`cv-view-tabs.tsx`). Inside `CvViewTabs`, the structured tab uses Radix `forceMount` paired with CSS visibility toggling:

```tsx title="apps/web/src/entities/workfolio-profile/cv-view-tabs.tsx"
<TabsContent value="structured" forceMount className="mt-0 data-[state=inactive]:hidden">
  {structuredSlot}
</TabsContent>
```

Search crawlers always receive the full semantic HTML resume at SSR time even though `'pdf'` is the default active tab, while the trilingual `author-profile.ts` dictionary stays `0 KB` in client JS.

## 2. Client Micro-Islands, Lazy Modal Loaders & Singleton `bfcache`-Safe SSE

Every interactive control is isolated into a dedicated micro-island:

| Micro-Island / Loader | Location | Responsibility & Actual Props |
| :--- | :--- | :--- |
| **`HeroActionRow`** | `workfolio-client-islands.tsx` | Navigates to `/knowledge-base`, `/cv`, and smooth-scrolls to `#tech-radar` / `#roadmap` (`ctaUnlocked`, `ctaLocked`, `ctaCvPdf`, `ctaTechRadar`, `ctaRoadmap`) |
| **`CaseStudyReadButton`** | `workfolio-client-islands.tsx` | Computes `/knowledge-base/${category}/${slug}`, checks `isUnlocked \|\| isPublicKnowledgeBasePath(targetUrl)`, and navigates or calls `openGuestPassModal(targetUrl)` (`category`, `slug`, `readUnlockedLabel`, `readLockedLabel`) |
| **`EarlierRolesDisclosure`** | `workfolio-client-islands.tsx` | Expand/collapse earlier career roles (`showLabel`, `hideLabel`, server-rendered `children: ReactNode`) |
| **`FooterSseStatus`** | `footer-sse-status.tsx` | Live telemetry pill linking to `/system-status` (`waitingLabel`, `inspectLabel = 'Inspect Live API'`) powered by `useTelemetryStream()` |
| **`GuestPassModalLoader`** | `guest-pass-modal-loader.tsx` | Listens for `?unlock=knowledge-base` redirects and lazily loads `GuestPassModal` (RHF + Zod + Radix Dialog) via `next/dynamic(..., { ssr: false })` |
| **`CommandPaletteLoader`** | `command-palette-loader.tsx` | Listens for global `Cmd+K` / `Ctrl+K` and lazily loads `CommandPaletteModal` via `next/dynamic(..., { ssr: false })` |

### Ref-Counted Singleton `EventSource` & `bfcache` Hygiene (`use-telemetry-stream.ts`)
Rather than opening separate `EventSource` sockets inside `FooterSseStatus` and `SystemStatusDashboard`, `apps/web/src/features/telemetry-stream/use-telemetry-stream.ts` encapsulates a single `SharedTelemetryStreamManager` exposed through `useSyncExternalStore`:

- **Single Connection per Tab:** ref-counts mounted React listeners (`this.listeners.size === 1` connects; `0` tears down), respecting the backend's `MAX_SSE_STREAMS_PER_IP = 2` cap and HTTP/1.1 6-connection-per-origin browser limits.
- **Bounded Exponential Backoff:** recovers cleanly from `EventSource.CLOSED` (e.g. `429`/`500` proxy errors or the backend's 15-minute stream TTL) from `2s` up to `30s` (max `6` attempts, reset on `online` / `pageshow`).
- **`bfcache` Hygiene:** closes the socket on `pagehide` and restores it when `event.persisted` is true on `pageshow`:

```typescript title="apps/web/src/features/telemetry-stream/use-telemetry-stream.ts"
private readonly handlePageHide = (): void => {
  this.clearReconnectTimer()
  this.closeSource()
  if (this.snapshot.sseConnected) {
    this.emitSnapshot({ ...this.snapshot, sseConnected: false })
  }
}

private readonly handlePageShow = (event: PageTransitionEvent): void => {
  if (event.persisted && this.listeners.size > 0) {
    this.reconnectAttempts = 0
    this.connect()
  }
}
```

## 3. `React 19 Compiler` & Atomic State Boundaries (`useState` vs `Zustand`)

`apps/web/next.config.ts` enables `reactCompiler` (`compilationMode: 'infer'`, `panicThreshold: 'none'`). Client state follows strict boundaries:
- **Component-Local `useState`:** used inside interactive `D3.js` simulations (`d3-architecture-flow.tsx`, `d3-react-render-graph.tsx`) and `CvViewTabs` so local toggles never re-render unrelated subtrees.
- **Atomic `Zustand` (`apps/web/src/shared/store/use-ui-store.ts`):** keeps `useUIStoreBase` private and exports explicit atomic selector hooks (`useIsGuestPassModalOpen`, `useIsCommandPaletteOpen`, `useTechRadarCategoryFilter`, `useExpandedKbFolders`, `usePalette`, etc.) plus a stable `useUIActions()` object — zero `createSelectors` proxies, zero server/auth data in Zustand, and hydration-safe `sessionStorage` / `localStorage` sync.

## 4. Enterprise Client Fetching: `apiClient`, IndexedDB Allowlist & `AuthCrossTabSyncBridge`

Client-side API communication (`'use client'` + `TanStack Query v5`) is architected for offline safety, tab synchronization, and strict error hygiene:

1. **Centralized `API_ENDPOINTS` & `APP_ROUTES`:**
   - API contracts live in `@repo/shared-schemas` (`API_ENDPOINTS` + `resolveEndpoint`), while page routes and Hybrid KB access predicates (`isPublicKnowledgeBasePath`, `isProtectedKnowledgeBasePath`) live in `apps/web/src/shared/i18n/app-routes.ts`.
2. **Typed Axios `apiClient` (`apps/web/src/shared/lib/api-client.ts`):**
   - Isolated `axios.create({ withCredentials: true, allowAbsoluteUrls: false, timeout: 16_000 })` with runtime `Zod` validation, `X-Request-Id` extraction into `ApiClientError`, query param compaction, and native `AbortSignal` support.
3. **Strict IndexedDB Persistence Allowlist (`apps/web/src/shared/providers/query-provider.tsx`):**
   - `QueryProvider` wires `persistQueryClientSubscribe` with `dehydrateOptions: { shouldDehydrateQuery: shouldPersistQueryToIndexedDb }`, where `PERSISTABLE_QUERY_ROOT_KEYS = new Set(['knowledge'])`.
   - **Security & Freshness Guard:** only offline-safe `['knowledge', ...]` queries persist to IndexedDB; `['auth', 'me']` (preventing 24-hour resurrection of expired/revoked sessions) and volatile observability queries (`['telemetry', ...]`, `['system', ...]`) are never persisted.
   - `QueryCache({ onError })` ignores `AbortError` / React 19 `StrictMode` cancellations and expected `4xx` responses, forwarding only real network/5xx errors to `captureClientException`.
4. **Single-Socket `AuthCrossTabSyncBridge` (`apps/web/src/features/auth/auth-cross-tab-sync-bridge.tsx`):**
   - Mounted once in root `[locale]/layout.tsx` inside `QueryProvider`, opening exactly **one** `BroadcastChannel('workfolio_auth_sync')` listener per browser tab (instead of one per `useVisitorProfile()` consumer) to invalidate `VISITOR_PROFILE_QUERY_KEY` and `['knowledge']` across tabs upon Guest Pass unlock or logout.
