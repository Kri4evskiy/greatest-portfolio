## 1. The 3-Tier Locale Matrix (`Internal Code` vs `URL Prefix` vs `Hreflang / OpenGraph`)

A core nuance of multilingual SEO in this monorepo is that internal locale codes, public browser URL prefixes, and search engine / social messenger specifications follow different standards.

In `apps/web/src/shared/i18n/routing.ts`, routing uses `localePrefix: { mode: 'as-needed', prefixes: { uk: '/ua' } }`. To prevent inconsistencies across pages, `apps/web/src/shared/lib/seo.ts` explicitly maps each representation:

| Language | Internal Type (`SupportedLocale` & `.mdx` suffix) | Public URL Prefix (`as-needed`) | Search Engine ISO 639-1 (`<html lang>` & `hreflang`) | Messenger Standard (`og:locale`) |
| :--- | :--- | :--- | :--- | :--- |
| **English (Default)** | `'en'` (`*.en.mdx`) | No prefix (`/`, `/cv`, `/knowledge-base`) | `en` (+ `x-default`) | `en_US` |
| **Ukrainian** | `'uk'` (`*.uk.mdx`) | `/ua` (`/ua`, `/ua/cv`, `/ua/knowledge-base`) | `uk` | `uk_UA` |
| **Russian** | `'ru'` (`*.ru.mdx`) | `/ru` (`/ru`, `/ru/cv`, `/ru/knowledge-base`) | `ru` | `ru_RU` |

> [!IMPORTANT]
> According to Google Search Central guidelines, the `hreflang` attribute must use the **ISO 639-1** language code (`uk` for Ukrainian, not the country code `ua`), while its `href` attribute must resolve to the actual public URL (`https://domain.com/ua/...`). Therefore, `buildLanguageAlternatesMap()` maps the `uk` key directly to the `/ua` URL prefix.

## 2. Unified SEO Core & Origin Hardening (`apps/web/src/shared/lib/seo.ts`)

All SEO URL builders live in pure server functions with zero external dependencies:

```typescript title="apps/web/src/shared/lib/seo.ts"
const DEFAULT_SITE_URL = 'http://localhost:3000'

const LOCALE_URL_PREFIX_MAP: Record<SupportedLocale, string> = {
  en: '',
  uk: '/ua',
  ru: '/ru',
}

const OG_LOCALE_MAP: Record<SupportedLocale, string> = {
  en: 'en_US',
  uk: 'uk_UA',
  ru: 'ru_RU',
}

export function resolveSiteUrl(): string {
  const raw = process.env.NEXT_PUBLIC_SITE_URL?.trim()
  if (!raw) return DEFAULT_SITE_URL

  try {
    const parsed = new URL(raw)
    if (parsed.protocol !== 'http:' && parsed.protocol !== 'https:') {
      return DEFAULT_SITE_URL
    }
    return parsed.origin
  } catch {
    return DEFAULT_SITE_URL
  }
}
```

### Why `resolveSiteUrl()` validates `parsed.origin` via `new URL(raw)`
In `apps/web/src/app/[locale]/layout.tsx`, Next.js expects a valid URL instance in `metadataBase: new URL(resolveSiteUrl())`. If a deployment environment accidentally provides a malformed `NEXT_PUBLIC_SITE_URL` (missing protocol or containing trailing path segments), unguarded `new URL()` calls would crash `next build`. Extracting `parsed.origin` with protocol verification (`http:` / `https:`) guarantees a clean origin or a safe fallback to `http://localhost:3000`.

## 3. Generating `canonical`, `alternates.languages` (`hreflang`), and `openGraph`

The `buildPageAlternates(pathname, locale)` helper is invoked inside `generateMetadata()` across all route levels (`[locale]/layout.tsx`, `[locale]/cv/page.tsx`, `[locale]/knowledge-base/page.tsx`, and `[locale]/knowledge-base/[...slug]/page.tsx`):

```typescript title="apps/web/src/shared/lib/seo.ts"
export function buildLanguageAlternatesMap(pathname: string): Record<string, string> {
  return {
    en: buildLocalizedUrl(pathname, 'en'),
    uk: buildLocalizedUrl(pathname, 'uk'),
    ru: buildLocalizedUrl(pathname, 'ru'),
    'x-default': buildLocalizedUrl(pathname, DEFAULT_LOCALE),
  }
}

export function buildPageAlternates(pathname: string, locale: SupportedLocale = DEFAULT_LOCALE) {
  return {
    canonical: buildLocalizedUrl(pathname, locale),
    languages: buildLanguageAlternatesMap(pathname),
  }
}
```

From this object, Next.js 16 automatically renders in `<head>`:
- **`<link rel="canonical">`** — the authoritative URL for the active locale (preventing duplicate indexing from query parameters like `?unlock=knowledge-base`).
- **`<link rel="alternate" hreflang="en | uk | ru | x-default">`** — cross-language links following the Section 1 matrix (`x-default` points to the unprefixed English route).
- **`openGraph` tags (`og:title`, `og:description`, `og:url`, `og:locale`, `og:type`, `og:image`)** — localized Rich Link Previews for **Telegram, LinkedIn, Slack, and Discord** (with `og:type="article"`, `article:published_time`, and `article:tag` added on Knowledge Base notes).

## 4. File-Based Metadata (`robots.ts`, `sitemap.ts`, `opengraph-image.tsx`, `icon.tsx`) & Edge Proxy

All metadata routes in `apps/web/src/app/` compile statically at build time (`SSG`, `0 KB` client JS) and bypass Edge JWT verification in `apps/web/src/proxy.ts` via the `matcher` exclusion list:

```typescript title="apps/web/src/proxy.ts"
export const config = {
  matcher: ['/((?!api|search-index|icon|apple-icon|_next|_vercel|.*opengraph-image.*|.*\\..*).*)'],
}
```

1. **Internal Endpoint Isolation in `robots.ts`:** `disallow: ['/api/', '/search-index/']` prevents search crawlers from indexing backend REST/SSE streams (`/api/telemetry/stream`) and raw `Cmd+K` JSON search dumps.
2. **Recursive `.mdx` Discovery in `sitemap.ts`:** combines top-level hubs (`/`, `/cv`, `/knowledge-base`) with all paths from `getAllStaticKnowledgeSlugArrays()` and real `publishedAt` dates from `getAllKnowledgeFrontmatters(DEFAULT_LOCALE)`.
3. **Code-Generated Branded Graphics via `next/og` (`ImageResponse` / Satori):**
   - `apps/web/src/app/icon.tsx` (`32×32`) and `apple-icon.tsx` (`180×180`) render the obsidian terminal prompt `>_` icon.
   - `apps/web/src/app/[locale]/opengraph-image.tsx` (`1200×630`) generates the `Obsidian Editorial Dark` preview card for each locale (`generateStaticParams`) offline.
   - **Soft-404 Prevention:** for any unmatched URL inside a locale, the catch-all route `app/[locale]/[...rest]/page.tsx` invokes `notFound()`, returning a strict HTTP `404` status to crawlers via the pure RSC `app/[locale]/not-found.tsx`.
