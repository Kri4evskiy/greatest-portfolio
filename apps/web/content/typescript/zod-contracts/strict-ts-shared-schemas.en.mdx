## 1. Eliminating Frontend–Backend DTO Drift

When `Next.js` and `NestJS` maintain separate TypeScript interfaces by hand, renaming a backend DTO field leaves the frontend build green while breaking production payloads at runtime.

## 2. Single Source of Truth in `@repo/shared-schemas`

```typescript title="packages/shared-schemas/src/auth.schema.ts"
export const GuestPassFormSchema = z.object({
  displayName: z.string().trim().min(2).max(50),
  visitorType: VisitorRoleTypeEnum,
  adminPasscode: z.string().trim().max(100).optional(),
})
export type GuestPassFormInput = z.infer<typeof GuestPassFormSchema>
```

| Layer | Integration Point | Guarantee |
| :--- | :--- | :--- |
| **Compile Time (`tsc`)** | `noUncheckedIndexedAccess` + `z.infer` | Any renamed property fails `pnpm turbo typecheck` immediately |
| **Client (`apps/web`)** | `zodResolver(GuestPassFormSchema)` | Synchronous form validation before network request |
| **Server (`apps/api`)** | `ZodValidationPipe(GuestPassFormSchema)` | Zero-trust runtime payload sanitization in NestJS |
