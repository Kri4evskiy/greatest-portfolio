## 1. Как мы устранили дрейф DTO между фронтендом и бэкендом

Когда фронтенд (`Next.js`) и бэкенд (`NestJS`) описывают типы вручную, переименование поля в DTO на сервере не ломает билд клиента — баг всплывает только в продакшене.

## 2. Единый источник истины в `@repo/shared-schemas`

```typescript title="packages/shared-schemas/src/auth.schema.ts"
export const GuestPassFormSchema = z.object({
  displayName: z.string().trim().min(2).max(50),
  visitorType: VisitorRoleTypeEnum,
  adminPasscode: z.string().trim().max(100).optional(),
})
export type GuestPassFormInput = z.infer<typeof GuestPassFormSchema>
```

| Контур защиты | Где подключено | Что гарантирует |
| :--- | :--- | :--- |
| **Сборка (`tsc`)** | `noUncheckedIndexedAccess` + `z.infer` | Любое изменение контракта ловится на `pnpm turbo typecheck` |
| **Клиент (`apps/web`)** | `zodResolver(GuestPassFormSchema)` | Валидация полей формы до отправки сетевого запроса |
| **Бэкенд (`apps/api`)** | `ZodValidationPipe(GuestPassFormSchema)` | Строгая рантайм-очистка входящего JSON в NestJS |
