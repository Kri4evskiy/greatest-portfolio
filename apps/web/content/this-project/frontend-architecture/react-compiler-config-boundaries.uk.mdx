## 1. Конфігурація `reactCompiler` та оптимізація бандлу в `apps/web/next.config.ts`

У Next.js 16 налаштування `reactCompiler` приймає типізований об'єкт `ReactCompilerOptions` у зв'язці з оптимізацією імпортів із barrel-пакетів:

```typescript title="apps/web/next.config.ts"
const nextConfig: NextConfig = {
  ...(process.env.DOCKER_STANDALONE === 'true' ? { output: 'standalone' } : {}),
  ...(process.env.NEXT_DIST_DIR ? { distDir: process.env.NEXT_DIST_DIR } : {}),
  poweredByHeader: false,
  reactStrictMode: true,
  reactCompiler: {
    compilationMode: 'infer',
    panicThreshold: 'none',
  },
  transpilePackages: ['@repo/ui', '@repo/shared-schemas'],
  experimental: {
    optimizePackageImports: ['lucide-react', 'd3', '@repo/ui', '@repo/shared-schemas'],
  },
}
```

### Чому обрані саме ці параметри

| Параметр | Значення | Інженерне обґрунтування |
| :--- | :---: | :--- |
| **`compilationMode`** | `'infer'` | Next.js застосовує швидкі евристики на Rust/SWC до виклику `babel-plugin-react-compiler`: компілятор запускається лише для файлів із PascalCase-компонентами (JSX) та хуками `use*`, не витрачаючи час збірки на утиліти (`mdx-ast-parser.ts`, `edge-jwt.ts`) |
| **`panicThreshold`** | `'none'` | При зустрічі зі складним мутабельним SDK компілятор безпечно пропускає оптимізацію конкретної функції замість аварійної зупинки `next build` у CI/CD |
| **`optimizePackageImports`** | `['lucide-react', 'd3', '@repo/ui', '@repo/shared-schemas']` | Переписує barrel-імпорти у прямі шляхи підмодулів на етапі збірки, щоб клієнтські чанки містили лише фактично використані іконки, функції D3, UI-компоненти та схеми |

## 2. Внутрішня таблиця `knownIncompatible` та `React Hook Form`

Усередині `babel-plugin-react-compiler` (`DefaultModuleTypeProvider`) зашитий список хуків сторонніх бібліотек, які повертають нестабільні або мутабельні об'єкти:

1. **`react-hook-form` (`useForm().watch`)**: метод `watch()` мутує внутрішні підписки без зміни посилання, тому компілятор позначає його як `knownIncompatible`. В `apps/web/src/features/auth/guest-pass-modal.tsx` ми використовуємо сумісний хук **`useWatch({ control, name: 'visitorType' })`**, завдяки чому вся модалка `GuestPassModal` успішно проходить авто-мемоїзацію.
2. **`@tanstack/react-table` v9 (`useTable`)**: повертає стабільне посилання на об'єкт таблиці поверх атомів TanStack Store. Прямий виклик `table.getRowModel()` усередині компонента під React Compiler може мемоїзувати застарілі рядки, якщо не ізолювати таблицю за межею `'use no memo'`.

## 3. Винесені межі ізоляції `'use no memo'` для таблиць (TanStack Table v9)

### А. `TechRadarTable` і винесені підмодулі `table/`
Компонент `TechRadarTable` (`apps/web/src/entities/engineering-roadmap/tech-radar-table.tsx`) поєднує пошук, фільтр категорій, мобільний стек карток (`< md`), десктопну таблицю (`>= md`) та модальне вікно інспектора `ADR`. Щоб батьківський компонент залишався скомпільованим, а невикористані фічі таблиці повністю вирізалися tree-shaking'ом, шар TanStack Table v9 винесено у два окремі файли в `apps/web/src/entities/engineering-roadmap/table/`:

- **`table/tech-radar-columns.tsx`** — чиста фабрика `createTechRadarColumns({ labels, onInspectAdr })`, що повертає типізований масив `TechRadarColumnDef[]`.
- **`table/tech-radar-data-table.tsx`** — статичний `tableFeatures({ rowSortingFeature, sortedRowModel: createSortedRowModel(), sortFns })` та тонка `'use no memo'` обгортка поверх `useTable` і `<table.FlexRender />`:

```tsx title="apps/web/src/entities/engineering-roadmap/table/tech-radar-data-table.tsx"
export const techRadarTableFeatures = tableFeatures({
  rowSortingFeature,
  sortedRowModel: createSortedRowModel(),
  sortFns: {
    alphanumeric: sortFn_alphanumeric,
    basic: sortFn_basic,
  },
})

export function DesktopTechRadarDataTable({ data, columns, emptyResultLabel }: DesktopTechRadarDataTableProps) {
  'use no memo'

  const table = useTable({
    features: techRadarTableFeatures,
    data,
    columns,
    initialState: {
      sorting: [{ id: 'adrNumber', desc: false }],
    },
  })

  return (
    <div className="hidden overflow-x-auto rounded-lg border border-border bg-card shadow-xs md:block">
      {/* Рендер заголовків та комірок через <table.FlexRender header={header} /> і <table.FlexRender cell={cell} /> */}
    </div>
  )
}
```

У батьківському `TechRadarTable` значення `filteredData` і `columns` (створені через `createTechRadarColumns`) свідомо обгорнуті в `useMemo`, а `handleInspectAdr` — у `useCallback`: це стабілізує посилання, що перетинають межу `'use no memo'` у `DesktopTechRadarDataTable`, щоб відкриття модалки ADR не викликало перерахунок моделі рядків TanStack Table. Фільтри, мобільні картки, `activeDialogItem` і JSX модального вікна `Dialog` водночас повністю оптимізуються React Compiler.

### Б. Універсальна `ObservabilityDataTable` зі scoped `metaHelper`
Для таблиць телеметрії та лідерборду на `/system-status` модуль `apps/web/src/features/telemetry-stream/ui/table/observability-data-table.tsx` надає узагальнений `'use no memo'` компонент на TanStack Table v9, який підключає **нуль** клієнтських фіч сортування/фільтрації/пагінації (усе керується сервером) та ізолює типізацію метаданих колонок безпосередньо на рівні таблиці через `metaHelper<ObservabilityColumnMeta>()` (без глобального `declare module`):

```tsx title="apps/web/src/features/telemetry-stream/ui/table/observability-data-table.tsx"
export interface ObservabilityColumnMeta {
  headerClassName?: string
  cellClassName?: string
}

export const observabilityTableFeatures = tableFeatures({
  columnMeta: metaHelper<ObservabilityColumnMeta>(),
})

export function ObservabilityDataTable<TData extends RowData>({
  data,
  columns,
  emptyState,
  getRowId,
  getRowClassName,
  minTableWidthClass = 'min-w-[560px]',
  isDimmed = false,
  tableTestId,
}: ObservabilityDataTableProps<TData>) {
  'use no memo'

  const table = useTable({
    features: observabilityTableFeatures,
    data,
    columns,
    ...(getRowId ? { getRowId } : {}),
  })
  // Рендер комірок через row.getAllCells() + <table.FlexRender cell={cell} />
}
```

## 4. Сумісна з React Compiler архітектура Zustand (`use-ui-store.ts`)

Хелпери на кшталт `createSelectors` (які створюють динамічні гетери `.use.field()` на об'єкті стора) маскують виклики хуків від статичного аналізу React Compiler і можуть призводити до зайвих вимкнень оптимізації.

Натомість `apps/web/src/shared/store/use-ui-store.ts` побудований на явних атомарних хуках:
- **Приватний базовий стор:** `useUIStoreBase` не експортується назовні — підписатися на весь стор цілком без селектора неможливо на рівні типів.
- **Розділення `UIState` і `UIActions`:** усі екшени зібрані в єдиний референсно-стабільний об'єкт `actions`, доступний через `useUIActions()`.
- **Явні атомарні хуки:** кожен реактивний зріз експортує власний хук `use*` (`useIsGuestPassModalOpen`, `useTechRadarCategoryFilter`, `useTechRadarSearch`, `useSelectedAdrItem`, `useExpandedKbFolders`, `usePalette`, `useHasHydratedPalette`), плюс мінімальний імперативний хендл `uiStore` (`getState` / `subscribe`) для не-React контекстів і тестів:

```typescript title="apps/web/src/shared/store/use-ui-store.ts"
export const useUIActions = () => useUIStoreBase((s) => s.actions)
export const useIsGuestPassModalOpen = () => useUIStoreBase((s) => s.isGuestPassModalOpen)
export const useSelectedAdrItem = () => useUIStoreBase((s) => s.selectedAdrItem)
export const useTechRadarCategoryFilter = () => useUIStoreBase((s) => s.techRadarCategoryFilter)
export const useTechRadarSearch = () => useUIStoreBase((s) => s.techRadarSearch)
```
