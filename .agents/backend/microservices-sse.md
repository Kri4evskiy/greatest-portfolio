# 📡 Микросервис телеметрии и Server-Sent Events (`apps/telemetry-ms` + `@Sse`)

Этот документ описывает распределенную часть архитектуры: взаимодействие основного API с микросервисом аналитики и потоковую передачу данных в браузер по протоколу `SSE`.

## 1. Микросервис `apps/telemetry-ms` (`@nestjs/microservices`)

- Запускается как отдельный легковесный процесс NestJS Microservice (транспорт `Transport.TCP`, по умолчанию порт `4001`, с поддержкой переключения на Redis).
- Слушает асинхронные события по паттерну `@EventPattern('telemetry.event')` и синхронные запросы статистики по `@MessagePattern('telemetry.stats')`.
- При получении сырого события (например, «Тимлид разблокировал Базу Знаний» или «Поставлена отметка Helpful статье по React 19»):
  1. Валидирует полезную нагрузку через `TelemetryEventSchema` из `@repo/shared-schemas`.
  2. Обогащает событие временной меткой, человекочитаемым сообщением и агрегирует счетчики активных сессий в памяти.
  3. Возвращает/пересылает обогащенное событие для трансляции подписчикам SSE.

## 2. Эндпоинт Server-Sent Events в `apps/api` (`GET /api/telemetry/stream`)

- Реализован в `TelemetryController` через декоратор `@Sse('stream')`, возвращающий `Observable<MessageEvent>` из `RxJS`.
- Объединяет (`merge` в RxJS) два потока:
  1. **Поток живых действий пользователей (`Subject`):** Мгновенно пушит события `GUEST_PASS_ISSUED`, `ARTICLE_VIEWED`, `ARTICLE_HELPFUL` всем открытым вкладкам сайта.
  2. **Пульс сервера (`interval(15000)`):** Каждые 15 секунд отправляет событие `SYSTEM_HEARTBEAT` с временем аптайма и статусом соединения с микросервисом, которое отображается в живом индикаторе в футере портфолио.
